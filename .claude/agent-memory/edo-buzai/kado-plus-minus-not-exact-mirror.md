2026-09-21・岡部の隅8本(`Dobei_Kado_95/00/01/14/18M/11M/08M/62`)を焼いたときに実測した。

**事実:** `build_kado.py` は留め面の法線 `n = (±sin(Δ/2), cos(Δ/2), 0)` の符号だけで左右を作る。
腕の素 `armA` は**厚み方向に非対称**(`s_hei_center` の表裏2枚組が 0.2m ずれ、厚みの中心が
x=+0.1 にある)ので、`Mx(結果(−Δ)) = armA を鏡映してから組んだ物` ≠ `結果(+Δ)`。
⇒ **頂点集合の鏡映比較は必ず False になる。**実測の食い違いは Δ とともに開く:
Δ=0.2° で面 4714/4714(ほぼ同一)→ Δ=62° で 5047/4634 → Δ=95° で **5278/4478**、
折れ点より先の張り出しも 0.563m 対 0.340m。⭕ どちらも正しく焼けており、
折れの向きだけが逆・躯体面は同じ側に残る。

**Why:** 呼び出し元(と自分)が「在庫にあるのはちょうど鏡像」と考えて頂点一致を期待する。
面数差 800 を見て「焼き損ない」と誤診すると、直しようのない物を直しに行く。

**How to apply:**
- 向きの検算は**真上からの平面レンダに新旧を並べて焼く**(`ortho`・`Screenshots/kado_narabe_*.png`)。
  折れがどちらへ振れるかは平面で一目。立面と斜めでは読めない。[[narabe-check-and-fbx-byte-noise]]
- 数値で見るなら Unity X の範囲: **非M(deg>0)は出の腕が +X へ / M(deg<0)は −X へ**振れる。
  入りの腕の厚みは両者とも X≈[−0.52, +0.32] で変わらない。
- ⛔ 頂点集合の鏡映一致を合否条件にしない。[[logical-axis-and-mirror-checks]]

⚠ 併せて直した: `build_kado.py` の `OUT` が `BUZAI_OUT` を見ていなかった(staging へ逃がせず
Unity のドメインリロードを踏む)。検証レンダの名も `|deg|` だけで、M と非M が**上書きし合っていた**。
どちらも 2026-09-21 に `V.out_dir()` と `hand` 付きの名へ直した。
