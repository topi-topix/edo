**焼き直した FBX が「姿を変えていない」ことは、頂点の多重集合(`Counter`)で示す。**

⛔ **整列して位置で突き合わせない。** 丸めて `sorted()` した 2 本を `zip` で比べると、
**1 頂点でも増減・移動があると以降の対応が総崩れ**になり、実際には 0.24mm しか動いて
いないのに **13.05m(= bbox の Y 幅)という偽の最大差**が出る。2026-09-22(EDO-0375)に
これで 3 分溶かした。

⭕ **`Counter(old) - Counter(new)` と逆向きの差**で「片側にしか無い頂点」を数え、
その余り同士の最近傍距離で移動量を測る。EDO-0375 の実測(入母屋 5 本 + 11x11):

| | 頂点数 | 一致 | 動いた | 最大移動 |
|---|---|---|---|---|
| 5x3 | 8,827 | 8,219 | 608 | **0.24mm** |
| 7x6 | 15,592 | 14,584 | 1,008 | 0.24mm |
| 11x11 | 33,666 | 31,980 | 1,686 | 0.24mm |

動いたのは `ridge` の `rh=True` 化ぶんだけで、**瓦場は 1 頂点も動かない**。
⇒ 焼き直しは安全だと数で言える(bbox と tris が `docs/asset-index.tsv` と完全一致することも併せて見る)。

**⚠ 面の突き合わせの「丸め」は 1mm では細かすぎる。** 位置の巡回キーを **1mm** へ丸めると、
0.2mm 動いた面が丸めの刃をまたいで**別の鍵**になり、実際は反転しているだけの面が
「不一致」に落ちる(2026-09-22 EDO-0394: `RokaGeya_2ken` は 1mm で 反転24/不一致16 → **1cm で 反転40/不一致0**)。
⭕ **1cm(`round(x, 2)`)で取り直して不一致 0 を出す**と、「全部の面が対応し、違いは巻きだけ」と言い切れる。
⚠ 1mm のままでも Kirizuma は不一致 0 で出る — **型によって出たり出なかったりする**ので、
不一致が残ったら欠陥と決める前に丸めを緩めて確かめる。

**⛔⛔ 既存 FBX を読み込んだ検証レンダは、`V.hook_textures()` を忘れると
「背景一色の真っ白(真マゼンタ)」になる。** 板が1枚欠けるのではなく**何一つ写らない** —
Village Kit 由来の FBX は `TransparencyFactor` を持っていて Alpha 0 で読まれるため。
カメラ・bbox・ortho_scale を 3 度疑って画角を組み直した(2026-09-22 EDO-0394)。
⭕ 順は **import → `V.studio()` → `V.hook_textures()` → カリング/マゼンタ**。
⚠ 「オブジェクトは in_view_layer で hide_render も False なのに写らない」なら、まずこれ。

**⛔ `V.studio()` は world を差し替える。** マゼンタ背景(穴の検査)や
`use_backface_culling` を **studio の前**に設定すると無かったことにされ、
ふつうの灰色の画が返ってくる(気づかず「穴は無い」と読みかけた)。⭕ **studio の後**に入れる。
⚠ マゼンタは環境光としても効くので**画全体が紫に転ぶ** — 穴は「彩度の高い素のマゼンタ」で
見分ける。格子・連子はマゼンタが透けるのが正しい姿。

**⛔ 部材の在処を材質名で絞れると思わない。** 鬼瓦を出そうとして `roof ornaments` の面の
bbox を採ったら、**棟モジュールが同じ材質を使っている**ので屋根ほぼ全域が返った。
⭕ 生成関数(`R.oni`)を一時差し替えて**置いた駒の `matrix_world` を控える**のが確実。
⚠ そのとき `bpy.context.view_layer.update()` を挟む(→ [[stale-matrix-world-after-location]])。
