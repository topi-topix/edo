2026-10-12 EDO-0502 第121巡(EdoBuild.HeiTenbaProfile / HeiProfileRows / NeribeiLineRun・EdoBuildHeiTenba.cs)。

1. **頂点の座(「辺の始まりの座 e35 23.27」)は芯線の折れ点(両辺の芯線の交点)で読む**。控え d が辺で替わる大きな隅では折れ点が区画の頂点から離れる
   (P29 +1.00・P32 −0.11・P35 −1.45・P37 −4.1)── 指図の段の点(辺の走り s)は頂点を基準に書いてあるので、辺34 s13.45 が P35 の折れ点の 0.14 先 = 隅の駒の中に入った。
   ⇒ 段が隅の駒の中なら、書かれた辺の側の「腕の最短 0.2 + 棟止めの柱 0.104」へ寄せる ⚠(HeiTenbaProfile の stepClear)。寄せた量は報告へ。
2. **KadoFace の篩つきの厳密解の下限 sin12° は、6.8° の P37(d 0.80→0.30)で両腕の面を 0.50 食い違わせた** ⇒ sin3°(bigCornerDeg と同じ)へ。隅は交点(頂点の 4.1m 手前)へ滑り、
   辺37 の run は s −3.37 から始まる(EdgePt は負の s でも線を延ばすので通る)。
3. 隅の腕の分け(SeatHeiLineKado・測り)は**折れ点**から見た二等分の線で ── 区画の頂点で分けると P29・P35・P37 は全頂点が片腕に入り「腕の足が測れない」で据わらず −0.10 のまま残った。
4. 城の石垣の駒の天端は水平 ⇒ 坂なりの区間の台は 1.80 ごとの段・天端 = 区間の高い方(塀の底は埋まる側・隙0)。出隅の駒(P24)は両脇を高い方へ揃えないと「天端が違う」で据わらない。
   台の駒の倍率が算出物 base[].s(前の座で焼いた)のままだと見付が足りず浮く(NW_Hei 辺28 s0〜4 で 0.65)⇒ 7 で解いた(浮き 0.087)。
5. Stage2 は帯の均し(WriteFootBand を外周全体の線で)で 30 秒を超え、MCP が送り直す ⇒ 呼ぶ execute_code の頭で印のファイルの合言葉を見て二度目を止める(run.mark)。
6. 指図の段の高さの向きを取り違えると(段を下りに足した)区間の終わりで 2Σh の残差が黙って出る ⇒ 残差 > 0.002 は ★ で線を当てない。
7. 台の区間と倍率(runs[].sFrom「棟梁が実地形から導く」)は天端の線の座で解き直す(HeiLineBaseFromTenba)── 算出物 base[] は旧い座で焼いてあり、辺20・29・32〜34・36〜38 に台が無く
   塀が FillUnderFoot の土の柱(最大 4.4)に載った。**1.0m 未満の台の切れ端は置かない**(0.1m の区間で控え c の測りが上限 2.5 に張り付き d が 2.8 に化けた)。台を替えると c→d→折れ点→勾配が動き、
   N の勾配の駒を焼き直すことになる(1 巡で 9 勾配 + 隅 10)。
8. FillUnderFoot の足 = 駒の最下点から 0.05 は坂なりの駒で低い端の一筋だけになる ⇒ その所の最下点(半径 0.15)から 0.05・足の高さも節点の近くの足で(EdoBuildChikei)。
**How to apply:** 天端の線を他の範囲へ広げるときは、まず HeiLineTenba の行(区間ごとの勾配・寄せた段)と KadoFace の「折れ角が浅い」を grep。新しい勾配の駒は S2 の「駒が無い」「部材が無い」から --list を作って焼く(r121/bake_list.txt の形)。
