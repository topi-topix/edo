層どうしの**比**(常緑:落葉など)を計画本数から解いても、**検査は据わった駒で測る**ので
混んだ庭では届かない。樹冠の大きい層が場所取りと軒の当たりで先に負けるため、
外れ方は偶然ではなく**一方向に偏る**。

**Why:** `TakeSite` は `MaxCrown(パレット)×ScaleHi` の空きを要求し、`Put` の後も軒から
`PadEave` を満たさない駒を落とす。だから樹冠が大きい層ほど二重に落ちる。
2026-09-22・EDO-0323 の `sanbezaka_ooka`(tsubo)で踏んだ: 落葉の意図は モミジ3+帯12 で
紙の上は 29% だったが、据わったのは モミジ1・帯3 で実測 8%。この区画は
退避で拒んだ駒13・軒へ食い込んで落とした駒8。効いていたのは樹冠の差で、
`MaxCrown` は **モミジ 3.49m / 常緑中木 2.98m(+17%)**。同じ庭に同じ数を頼んでも、
モミジだけが据わらない。

**How to apply:**
- 比を実装したら、**意図と実測の両方**を刷って差を見る(`want`/`got` が既にある)。
  「式どおり入れた」で終えない — 合否は `got` 側で出る。
- 実測が届かないとき、**まず据わりの記録を読む**(置けなかった駒・軒へ食い込み・急斜面)。
  そこに数が立っていれば、比の式をいじっても直らない(⛔ 係数を上げて辻褄を合わせない)。
- 樹冠の差は `EdoBuild.CrownR(パス)` で即測れる。層を足す設計を受けたら、
  同じ役割の既存層と `MaxCrown` を比べて報告に添える。
- 直し方(小振りな個体を使う/別の置き場も許す/意図の本数で計る)は**意匠の判断**なので
  差し戻す。→ [[measure-dont-nudge]]
