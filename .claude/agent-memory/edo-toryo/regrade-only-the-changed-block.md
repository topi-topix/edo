段(terrace)の高さだけが改まったとき、`Stage1_Grade()` を**敷地全部**で流すと `DesignY` が
築山の盛土も池の掘削も知らないので**平らに戻る**。しかも `1b` / `6a` / `6a'` は
`Niwa/_markers/*` のマーカーで二度流せない(⛔ マーカーを消して流し直す、はもっと危ない)。

**How to apply:** `Stage1_Grade(float[] clipUV)`(格子 u,v の矩形)で**変わった段とその法面だけ**
流す。松江松平 2026-09-20(EDO-0288)は `{-58, 2, 20, 32}` で 613 格子点・切土 735㎥・盛土0。
⚠ 範囲に築山(v≥33)・池(v≥35)・遣水・滝見口を**入れない**。世界座標では v が増えると z が減るので、
グリッドの向きを確かめてから箱を決める(松江松平は 池の水面メッシュが z 1172..1192 / 箱は z 1200..1254)。

**確かめ方:** 流す前に heightmap を scratchpad へ `.bin` で退避し、流した後に差分の
**格子点の数と世界の外接箱**を出す(`613 点 / 下げ最大 0.301 / x −685.9..−591.9 z 1200.1..1254.1`)。
⛔ `GradeQA` の「0.30m 超ずれ」件数は**池と築山が常に入る**ので、それ自体は欠陥ではない
(松江松平は 158 件 = 池と築山。流す前は 762 件だった)。

関連: [[regrade-then-reseat]] は無い — 動いた地盤の上に居る駒は毎回**退避と突き合わせて**拾う。
