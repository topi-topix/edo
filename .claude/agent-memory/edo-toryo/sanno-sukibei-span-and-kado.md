山王権現社の透塀・袖塀(2026-09-16 実装)で踏んだ三つ。**どれも「据え方」ではなく「名前と測り方」の罠**。

1. **部材名の mm を算出物の座標から作ると 1mm ずれる。**
   `sanno_impl.json` の座標は小数4桁で丸まっているので、辺長 ÷ 本数 の mm が
   焼いた部材と 1mm 違う(実測: 透塀 `Sukibei_S` 2530 ⇔ 焼いた 2531 / 袖塀 4201 ⇔ 焼いた 4200)。
   ⇒ **±2mm まで探して、拾ったらログでそう名乗る**。⛔ 似た寸法の別部材で代用しない。
   割り付けの規約そのもの(本数 = round(辺長 / `bom[透塀].spanBaseM`)・スパン = 辺長 / 本数)は
   指図の側にあり、正典は生成器の `sukibei_span_plan`。⛔ 実装が数を持たない。

2. **隅部材を run の命名(`<run>_<k>f`)で据えると、突き合わせの「芯」が 0.29m 動く。**
   `EdoSannoSashizuCheck` の囲いは **`segs` の外接矩形の芯**と **`*f` 部材の外接矩形の芯**を
   比べる。隅部材は隅柱の芯に据わり seg の端から ~0.49m 張り出すので、run ごとに 8 件の
   「芯が 0.29m ずれている」が必ず立つ。⛔ **名前を変えて検査から隠さない**(隠すと隅は
   どの検査にも掛からなくなる = 未検査)。直すなら検査の側(隅を別に測る)で、それは呼び出し元の判断。

3. **`joints` の「出隅/入隅」の呼び名は折れ線の凹凸と食い違うことがある。**
   2026-09-16 時点で 8 隅のうち 4 隅(北の段・南の段)が逆。総数(出隅6・入隅2)は合う。
   ⇒ 実装は**折れ線の凹凸(符号付き面積で向きを取ってから外積)から測って**据え、
   食い違った隅を名指しでログに出した。⛔ 黙って呼び名に従わない・黙って直さない。

**Why:** どれも「建て方が間違っている」ように見えて、実は指図・検査・部材の**名前の突き合わせ**の
問題。取り違えると、正しい実装を壊す方向へ手が動く。
**How to apply:** 透塀・袖塀・回廊を触る回は、据える前にこの3点を確認してから段を流す。
