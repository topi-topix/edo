## 御殿複合の組み方

**目的は一体の屋根群に見せること**(SKILL.md §B-2、[福井図])。

- Village Kit の棟を**躯体間0.6mで並べる**。軒が重なって連続複合に読める。
  **躯体 = `Roofs` 子孫を除いたメッシュのローカルAABB**:
  ```csharp
  bool isRoof = false;
  for (var t2 = mf.transform; t2 != null && t2 != tr; t2 = t2.parent)
      if (t2.name.ToLower().Contains("roof")) { isRoof = true; break; }
  ```
  この判定で置かないと「軒同士が2m離れた別棟」になる(バウンズ基準だと壁は2m空く)。
- 配置は **表御殿を門の正対軸**に、台所・役所を側面列、奥御殿を背後、長局を反対翼
  ([西川1959]の表→中奥→奥の一列連続)。
- 分棟しても **2〜6.5m 以内**(渡り廊下で繋がると読める距離)。72m離して破綻させた実例あり。
- **Manor の向き**: facade +Z、**OBB中心 = facade 狙い位置の 31.2m 奥**(facade+35.2/OBB中心+4.0 の差)。
  これを使うと崖肩に facade を合わせる配置が一発で決まる。

**渡辺邸で使った具体配置**(躯体間0.59〜0.62mを達成):
表御殿(BigHouse 26.2×24.2)を門の正対軸に、台所(SmallHouse ry=90)を西へ0.6m、
役所(HouseB ry=0)を台所の南へ0.6m、奥御殿(House)を表御殿の背後へ0.6m、長局(HouseB)を東翼へ0.6m。

## 上屋敷のドレスアップ

家門・大藩の**上屋敷にしか無いもの**を足すのが正道([福井図]の御成セット):
- **表門両番所**: `edogoyomi/es_dbansho/dbansho.obj` scale1.818(3.6×2.1m)。前面=ローカル+Z
  (nokigawara が +Z 端にある)。門中心から u=±11、**前面を門の前面と面一+0.15**、街路地盤に接地。
- **能舞台**(アセットが無いので合成): 台=Cube(6.4×0.85×6.4, ベンチのProps木材)、柱=Cylinder×4、
  鏡板=Cube(5.6×2.4)、屋根=**Village Kit Small House を Instantiate して Roofs 子だけ残し**
  scale(0.57,0.8,0.63)。表御殿の脇の白洲に、正面を御殿へ向ける。
- **邸内稲荷**: 朱鳥居(Cylinder×2+Cube笠木/貫、URP/Lit朱)+祠(石基壇+木箱+`roof 2x2`×2の切妻)
  +春日灯籠一対。奥庭の築山の上、参道は庭へ。旗本屋敷では**北東角(鬼門)**。
- **茶屋**: Small House ×0.72 を池畔に。**厩+馬場**(fence A x8 を y0.5 で柵2列)+**中間長屋**は表の脇。
  蔵前に俵(RiceBarrel ×1.2)。
- 順序: 構造物 → スプラット(白洲/馬場土/芝) → 植栽 → 州浜 → QA。

⚠ **合成コンテナ(Umaya/井戸/稲荷)の pivot が原点にある**ことがある(子を世界座標で置く実装のため)。
`transform.position` 基準で動かすと絶対座標分すっ飛ぶ。**移動は子バウンズ中心→目標点の差分**で。
⚠ 稲荷の子オブジェクトを一括で terrain スナップすると祠の基壇/屋根の localY が壊れる。
接地は**鳥居・灯籠など独立据えの子だけ**。壊したら design localPosition を再代入して直す。

## Estate-local placement frame (u,v)

**origin = LIVE な門の transform 位置**(門は手調整済み。ビルダーの設計 gateT ではない)、
û = 区画ポリゴンの街路辺方向、v̂ = 内向き法線。
`streetYaw = Atan2(-v̂.x, -v̂.y)·Rad2Deg` → yaw `streetYaw` の建物が街路/門を向く
(Village Kit の facade = local +Z)。
**フレームの検算**: streetYaw が既存の手置き建物の ry と一致すること(例: 加納 327.5≈328 ✓)。
World: `pos = gate + û·u + v̂·v`、`y = terrain.SampleHeight + terrain.position.y`。

Akasaka frames (gate pos / û / v̂):
- 太田: (118.89,242.05) / (-0.7549,-0.6563) / (-0.6563,0.7549) — u<0=東(B角), u>0=西(C角)
- 加納: (21.21,309.36) / (0.8437,0.5369) / (0.5369,-0.8437)
- 鍋島: (-90.20,242.73) / (0.8175,0.5762) / (0.5762,-0.8175)

## クリアランス(実際に起きた衝突)

- **Castle-Wall 石垣は敷地側へ ~7.6m の中空躯体**を持つ。建物**中心 ≥ 10-13m** を境界から取る。
  共有壁は片方の屋敷の持ち物で、躯体もその側にしか無い(隣は ~2m でよい)。
- **edogoyomi 長屋の内面は ~8m 食う**。長屋のある街路辺は v ≥ 12-14。
- **門一式(k_mon/nagayamon/h_mon + 袖塀 + 番所)は内側へ ~13m**。御殿前 ≥ v15(前庭15-20mが正解)。
  参道の躑躅は |u| ≥ 14。
- 斜めの辺は軸別マージンで判定不能。**辺の直線に対する符号付き距離**を建物矩形の最悪隅で取る。
- **閾値は建物種別で変える**: 主要建物(御殿/主屋/台所)は輪郭で**≥8m**(石垣の中空躯体7.6m)、
  蔵・厩・中間長屋は**≥6m**(史実でも敷地の周囲・隅に置かれる小規模棟)。
  一律9mにすると小さな敷地で解なしになる。建物間は **≥2.0m**(同一御殿群の別棟は2〜3m)。

## QAはOBBで、配置は探索で解く

- **世界AABBの距離は回転建物で嘘をつく。過検出も見逃しも両方起きる。**
  AABBで「壁2.8m ⚠」と出たものを過検出と判断して放置したら**実フットプリントでは0.2m貫入**していた。
  逆にAABBで0.3mだった蔵は実際は11m空いていた。
  必ず**実メッシュ頂点からローカルAABB(=OBB)**を作る:
  `t.InverseTransformPoint(mf.transform.TransformPoint(v))` の min/max。
  輪郭点(8〜12点)を相手OBBのローカル系に入れて符号付き距離。負値=めり込み量。
- **ピボット偏心を甘く見ない**。Village Kit は pivotOff が中心から最大(6,6)、
  Manor は facade +35.2 / back -27.2。「中心間距離−半寸法」の暗算は必ず外れる。**置いてから測る**。
- **手で詰めると振動する(1件直すと別の1件が出る)。合格基準を決めて総当たり探索させる**:
  目標(u,v)アンカーの周囲を1m刻みで走査 → 壁距離・他建物距離の制約を満たす中で
  **アンカーに最も近い点**を採る。これで3件が1回で解けた。
- 疑わしいペアは**メッシュ頂点サンプルの最小距離**で個別に測る
  (NohButai-御殿 8.5m、Chugen-内壁 0.4m=正常な背付け、と判別できた)。
- **屋根部品名をフィルタ**(`n_hira/n_noki/n_taruki/n_maru/mune/oni/kera`)—
  軒の重なりは可、`n_wall`/`n_dodai`/`CW_*` は実害。
- **AABB corner→壁線距離は回転建物で常時誤検出**(0.3-2.9m と出ても実OBBでは11m超)。
  ⚠が出たら中心距離−実半対角で再計算してから動かす。

## 平坦パッチ探索

(u,v)グリッド(6m刻み)で「建物サイズの矩形の四隅+中点の地面 min/max」を走査し高低差最小を探す。
赤坂の台地上面は広く平坦なことがある — 諦めて縮小する前に測る(Manor級64×50mでΔ0.60mが見つかった)。

- **大きい建物から**置く(小物を先に置くと御殿の唯一の適地を塞ぐ)。
- **大型アセットは置く前に OBB を測る**(Manor=38×62m。幅40m級の平坦帯には物理的に入らない。
  世界AABBは回転で73×67に膨張し「解なし」や誤配置を連発した)。
- 探索の `Free()` には必ず **(a)ポリゴン内 (b)辺マージン (c)白洲 (d)通路 (e)既存建物AABB** の
  5条件を入れる。入れ忘れると既存棟の真上に「最適点」が出る(静遠館が長局に重なった)。
- **合成コンテナは中心1点の地形高で置くと斜面で子が浮く**(浮2.37m)。
  四隅±2.5mの地面スプレッド ≤0.8 を配置条件に入れる。
- **FlatNear(中心点の辺距離だけの探索)は台形区画で建物の角がはみ出す**
  (14×10建物の半対角8.6m > edgeMargin 4m)。QAで edge<0 が出たら
  OBB輪郭12点を poly 内制約にした総当たり(1〜1.5m刻み)で再配置。
- 傾斜地で1辺だけ深く埋まる時は**90°回して薄い辺を斜面に向ける**と埋没が半減する
  (井上台所 1.88→0.80、戸田役所 3.34→0.41)。
- 納まらない建物は無理に置かず **`SetActive(false)` で保留**し、ビルダーに保留理由を書く。
- **斜面の建物QAには「埋/浮」を入れる**: bounds四隅の (ground − bounds.min.y)。
  目安 埋≤1.0 / 浮≤0.7。浮きが2mを超える置き方は調整で救えない — パッチごと変える。

## ⛔ Village Kit のプレハブは御殿には使えない

**ユーザー裁定(2026-08-14)。この判断を覆すのは新しいアセットができてから。**

理由は寸法ではなく**構造**:
- Village Kit の家は**壁で閉じた一軒家**。入側(廊下)から見ると**壁が見える**。
- 実際の御殿は**廊下に面して障子・襖が並び、そこから室に入る**。壁が来るのは外周だけ。

したがって「矩形にプレハブを詰める」も「プレハブの組み合わせから矩形を導く」も、
**同じ理由で破綻する**。両方やって両方差し戻された:
- 矩形に詰める → 幅が合わず身舎の26〜45%が空く / 重ねると内部に穴が残る
- プレハブから矩形を導く → 棟の寸法がバラバラになり**廊下がぐちゃぐちゃ**になる

→ **御殿は専用アセットを Blender で作る。着手済み(2026-08-14)** — 下の「Blender で御殿部材を起こす」。

## Blender で御殿部材を起こす

**Village Kit はプレハブが閉じた箱なだけで、`Meshes/` には障子・白壁・縁・柱・畳・瓦が
単体 FBX で425点ある。** 閉じた箱を壊すのではなく部材から組み直す。
キットは **2.0m/間** なので **×0.909 で江戸間(1.818m)に端数なく一致**する
(畳 1×2m → 0.909×1.818 = 江戸間の畳、柱0.2角→0.182=六寸角、建具高3.0→2.727)。

手順・規約・落とし穴は **`<project>/Tools/Blender/README.md`** が正典(ここには書き足さない)。
生成は `blender --background --python Tools/Blender/build_goten_parts.py` 等でヘッドレスに回す
— 指図が変われば作り直せるようにするため。

要点だけ:
- 書き出し規約は Unity 座標で 幅X/高さY/厚みZ、**表 = +Z**、ピボット = 一間の中心・床レベル
- **マテリアル名は Village Kit のまま**にする。同名の `.mat` があるので Search&Remap で当たる。

### ⚠ 全モデル一括の remap を軽い気持ちで走らせない(2026-08-23 に PC が止まった)

`RemapGotenMaterials()` 相当の「配下の全モデルを回して
`SearchAndRemapMaterials(..., ModelImporterMaterialSearch.**Everywhere**)`」は、
**モデル1点ごとにプロジェクト全体を走査**する。ベンダーパックを抱えた本プロジェクト(約6.9GB)では
これが十数分メインスレッドを塞ぎ、**Unity が無反応になりユーザーの PC がフリーズしたように見える**
(MCP は `Command TCS timed out (36 consecutive)` を吐き続ける)。CPU は張り付くのに
`Library/Artifacts` は増えないので「固まった」と誤診しやすい — 探索で回っているだけ。

**新しく出した数枚に当てたいだけなら、既に解決済みの同族モデルから対応表を写す。**
プロジェクト走査はゼロで済む:

```csharp
var refImp = (ModelImporter)AssetImporter.GetAtPath(既に当たっているFBX);
foreach (var kv in refImp.GetExternalObjectMap())      // 例: roof / roof ornaments / wall C / wood
    imp.AddRemap(kv.Key, kv.Value);
AssetDatabase.WriteImportSettingsIfDirty(path);
AssetDatabase.ImportAsset(path);
```

一括 remap を流すのは**部材の材質名を変えたとき**だけにし、走らせる前にユーザーへ
「数分〜十数分 Unity が固まる」と断ってから実行する。
なお**中断しても既に書けた分の対応表は残る**(途中で落ちても、当たったモデルは当たったまま)。
  新規マテリアルを作るとリアルさが既存建物とズレる
- 屋根は瓦が実ジオメトリなので、`roof 2x2` を流し葺きに並べて屋根面で切る。
  **ブーリアンは使えない**(非マニフォールドで型そのものが返る) — 平面 bisect で切る
- `bpy.ops.transform.rotate` は正の値で**時計回り**。回転は行列で書く

### 雁行する棟どうしの屋根の取り合い(U: ユーザー裁定 2026-08-14)

⛔ **旧記「谷や隅は作らない。各棟は独立した入母屋のまま置き、接続部は渡廊下の低い切妻で処理する」は
2026-08-27 のユーザー裁定(松江松平)で撤回された。** 棟を1間離して渡廊下を挟むと軒の出が重なって
成立しないため、**谷樋(妻谷=大棟と直交・軒谷=大棟と平行)で受ける**形が採られている
【U 2026-08-27。谷樋の作法「縦樋を立てず両端の軒先へ落とす・勾配は中央から両端へ 1/100」は
確度P=一般類型で、史料の典拠は無い】。
⭕ **棟どうしが離れている場合**は従来どおり渡廊下の低い切妻で処理してよい(下の縛りが効く)。
⛔ **1間しか離せない所で渡廊下を挟まない** — 切妻の端 0.30 + 両隣の軒の出 0.90 ×2 = 2.40m >
1間 1.818m で瓦が突き抜ける。2間(3.64m)へ広げるか、突き付けて谷で受ける。
⚠ **1棟の身舎を平行な帯に割って谷で受ける**構成(土井 2026-09-06 の案C)も同じ谷樋の作法に乗る。

設計上の縛りはひとつ — **渡廊下の大棟の天端が、棟の軒先より低いこと**。
渡廊下の屋根は両端が少し長く作ってあり、棟の軒の出と重ねて突き付ける(離すと隙間が出る)。
数値と手順は `Tools/Blender/README.md` の「雁行する棟の取り合い」、
Unity 側は `EdoGotenKit.Roka()`(板敷き+柱+桁+高欄+切妻)とその定数。

長屋(`es_knagaya`)・門・土蔵(`es_kura`)・石垣(Castle Wall)は**そのままで問題ない** —
これらは元々「外から見る閉じた箱」なので構造の矛盾がない。

### 入側は身舎の四方に回す(U: ユーザー裁定 2026-08-14)

前後(梁間方向)だけに取ると、**妻側の白壁が廊下に面する** — Village Kit のプレハブを
捨てたのと同じ欠陥がそのまま出る。二条城二の丸御殿も六棟を取り囲む廊下が一周する
(確度U — 一般知識で、このスキルに典拠を登録していない)。

- 実装は `EdoGotenKit.Mune(iriX: 1)`。妻側は白壁でなく障子になり、濡縁も四方に回り、
  屋根の桁行が2間広がる(屋根FBXの寸法もそれで生成する)
- **敷地の取り分は増えない**。指図はもともと身舎の外周に廊下の帯を描いているので、
  その帯を「棟の一部」として組むか「別の床」として敷くかの違いでしかない
- 隅の升目(入側どうしが交わる所)には建具を立てない。立てると廊下が角を回れない
- 座敷飾り(床の間・違い棚・帳台構)は妻側の建具を `openBays*` で抜いて据える

### 指図が間割りに乗っていないときは、指図の方を直す(U: ユーザー裁定 2026-08-14)

メートルの丸い数字(14/22/36m)で描いた指図は江戸間 1.818m の倍数に乗らない。
`Mune()`/`Roka()` は整数間しか受けず、端数を残すと**柱・障子・畳・屋根のモジュールが端で崩れる**。
→ **柱割りを正とし、指図の寸法を書き換える**(岡部邸で最大 ±0.91m 動いた)。

⚠ **指図に書いた畳数を独立した典拠として扱わないこと。**
岡部邸では 面積 ÷ 1.65256(江戸間の畳1枚 = 0.909×1.818)で13棟中12棟が記載畳数と
**±1畳以内**に一致した — 畳数は寸法から逆算した従属変数で、拘束にならなかった。
**まずこの割り算で従属かどうかを確かめる**。合わない棟があればそれは寸法を後から変えた
取りこぼし(岡部邸の長局棟(西)がそれで、幅12m時代の畳数が残っていた)。

### 渡廊下は1間では成立しない

切妻屋根は両端が 0.30 長く、両隣の棟の軒の出 0.90 と **1.20 ずつ重なる**。
重なりの合計 2.40m が廊下の長さ 1.818m を超えるので、瓦が棟の屋根を突き抜ける。
**2m程度の隙間は2間(3.64m)へ広げる**か、隙間を詰めて入側どうしを直に継ぐ。

### 廊下の連結は機械で確かめる

「廊下は一続き」は目視では守れない。**通れる面(入側の環 + 渡廊下 + 参道 + 石段)を
ラスタに落として連結成分を数える**。1個でなければどこかで切れている。
岡部邸では石段の取付きが **0.36m 届いていない**のをこれで見つけた
(実装例 `EdoOkabeYashikiBuilder.RokaConnectivity()`)。
⚠ 段を跨ぐ所・間割りに乗らない所は**端で突き合わせず、両側へ1m弱食い込ませる**。

## アセットパレット (URP-ready)
