## run の天端は一定。地形追従で置かない ★

**一本の run(長屋でも塀でも)は、ひとつの天端の高さで通す。** 石垣の
「天端は丸い数字で一直線」(`unity-modular-stonewall` §2)と同じ規律を、上に載る長屋・塀にも掛ける。

**やってはいけない**: `NaturalMode`(地面追従)で一枚ずつ地面に落とす。棟が一枚ごとに段々にずれ、
なまこ壁の下端が埋まったり浮いたりする。**2026-08-15 岡部邸で実測**した振れ幅:

| run | 延長 | 部材数 | 天端の振れ |
|---|---|---|---|
| 南辺(東) | 141m | 19 | **17.7m** |
| 北辺(中) | 155m | 104 | **15.4m** |
| 南辺(西) | 63m | 9 | 13.7m |

**How to apply**:
1. **造成を境界まで伸ばす**。段の矩形の中では外周の足元まで郭の高さに均す。
   造成が境界の手前で止まっていると、外周だけが生地形に載る(岡部邸は 1.4m 手前で止めていた)。
2. **run は郭ごとに割る**。段の境で切り、段差は石垣で落とす。石垣は境界まで延ばす。
3. 段の外(造成しない辺)は生地形に載せてよいが、**run を 40m 以下に割り**、各 run は一定にする。
   天端は区間の中央値を 0.5m 刻みに丸めて決める。
4. **門・隅櫓も段の高さに合わせる**。門は両袖の長屋と棟高も揃える(屋敷の顔なので一番目立つ)。

**検査**: run ごとに「据えた部材の天端の最大−最小」を出し、**0.05m を超えたら警告**する。
目視でなく数字で押さえる(廊下の連結検査と同じ考え方)。

## 表門の形式 — 石高から一意には決まらない

⚠ **[表門格式表] は確度 ? へ降格した(2026-08-21)。** 出典 URL は 404 で、Wayback から
復元した本文に**石高別の表は無く**、「五万石以下の**旗本**屋敷」という破綻した記述を含む。
下の表は**この表が正しいと仮定していた頃の記述**で、根拠として引いてはならない。

| 家格・石高 | 表門 | 番所 |
|---|---|---|
| 国持大名 | 放れ門 | 両番所・石仕上げ・唐破風 |
| 10万石以上 | 長屋門 | 石仕上げ・唐破風 |
| 5万石以上 | 長屋門 | 石仕上げ・**片庇** |
| 1万石以上 | 長屋門 | 格子窓 |
| 外様大名 | 長屋門 | 石仕上げ不可 |

**代わりに使える確かなもの**(いずれも遺構・確度A)。
- **[黒門]**(旧因州池田屋敷表門・鳥取32.5万石の上屋敷表門・重文) — 門の左右に唐破風造の番所

  両袖が築地塀に連続する単独の長屋門(門長屋)は形式として成立する

**冠木門は大名の上屋敷の表門にはならない**(焼失後の仮の再建など簡素な場合の形式)。

readme は "gate of daimyo's mansion / Please use gate model with **bansho** model" で、

### ⛔ 門の形式と、その辺の囲いの種別は必ず整合させる

**長屋門を建てたら、その辺は長屋塀** — これは**実装上の作法であって史実の規則ではない**
(2026-08-21 訂正)。長屋門は門の両側に門番部屋・仲間部屋を持つ**一棟の建物**で、
**両袖が築地塀に連続する単独の長屋門(門長屋)は形式として成立する**(確度B)。
独立門(薬医門・棟門・唐門・放れ門)なら袖塀＋築地塀。
片方だけ決めて他方を放置すると破綻する。

⚠ **やった誤り(2026-08-15)**: 岡部邸で東辺を築地塀にしたうえで表門を長屋門にした。
根拠にした[追川2017→宮崎1994]「表門に連なる塀に長屋塀を避けた」と加賀藩本郷邸の実例は
**102万石の国持大名=放れ門**の話で、そもそも長屋門ではない。
**国持大名の作法を5万石級に当てはめたのが誤り**だった(ユーザー指摘「長屋門にするなら
築地塀ではなく長屋にしたらいいやん」)。格式の序列(下表)は**門の形式を決めてから**当てる。

### ここから出る帰結

### 部材の据えは「計算して直置き」でなく「仮置き→実測→差だけ動かす」

**ピボットが躯体の外にある部材は、位置を計算で出してはならない。**
edogoyomi の門(`k_mon`)はピボットが鏡柱の面より 2.18m 街路側の**空中**にあり、
しかも部材の向き・flip で符号が変わる。2026-08-22 に岡部邸で
「オフセットを計算して直置き」を **2 度続けて外した**(+5.44m → +0.73m)。

正しい手順（確度 P — 実装上の作法）:
1. **基準面を先に決める** — 何の面を何に合わせるかを指図に書く
   （例: 鏡柱の街路側の面 = 築地塀の板の面）。屋根の輪郭や AABB を基準にしない。
2. **仮に原点へ置く**（オフセット 0）。
3. **その面だけを実測する**（部材名で絞る。`kagami` の頂点の外向き射影の最大など）。
4. **目標との差だけ動かす**。
5. **同じ関数でもう一度測って検算し、ログに出す**。

⚠ 指図（json）に「pivotO」のような**部材のピボット依存の値を持たせない**。
持たせると部材を差し替えた瞬間に嘘になる。指図が持つのは**基準面と目標値**だけ。

- **番所は門と一体**。長屋門なら門の躯体に番所が組み込まれる。
  **独立門では番所は門に接して建ち、その外壁が外周線を引き継ぐ**
  (門 → 繋塀 → 番所 → 築地塀)。離した小屋にはしない。[黒門] 確度A ／ [赤門] 確度A/B。
  **片番所**(出格子)が中位。左右両方に唐破風番所を置くのは国持・御守殿の格なので
  中小藩には使わない。
  独立した小屋を門の脇に離して置くのは誤り(岡部邸で北の番所が 5.97m 離れていた)。
- **袖塀は長屋門には要らない**(門の左右がそのまま長屋へ連続するため)。
  **独立門には要る** — [赤門] は 門柱 → 海鼠壁の繋塀 → 番所 の順(確度A/B)。
  ⚠ 実装では「端パネルを localScale.x ストレッチで実柱へ0.3m差し込む」が袖塀の代用になる。
  **「袖塀は不要」と書いてあるのは実装の話で、史実として不要という意味ではない。**
  袖塀が要るのは薬医門・棟門のように**門だけが独立して建つ**形式のとき。
- したがって「門と塀の隙間を袖塀で埋める」より先に、**門の形式を正す**ほうが根本。

⚠ 岡部邸では冠木門(`Eg.Kmon`)を使っていたため、番所が離れる・塀が門を貫通する・天端が三者三様、
という不具合が繰り返し出ていた。**部材の据え方でなく形式選択の誤り**だった(2026-08-15)。

## 面ごとに囲いの種別を変える — 格式の序列 ★

**格式の要る面ほど築地塀、裏手ほど長屋。** [追川2017]が引く宮崎1994:
「築地塀こそが正式で伝統的な屋敷囲いであり、家臣団の住居を兼用する表長屋は略式で薄礼のもの」
ゆえ「**表門に連なる塀に、長屋塀を構築することを避けた**」。
加賀藩本郷邸(確度A): 表門(赤門)のある本郷通り側に長屋なし / 南の春日通り側が盲長屋 /
東側が長屋塀+石垣。

| 面する相手 | 囲い | 確度 |
|---|---|---|
| 表門のある街路 | **門の形式に合わせる**。長屋門なら長屋塀、独立門なら築地塀＋袖塀 | B |
| 社寺の境内 | 築地塀。家臣の生活の場(窓・物干し・生活音)を向けるのは薄礼 | B |
| 隣地境 | 長屋塀・盲長屋。**ここが長屋の置き場所** | B |
| 水際(池・堀)・庭園帯 | **竹垣・木柵**。塀で閉じると座敷や外廊下から望む景を自分で塞ぐ | ? |

**水際の囲い**: 歌川広重「赤坂桐畑」に溜池の対岸の木の柵が描かれる[広重・赤坂桐畑]。
ただし描かれた対象は寺群の囲いの可能性が高く、**同じ水際の風景からの類推**にとどまる。
在庫は `Village Kit/Prefabs/Fences/Bamboo garden fence (B)`(竹垣・高0.9)、
`edogoyomi/obj_hogaki/hogaki5.obj`(矢来・水際の柵・高0.78)。

**崖線の敷地の囲いは「面の縁」だけに立てる**(ユーザー裁定 2026-08-23【U】— 松江松平邸で確立):
- 練塀・長屋と石垣基壇は**造成した平場(面)が境界に接する縁**にだけ立てる
- **崖の中腹・崖下・谷底・水際に塀を立てない** — この型に典拠は無い。囲いの働きは崖と樹林が担い
  ([橋本・堀1998] 幕府御用地の緑=「外から敷地内の建物を隠蔽」)、生活面の縁=法肩に竹垣、
  境界線上は地形なりの木柵(高さ1.4m・基礎/整地なし)で標示する
- 崖下に塀を通すと数m級の石垣基壇と裾の整地帯が要る — **その土木自体が無典拠の既成事実になる**
  (松江松平で崖中腹の練塀15 run+裾の整地帯を撤回した経緯)

⚠ どれも**型からの推定**。個別屋敷の絵図が無いときは、コミットに
`【典拠: 一般類型/当屋敷の一次史料は未確認】`(SKILL.md §A-3)を明示する。

## 長屋が載る勾配の限界(物理制約)

**剛体8mモジュールは勾配13.7%の辺では成立しない**(渡辺 辺4 で実証・撤去)。

- **急斜面の辺は築地塀にするか、隣家の囲いに委ねる。** 長屋は平坦な辺へ回す。
  (`historical-layout.md`「外周を塀にするか長屋にするか」— どちらも史実の類型なので、
  この物理制約で決めてよい)
- **緩斜面(〜12%)の辺は、足元を「段」でなく連続ランプ整地する。**
  隣接モジュールは設計上0.1m重なるため、段(0.5m刻み)では各棟専用の平場を割り当てられず
  必ず埋/浮が残る(4回作り直して確認した)。走り方向に各棟の高さを通す**折れ線ランプで帯を整地**
  すれば残差は「半モジュール×勾配」まで下がる(渡辺 辺1: 埋5.19→1.46)。
- **段幅が「躯体+軒+路地(約10m)」未満の段には列を置かない。**

## 囲いは石垣の天端に**犬走りを残して**据える ★★

**長屋も築地塀も、石垣の法肩から 0.30m(≒1尺)控える。面一にしない。**
(ユーザー裁定 2026-08-18。確度 U/B)

```
        ┌─ 囲いの外面
        │  ┌─ 犬走り 0.30
        ▼  ▼
   ╭────╫──┐            法肩(天端の外縁)
   │    ║  │╲
   │ 躯体 ║  │ ╲ 勾配(1.4×s → 2.4×s)
```

| 指標 | 基準 |
|---|---|
| **crestOuter − 囲いの外面**(横) | **0.30 m**(長屋のなまこ壁面／塀の壁面とも) |
| **coping − dodaiBottom**(縦・長屋) | **1.51〜1.59 m** |
| 塀の底 | **= coping**(天端そのもの) |

### 門の面も囲いの面へ揃える ★★

**門は塀の面の中に入れる。**門だけ前へ出ると、壁の一部でなく前に置いた飾りに見え、
ユーザーの言葉で言えば「門や塀の意味を成さない」。
2026-08-29 に松平邸で実測すると **小門が +0.59m・表門が +0.26m** せり出し、囲いは −0.30m だった。
⛔ 例外は**番所**だけ — `bansho.protrude`(石垣畳出)で張り出すのが設計の意図。

### 実装では「置いてから測って寄せる」パスを必ず入れる

犬走りは**規則としてスキルに書いてあっても、実装が守っているとは限らない**。
松平邸では規則が 2026-08-18 に決まってから 11 日間、**全 39 run が外れたまま**建っていた
(長屋 +1.63m 引っ込み・練塀 −0.08m せり出し)。誰も測っていなかったから。

```
Stage2 の最後に AlignInubashiri() を回す:
  各駒について 壁面の部材の頂点を外向き法線へ射影した最大値 = 外面
  shift = (法肩 − 0.30) − 外面   を法線方向に足す
突き合わせ(Compare)に InubashiriQA() を足して、0.30±0.05 から外れた駒を数える
```
⛔ **部材の見かけ幅を定数にしない** — 部材を差し替えた瞬間に壊れる。実メッシュから測る。

**なぜ犬走りが要るか**: 天端の縁ぎりぎりに躯体を建てると (a) 軒からの雨落ちが天端の目地を
直に洗う、(b) 笠石が縁で欠ける、(c) 据え付けの余地が無い。実物の武家地の石垣＋塀は必ず
狭い犬走りを残す。城の犬走りは数mになることもあるが、屋敷境では**1尺級で足りる**。

⚠ **撤回(2026-08-18)**: 旧版はここに「なまこ壁の外面を石垣天端の外面と**面一**にする
(crestOuter − namakoOuterFace = 0.00〜0.20)」と書いていた。根拠にした
`historical-layout.md`「犬走りを**大きく**取らない」を「取らない」と読み違えたもの。
**面一の記述は誤り**。0.00〜0.20 の実測値はユーザーの手組みの初期値であって規範ではなかった。

縦は据え方を変えない: 土台底を天端より1.59m下げるので**土台となまこ壁下部は石に埋まって見えず**、
なまこ壁の上端**0.63mだけが天端から出る**(黒帯が天端に刺さって見える)。
躯体(奥行約4.3m)は天端幅1.4mを超えるので、前のほうは石の体積に**めり込む** — これは正しい。

### 生成器での持ち方
run の**ピボット線(＝敷地境)から法肩までの符号付きオフセット**を一箇所に持ち、
そこから 芯線 = 法肩 − 1.4×s / 法尻 = 法肩 + 1.0×s を出す。囲いの種別ごとに:

```csharp
const float INUBASHIRI = 0.30f;                    // 犬走り ≒ 1尺
Nagaya  → 長屋のなまこ外面(run線の内 1.044) + INUBASHIRI = -0.744
Tsuiji  → 塀の外面      (run線の外 0.575) + INUBASHIRI = +0.875
```

⚠ **この値は造成にも効く。** 法肩が run 線より内側だと、敷地の内側 100% を段の高さで張る
造成が**石垣の前に土を残す**。2m 格子では 1m 前後の端数がそのまま楔になり、石垣が三角形に
しか見えなくなる(岡部邸北辺で実測 2026-08-18)。造成の落としは**法肩から内へ 0.7×s(最大1.0m)**
＝石の体内で行うこと。

```csharp
// ry = 外向きyaw(表+Zが外) なので outward = +transform.forward
var fwd = c.forward; var Oout = new Vector2(fwd.x, fwd.z).normalized;
// 近傍6m の石垣ピースから
//   coping     = max(piece.position.y + 4*piece.localScale.y)
//   crestOuter = max proj(頂点, Oout)  ただし y∈[coping-0.20, coping+0.05]
// 長屋側は namako を含む sub-mesh の max proj(頂点, Oout) = namakoOuterFace
float shift = INUBASHIRI - (crestOuter - namakoOuterFace);   // >0 なら内側へ
c.position += new Vector3(-Oout.x*shift, 0, -Oout.y*shift);
```
- 適用後は必ず再測定して収束を確認する。局所の天端は run に沿って動くので**2〜3パス反復**。
- 縦は `dodaiBottom = coping − 1.59` に合わせる。**地形には合わせない。**
- **私が最初にやった誤り**: 長屋を石垣の背後(内側)に置き、外面より0.98m外へ突出させた。
  結果、長屋が石垣に載らず前へせり出し天端が見えた。**設計線からの lat 値で置くのは不可 —
  必ず石垣の実メッシュから測って合わせる。**

### 塀(es_dobei)を天端に載せる場合
- **塀の底 = 石垣の天端(coping)**。coping = piece `position.y + 4.0·scale.y`。地形に合わせない。
  結果は**1 run に1つの base 値・天端線のばらつき0.000**でなければならない。
- 石垣が段になっている区間は**パネル毎に近傍5mの石垣から天端と外面を実測**する(一括値は不可)。
  手組み run は設計線から最大~2°ドリフトするので、run 一括値だと平均0.63m・最悪1.38mずれる。
  ⚠ **出隅ピースを yaw で除外**(支配的 yaw ±4°のみ採用)しないと「天端幅」が1.4mでなく
  3.2〜5.8mと出て run 全体が数m横へ飛ぶ。
- **横は「高い側の天端エッジ」から犬走り 0.30 控えて合わせる**(2回間違えた)。Castle Wall の
  天端は**1.4m幅**だが es_dobei の塀は**0.34m厚**なので、塀は片側のエッジにしか寄せられず、
  反対側に残る天端が「天端の前面が見えて土塀が浮いている」に見える。
  **人が立って見る高い地盤側のエッジ**を選ぶ
  (石垣グループの所有者で決めない)。判定は**測量**で: run 中線から外向き軸に ±1.5/3/4.5/6m の
  地形をサンプルして平均を比較する。石にめり込むのは**問題ない**(ユーザー確認済み)。
- **共有境界の壁は一本化して持つ**([丸の内三丁目] 確度A: 隣り合う2家の屋敷境に引かれたのは
  **1条**の区画溝。両家がそれぞれ建てて二重になる作りではない)。
  ⚠ **どちらが持つかを決める規則は史料未確認**(2026-08-16 調査)。下の「高い側」は
  石垣を土留めとして要るのは高い側という**工学的な理屈**で、史実の裏づけはない(確度P)。
  実際、岡部/土井の共有境界は18点中15点がほぼ同高で、この理屈はそもそも効かなかった。
  **迷ったらユーザーに決めてもらう。**切絵図からは読めない([東大埋文年報3] 確度A)。
- 既にある壁の**所有者を読み取る**には**測量で決める** —
  ポリゴン辺から~4m以内の Ishigaki ピースを集めて coping でバケットし、
  辺全体を単一 posY で張っている run が所有者。
- 隣の高い屋敷の地盤が共有壁の天端より上にあるのは正常(塀は高い側で~1m、低い側で全高を見せる)。
  地形サンプルで base を決めて「直す」と、浮いた/段になった塀になる。
- **Blender で新しい土塀をモデリングしない** — ユーザーに「全然ダメ」と却下された。
  プロジェクトアセット(`s_hei_center.obj` の表裏0.2mペア)を使う。中が中空なのは明示的に可。
- ピッチ = `edge_len / round(len/2.982)`、**localScale.x のみ**ストレッチ(= pitch / 部材の走り方向の実寸)、y=z=1.818。
  実寸は決め打ち(1.6447)でなく `EdoBuild.RunMeasure` が頂点から測る(1.6449)。
  **置くのは前の駒の端の実測へ突き付ける**(`ButtOnRun`)— bounds の中心で決めない(EDO-0302・規則21)。
  Unity 実測(2026-09-21・角度 0/17/90/133/251° の辺 47.3m・練塀16枚/板塀6枚): 継ぎ目の隙 0.004mm 以内・始端終端の誤差 0.02mm 以内・
  表裏の端の食い違い 0・旧(bounds 中心合わせ)との位置差 練塀 0.13mm / 板塀 0.00mm。**塀の位置は旧と変わらない**(旧は `Renderer.bounds` が
  回した箱の中心を返すので、部材が箱形のうちは中心と端が合っていた)。直したのは「決め打ちの 1.6447 と中心」を「実測の端」へ換えた点。
  ⚠ `Renderer.bounds` は回した部材の頂点の外接ではなく**メッシュ bounds を回した箱**なので、頂点だけで机上に再現すると 3〜21mm 違って見える。
  ⚠ Unity の OBJ 取り込みは X が反転する(`RunMeasure` は lo=-1.3002 .. hi=0.3447・OBJ 本文は -0.3447 .. 1.3002)。走りの端は**置いた後に**測る。
- **前辺の塀は「門の左右2セグメント」で建てる**。中央ギャップのスキップ方式は、短い前辺
  (パネル3枚級)で全パネルがスキップ条件に入って塀が消える。

## 長屋 run は単一の格子に乗せる

### ★★ ピッチは**壁の実寸**。屋根で測ると全継ぎ目が重なる(2026-08-23 是正)

`knagaya01c` を部位別に実測すると(scale 1.818・ピボット基準の走り方向):

| 部位 | 走り方向の範囲 | 幅 |
|---|---|---|
| **壁 n_wall / 海鼠 namako / 土台 n_dodai / 垂木 n_taruki** | −4.368 .. +3.697 | **8.065 m** |
| 棟 n_mune | −4.396 .. +3.701 | 8.097 m |
| 屋根 n_hira / 丸瓦 n_maru / 軒 n_noki | −4.38 .. +3.70 | 7.92〜8.08 m |
| 妻部材 `knagaya01l` / `01r` の**壁** | −4.368..+3.542 / −3.542..+4.368 | **7.910 m** |

**繰り返し長は壁の 8.065m。** 旧記述の「屋根幅7.959m / ピッチ7.81」は**屋根で測った値**で、
これで並べると**全部の継ぎ目で壁と海鼠が 0.252m 重なる**。ユーザー指摘(2026-08-23)
「なまこ紋が変・瓦の間隔がずれる・窓の間隔や長さがまちまち・隣に刺さる・隙間がある」は
すべてこの一つの原因から出ていた。

- **ピッチは決め打ちしない。実行時に部材を測って壁の範囲を取る。**
- **妻部材は壁が 0.155m 狭い。** 一律ピッチだと妻の隣に隙間があく。
  **部材ごとの実寸を積み上げるカーソル**で置き、継ぎ目を必ず面一にする
- **走りが反転する辺**(ローカル +X が s の減る向き)では
  `pivot = cursor + m.hi`。非反転は `pivot = cursor − m.lo`。ここを間違えると1ピッチずれる
- **段違いの run は1本の鎖として通す。** run ごとに前後を内側へ寄せると継ぎ目に 8m の隙間があく
  (松江松平の東翼 25.8/27.0/28.8 の雛壇で実際に開いた)。天端は
  **部材の中心が入っている run の seat** を使う → 段は部材の境目で起きる
- 検証は**ピボット間隔でなく壁の実体の継ぎ目**で見る。妻部材はピボット位置が違うので
  間隔は 7.239 / 8.065 / 7.910 とばらつくが、それで**壁は面一**

⚠ 共有の `EdoNishiTameikeBuilder.NagayaRun` は旧ピッチのまま(他屋敷が使っているため未変更)。
**同じ崩れが他屋敷の長屋にも出ている。**作り直すときに寄せること。

`t = t0 + pitch·k`。**横位置・Y・ry は run で1つの基準値**を全モジュールに配る。
- **端部材(`knagaya01l/r`)も同じ格子上に置く**。角へ寄せたいからと任意 t に置くと、そこだけ
  ピッチが6.0や7.3になり瓦が重複・不連続になる。足りなければ**格子を1つ延ばす**か隅櫓で納める。
- **個々のモジュールに石垣フィットを個別にかけない**。run 代表で1回求めた値を全員に配る
  (個別収束は横位置に数cmのばらつきを生み、屋根がわずかに段になる)。
- 横位置は「ある原点からの相対オフセット」で統一。**絶対射影 `pos·N` と混同すると数十m横へ飛ぶ**
  (`p = C + E·t + N·lat` の lat に `pos·N` を入れて90mずれた)。
- **妻側**: `knagaya01c` は妻が開いている。単独棟(厩・中間長屋など)を c だけで並べると横から素通し。
  **走り方向(ローカル −X)で 低t端=`knagaya01l` / 高t端=`knagaya01r`** に差し替える
  (手組みの North/South/West 全 run がこの並びだった)。
- **検証(レンダ前に数値で)**: run 内の ピッチ差=0、横位置幅<0.01m、Y幅=0、ry幅=0。
  正射投影(真上・走り方向を画面縦)で撮るとパースに惑わされず継ぎ目を判定できる。

## 面の裏表は数値で判定する

**`knagaya` の「表」= namako薄板・inner_win・なまこ紋のある側 = ローカル +Z**。これを敷地外へ向ける。
**片面ポリの裏面にも紋様が透けて見えるため、レンダの見た目では裏表を判定できない。**
`namako` 薄板(厚0.01)の頂点を外向き軸に射影し、ピース中心より外側にあることを数値検証する。
門も同様に**控柱(kagami)が敷地内側にあること**で判定する(k_mon/h_mon/nagayamon 共通)。

⚠ **「手組み run との一貫性」チェックは基準 run 自体の向きの誤りを検出できない。**
当初「ry=外向きyaw+180」で全108ピースを内向きに置いてユーザー指摘で全反転した実例がある。

### 108ピース一括反転の手順
1. 反転**前**に固定軸を確定: `outward`(現在の外向き)と `rundir`(走り)
2. 全メッシュ頂点から **走り方向の中心 cenR0** と **外側面 outer0**(外向き軸の最大射影)を記録
3. `c`材は `rotation *= Euler(0,180,0)`。**端部材 l/r は 180°回すと妻壁が run の逆端へ移る**ので、
   **l↔r を入れ替えた別変種**を同 pivot に置いて180°(幅も l/r で0.42m違うため入替が必須)
4. ピボットが中心に無いため反転で footprint が走り±0.7m/奥行にズレる。
   **なまこ薄板面 = outer0、走り中心 = cenR0** の2軸で位置を復元
5. 検証(全数): なまこ面ズレ・走り中心ズレ ≤0.01、`kera` 部の平均位置がピース中心に対し反転前と同符号

## 角(出隅)の閉じ方と隅櫓

角材アセットは**無い**(knagaya01 は c/l/r の直線材のみ)。
ユーザー手組みの角(曲がり −70.5°)を実測すると **両側 run の端部モジュールのメッシュ間距離 = 0.00m**、
つまり**突き合わせて食い込ませる**のが現行の作法。屋根が不透明なので交差部は塞がって見える。
- 端部材のピボットは角の頂点から **2〜6m** 手前に置き、据え方は直線材と同じ収束処理を通す。
- **検証は「頂点までの距離」ではなく「隣接 run とのメッシュ間距離」。** 0.00m になるまで端部材の t を寄せる。

### 隅櫓(採用形)
既存アセットに使えるものは**無い**: Japanese Castle の櫓類は **14〜30m** で長屋(高さ5.5m)の3〜4倍、
縮小すると瓦の粒度が破綻。`jishinban`(自身番)は番所形状で**庇と梯子**が付き、
どう回しても庇が変な方向へ張り出す。

**正解は長屋モジュールの転用**: `knagaya01c` を**走り方向(ローカルX)だけ 0.55倍**に縮めて
4.5m角の小屋にし、**二辺の外向きベクトルの二等分線に正対**させて角に載せる。
- 屋根勾配は yz 平面にあるので **X方向の圧縮では変わらない**(非一様スケールが許される理由)
- 材質・瓦・なまこ壁が長屋と完全一致するので**二重櫓**として自然に読める
- 据え: 土台底 = **天端 + 0.95m**(下段の屋根に深く食い込ませて隙間を消す)、
  平面は**角の頂点から内側へ 2.4m**、`ry = 二等分線のyaw + 180`
- 結果: 棟が下段の棟より **約2.5m** 高くなり、角が「継ぎ目」でなく「意匠」になる

隅矢倉は[福井図]では上屋敷の外周に3基あり、[中屋敷図]には無い → **上屋敷格の装置**。

## 築地塀と門の取り合い

**塀を門より低くして直接接合する**(確定形)。「隙間を塀の延長で埋める」と屋根貫通を起こす。
1. 門の**けらば(大屋根張り出し)下端**を実測(松平表門=16.86。端部ゾーンには屋根しか無い)
2. **屋根の実際の張り出し範囲(t)を実測**し(門本体の y>屋根高 の頂点で t min/max)、
   **その範囲と物理的に重なるパネルだけ**天端をけらば下端−0.15mに切り詰める。
   それ以外の大半のパネルは石垣の段(coping)に追従したまま=触らない。
   ⚠ **run全体を一律の天端に揃えるのは過修正**(一度やって差し戻された)。石垣が何段かに分かれて
   傾斜を追っている区間では、塀もその段ごとに高さが変わるのが正しい。
3. 門の**実柱の位置は壁高さ帯(y13.5〜16.5)の頂点密度**で測る — 全域スパンの端は迷い頂点で1m以上ずれる
   (43.4/54.6 と読んだが実柱は 44.5〜45.0 / 52.5〜53.2 だった)
4. 端パネルを **localScale.x ストレッチ**で実柱に0.3m差し込む(袖塀は不要になる。
   手組みの袖塀は削除でなく `SetActive(false)`)

**埋め込みが許されるのは (a)同種の壁同士が同一線上で重なる (b)端面が相手の躯体に浅く刺さる の2つだけ。
屋根・庇・開口部を横切る貫通は禁止。**

**「隙間ゼロ」を検証するときは必ず「異種構造との重なり」も同時に測る。** 閉塞チェックだけ通すと
貫通で隙間を埋めたことに気づけない。合格条件は
`空隙=0 ∧ 門(屋根持ち構造)との t 重なり=0 ∧ 袖塀差込 ≤0.3` の**3つセット**。

門・袖塀は**石垣天端ではなく門の地盤**に建つので、塀(天端の上)とは 1.2〜1.6m の段差が残る。
これは地形上の正しい段差なので均さない。取り合いは「差し込んで隠す」で処理する。

## 門を長屋列に組み込む

### 長屋門(nagayamon)
- `edogoyomi/es_nmon/nagayamon.obj` scale 1.818。**幅22.5m・奥行6.2m**(pivot中央)。
  扉側ローカル −Z が街路([[edogoyomi-mon-dobei-conventions]])→ `ry = 内向きyaw`。
- 位置合わせは**バウンズ逆算3点セット**: ①幅中心=長屋列の開口中心 ②足元(bounds.min.y)=門前の
  街路平場レベル ③**街路側の面=隣接長屋のなまこ壁外面と面一**(門・長屋の頂点をそれぞれ外向き軸に
  射影して最大値を一致させる)。
- 門幅が開口より広い場合、**両側の長屋に食い込ませてよい**(同種の重なりは許容)。
  鍋島邸では開口14.7mに対し各4m食い込みで自然に接続した。

### 実体エッジで合わせる(重要)
knagaya の c/l/r ともメッシュ実体はピボットから走り方向に約 **-4.3..+3.6**(scale1.818)と大きく非対称。
**ピボット演算で開口を作ると4m以上ズレる。**
正解は 壁高帯(y=基部+1〜3.5m)の頂点を走り軸に射影した min/max を「実体」とし、
門の実体端 ±0.2 食い込みにキャップの実体端を合わせる。
サブラン同士の平行重なりが2mを超えたらサブラン全体をシフト(格子は崩さない)。
k_mon(14.41m幅)は 2枠除去(15.6)ではなく実体合わせで **14.0 開口**になる。

### 既存 run への小門の外科的挿入
NagayaRun の gap 機能は skip 窓が ±(gapHalf+3.9) と広く**長屋門専用**
(腕木門だと3モジュール消えて開口23mになる)。小門は外科的置換で開ける:
1. 置換モジュール(平坦な区間・隅寄りの c を選ぶ)と両隣を実測(走り軸への全メッシュ射影 min/max)
2. 3枚とも `SetActive(false)`
3. 低t隣の位置に `r` 変種、高t隣に `l` 変種を同ry・同ESで新設し、
   **「開口と反対側の実測エッジ」を旧cの同エッジに一致**させる
   (l/r は c より0.4m広く、余幅が自動的に開口側=妻側へ出る。ピボット合わせだと0.5mズレる)
4. 門を旧cのグリッド点に設置
5. 門の外面を長屋 namako 外面に射影一致
6. 門を**キャップ実測エッジ間の中心**へセンタリング(グリッド点のままだと非対称に食い込む)

**腕木門(幅8.0=袖含む)>開口(6.6)でも成立する**: 袖が両側の長屋躯体の中へ埋まり、
開口には門柱+扉だけが見える。妻壁(白漆喰+なまこ)が門を挟む構図になる。
壁実体同士の重なり0.70mまで実証済み。

## run の端数は「棟の間隔」で吸う — 端に残すと継ぎ目が開く ★★

`NagayaRun` は run 長にモジュールの**整数個**を割り付けるので、端数がそのまま端の隙間になる。
岡部邸で実測すると、**長屋の run 11本すべて**が同じ癖だった(2026-08-15):

- a 端に **0.54m の隙間** / b 端に 0.16m の重なり
- → run どうしの継ぎ目が **0.38m 開く**(北辺 9 箇所すべて)
- 表門との継ぎ目は 0.34m と 1.04m。**1.04m の側は屋根にも 0.53m の穴**が開いていた
- 築地塀・竹垣は 0.00。端数を自前で吸う実装になっている

**直し方**: 棟を並べたあと、**棟の間隔だけ**を伸縮して run の両端へ合わせる。

- 棟自体は拡縮しない — なまこ格子が歪む
- 棟どうしは元々 1.2m 重なっているので、間隔を 0.2m 広げても継ぎ目は開かない
- 門に接する端は run の端でなく**門の壁面**に合わせる(門は run 端より外に出ることがある)

**チェックは軸ごとに要る。** 一つ通っても他は破綻している:

| 軸 | チェック | 見落とした例 |
|---|---|---|
| 高さ | 天端の振れ | 天端OKでも街路面が鋸歯 |
| 面(直交) | 街路面の振れ・門との面差 | 面OKでも継ぎ目が開く |
| 走り | run の両端の覆い | 1.04m の穴 |

**「run を辺の全長に並べた」は「閉じた」ではない。** 2026-08-29 に松平邸で、ユーザーが
外周の穴を4箇所まとめて見つけた(EDO-0053)。当時この屋敷には検査が20本以上あって全部 0 件で、
そのどれも**外周の閉じを測っていなかった**(結界の検査はあったが、見ていたのは内側の御錠口だけ)。

### 測り方 — 区画線をまたぐ線を全長で引く

辺ごとに `s` を 0.2m 刻みで走らせ、各点で**区画線の外 2m から内 5m へ引いた線分**が、
外周の物の平面形と交わるかを見る。交わらない区間が「穴」。閉じの検査はこれ一本でよい。

```
覆いに数えるもの: run(長屋・練塀)/ 木柵 / 門の袖と番所 / 隅櫓
⛔ 覆いに数えないもの: 門の開口(扉を申告するまで) / 石垣基壇だけの区間
```

- **run の平面形は線の上に中心を置かない。**長屋は区画線から内へ躯体の深さぶん、練塀は線をまたぐ。
  中心を置いて組むと長屋が外へ半分はみ出した形になり、隅の当たり判定が偽陽性を出す。
- **点の内外判定(point-in-polygon)では捕まらない。**厚み 0.1m の木柵は格子を素通りする。
  必ず**線分と平面形の交差**で測る。
- 実装側でも同じ検査を回すときは、**格子の flood fill(外から歩いて入れるか)**が確実。
  ただし格子で塗ると薄い部材が漏れるので、部材の輪郭を線としてラスタライズしてから塗る。

### 穴の四大発生源

| 出所 | なぜ空くか | 指図で塞ぐ書き方 |
|---|---|---|
| **門の開口** | 門が開口幅と敷居しか持たず、**扉という概念が無い**。建てれば素通し | 門に `leaf`(扉の種別・寸法・確度)を持たせる。無ければ穴と数える |
| **隅櫓の脇** | 櫓を内角の二等分線に据えると辺と斜めに交わり、辺の開口の端が残る | 櫓の躯体の**辺への射影**を計算し、残りを袖塀で継ぐ |
| **run の継ぎ目** | 駒のピッチが割り切れず、run の端に端数が残る | → [run の端数は「棟の間隔」で吸う](#run-の端数は棟の間隔で吸う--端に残すと継ぎ目が開く-) |
| **隅(出隅・入隅)** | 隅部材が無く、両 run が突き付けで終わる | 隅の納め(小口・留め継ぎ)を run の属性として書く |

### 「開口を空けておけ」という検査を書かない

隅櫓のために長屋を引く量を、**「開口をこれだけ空ける」**という形の検査で守らせると、
「櫓の脇に穴が残る」ことを**検査が要求してしまう**。守らせたいのは
**「櫓とぶつからないこと」**であって、開口を空けることではない。
実際の平面形どうしの重なりで測ること。
→ `qa-and-pitfalls.md`「検査の文言と実装の集合を突き合わせる」

高さで判定を分ける: **長屋(躯体が深く背が高い)は櫓の軒を含む外形と、
練塀(丈 2.65m)は櫓の躯体と**当たり判定する。塀は櫓の軒下へ入って取り付いてよい。

### 目の高さの実面で測る(実装側)

実装を測るときは、**軒先で測ると隙間が消える**。松平邸の隅では屋根の反りどうしが 0.09m まで
寄っていて「閉じている」ように出たが、目の高さの壁面では 0.75m 開いていた。
**地盤+0.5〜1.6m の帯に立ち上がりを持つ部材だけ**を集めて測ること。
→ メモリ `gate-wall-closure-rule`(門と塀の閉じは「隙間>めり込み」)

## 塀は傾けない — 段は「読める大きさ」で ★★

**練塀・築地塀は斜面でも傾けない。**水平な塀を段で継ぐ(瓦も柱も水平のまま)。
だから指図で run の天端を `seat0→seat1` の斜めで指定すると、**実装は勝手に刻んで段にする** —
その刻み幅を指図が決めていないと、段の大きさが行き当たりばったりになる。

**一段は 0.25〜0.60m。** 下限の根拠は棟瓦の厚み(当プロジェクトの土塀で 0.17m)で、
**それを下回る段は「段」に見えず、据え付けのずれに見える**。
2026-08-29 に松平邸で、天端 0.60m の下りを 20m の run に指定した結果
**2m ごとに 0.06m** という刻みで建っていたのが見つかった(ユーザーが「土塀の接続がずれている」と指摘)。

### 書き方 — 段ごとに run を分け、各 run は水平にする

```
悪い: 1本の run に seat0=27.93 / seat1=27.00(12m)   → 実装が 6片 × 0.155m に刻む
良い: 3本の run に seat=27.93 / 27.62 / 27.31(4m ずつ) → 段は 0.31m ×3。次の run が 27.00
```

- **隅に接する run は、相手の run と同じ天端にする。**隅の食い違いは「角に段差」に見えて最も目立つ。
  段は隅から離れた直線区間で吸わせる。
- run を割ったら**石垣基壇の丈(`s`)を run ごとに測り直す** — 天端が上がった run は足元が浮く。
  能力は `4.0×s + 0.3`(モジュールの丈)で、**外面の露出**は 2.5m を超えないこと、
  **内側で受ける高さ**は run の天端検査(`run_seat_check`)が見る量。両方を満たす `s` を採る。
- 斜面が急な区間(勾配 20% 超)は一段 0.6m を超えてよい — 大きな段のほうが自然に読める。
