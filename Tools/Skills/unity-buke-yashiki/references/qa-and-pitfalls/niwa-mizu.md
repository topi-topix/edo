# 庭・水・地形の罠(失敗事例集・6 件)

索引は `../qa-and-pitfalls.md`。⛔ 丸読みしない — 索引で当たりを付けて該当節を grep で引く。

## ⛔⛔ `WaterBaker.Create` は **snap 矩形の全域を平滑化して書き戻す** ★★★

**2026-09-06・土井の奥庭。**指図は `impl.waterBaker` で `WaterBaker.Create(pts, depth)` を
指示していたが、**`Create` は内部で `Recarve` を呼ぶ**。そして `Recarve` は

1. snap 矩形(**輪郭 bbox + 余白 150m**)の全域をスナップショットから復元し
2. **4パスの4近傍平滑化**を**その全域に**かけ
3. `td.SetHeights(sX, sZ, H)` で**全域を書き戻す**

土井の池では snap が **312 × 320m** になり、溜池・外堀・岡部邸・松江松平邸の造成が
まるごとその平滑化に巻き込まれる。⚠ 指図の `impl.noRecarve` は「Recarve を呼ぶな」と
書いていたが、**`Create` が Recarve を呼ぶことは書いていなかった**(指図方は API の中身を見ていない)。

⭕ **対処**: 池を「地形を触らずに」置く。

```csharp
var go = new GameObject("P_<池名>");
var wb = go.AddComponent<WaterBody>();
wb.outline = <汀線の世界座標(y=水位)>;
wb.depth = <深さ>; wb.waterY = <指図の水位>;   // ⛔ Create の自動値 median(shore)−0.3 を使わない
WaterBaker.RebuildSurface(wb);                 // ← これは地形に触らない
```

掘削は**自前で庭の矩形の中だけ**に行う(目標の面を絶対値で書けば冪等になる)。

- ⚠ **材質とメッシュは決まったパスを使い回す。**`RebuildSurface` は `mf.sharedMesh == null` のとき
  `GenerateUniqueAssetPath` で作るので、Stage を流し直すたびに `P_… 1.mat` … と孤児が溜まる
  (この日 8 個作った)。先に固定パスの既存アセットを `sharedMesh` へ入れておけば上書き更新になる。
- ⛔ `execute_code` から `AssetDatabase.DeleteAsset` は**安全弁に止められる**。孤児の掃除は
  シェルで `rm`(`.meta` も)してから `AssetDatabase.Refresh()`。

## ⚠ 指図の庭は「位置は間・寸法はメートル」で書かれている ★★

**2026-09-06・土井の奥庭。**汀線 `migiwa.pts` や園路の `pts` は**間**、いっぽう
石の長軸 `lenMin/lenMax`、乱杭の芯々 `pitch`、沢飛石の `pitch`、刈込の控え `off0/off1` は
**メートル**である。混ぜると本数が **1.818 倍**ずれる(護岸石が 29 本しか並ばなかった)。

⭕ **個数は生成器 `niwa_stats` と同じ式で出す** — 弧長を `× ken` で m に直してから割る。
そうすれば図の表と実装が同じ数字になる(実測で 護岸 55+荒磯1 / 乱杭 39 / 沢飛石 5 が一致した)。

⛔ 逆に**株の間隔のような「実装が決める値」は部材の実寸から出す**(刈込は在庫のツゲを
1本置いて幅を測り、その 0.8 倍で詰めた)。決め打ちの 0.42 のような数を残さない。

## ⛔ `Own.Tateishi` の丈は **S / M / L**。樹木の **Big / Mid / Small** と混ざる ★★

**2026-09-06・土井の沓脱石。**指図が `EdoAssets.Own.Tateishi("Big", 1..3)` と書いていたが、
立石に **"Big" は無い**(S 0.60×1.00×0.45 / M 0.70×1.40×0.50 / L 0.80×2.10×0.60)。
"Big"/"Mid"/"Small" は**樹木**の呼び名(`Own.Jouryoku("Big", i)` など)で、
指図方がそちらの語彙を石へ持ち込んでいた。

⚠ `LoadAssetAtPath` は**例外を投げず null を返す**ので、そのままだと**黙って据わらない**。
⭕ 解けない丈は **null を返して「未据え付け」へ積む**(⛔ 近い丈へ寄せない — どれを寝かせて
目標の足形に当てるかは**設計判断**)。⛔ 実装で S/M/L のどれかに勝手に読み替えない。

⭐ あわせて: **「石は立てる」を沓脱石・飛石・沢飛石に当てない。**立石の形を借りるのは
**形状の借用であって姿勢の指定ではない** — 沓脱石は寝かせて天端を水平(`topY`)に据える。

## ⛔ 渡廊下の間数は整数とはかぎらない — `Roka` / `RoofKirizuma` は **float** で受ける ★★

**2026-09-06・土井の `L_ImaDaidokoro`(居間×台所・1.5間)。**`EdoGotenKit.Roka(… int nx …)` と
`EdoAssets.Goten.RoofKirizuma(int)` が **int 引数**だったので、1.5 を丸めて 2間で据えると
**居間棟へ 0.909m 食い込む**(⛔ 廊下は両端を棟の壁面へ突き付ける前提なので、はみ出しは必ず食い込みになる)。

⭕ **対処**: 引数を `float` にして、**端数は最後の一駒を走り方向へ縮めて吸う**
(床板・桁・高欄の X を `rem` 倍する)。屋根は端数の定尺を焼いて引く
(`Goten_Roof_Kirizuma_1.5ken.fbx`)。
⚠ ファイル名の綴りは **InvariantCulture で末尾の 0 を落とす**(1.5 → `1.5ken` / 2 → `2ken`)。
⛔ `ToString("0.#")` はロケールで小数点が変わる。

## ⛔⛔ heightmap の格子より細い水面は、**セルの中心点で掘ると割れる** ★★★

**2026-09-06・土井の奥庭。**heightmap のセル 2.0m に対し池幅 8.7m・水口 2.07m。
汀の内側のセルを**中心点判定**で掘ったところ:

- 汀内 3,031 点のうち **14.4% が水面より上**(最大 +0.648m)
- **水口(2.07m)には中心が入るセルが1つも無く**、陸が残って**池が東西2つに割れた**
- 沢飛石の足元(26.23)が陸

⭕ **手当て(庭方の3条)**:
1. **セルの判定は中心点でなく面の重なり**(coverage > 0)。セルの矩形が汀線ポリゴンと
   少しでも交われば落とす。判定は ①セルの 3×3 標本が池内 ②汀の頂点がセル内
   ③汀の辺がセルの辺と交わる、の論理和(②③が無いと格子より細い水路を取りこぼす)。
2. **落とす値は `min(現況, 設計の池床)`**。⛔ 一律の平床にしない(水が透けて水たまりに見える)。
   ⭕ `waterY − 0.30` は**下限の保証**として別に掛ける(汀ぎわのセルが浅く残らないため)。
3. **据え位置は水面メッシュの縁から。**`WaterBaker.RebuildSurface` は輪郭に
   **Chaikin ×2**(`WaterGeom.SmoothTagged(outline, sharp, 2)`)を掛けるので、
   **見えている水際は `migiwa.pts` の折れ線ではない**。⛔ **地形の水際**
   (外へ進んで最初に地表が waterY を超える点)で据えると最大 2m 引っ込んで石も砂利も浮く。

⚠ **計測と据え付けで基準線を分ける。**据え付けは水面メッシュの縁、
**面積の計測と `clip` は設計の汀**(生成器が刷る表と食い違わせないため)。
⚠ 深さは格子の限界で設計に届かない(土井は設計 1.00m に対し格子上 0.87m)。
⛔ 黙って呑まず、**控えへ積んで指図方へ「格子の限界」の断りを書かせる**。

## ⛔⛔ 「7 庭の植栽」(旧 Stage7)は `Group("Niwa")` を**丸ごと Clear する** — 池も石組も点景もマーカーも消える ★★★

**症状(踏む前に気づいた・2026-09-09 松江松平)。** 「植栽を撒き直す」と言われて
`Edo/<屋敷>/7 庭の植栽` を押すと、**`Niwa` の下が全部消える** — `Niwa/Sensui` `Niwa/Ishigumi`
`Niwa/Tenkei`、そして**非冪等ステージの実行済みマーカー `Niwa/_markers`** まで。
マーカーが消えると 1b(築山)・6a(掘削)・6a'(隆起)・6b(野筋)の**二重実行の歯止めが外れる**ので、
次に誰かがそれを流した瞬間に地形が二度掘られる(Undo の外)。

**原因。** 旧 Stage7 は自前で撒く実装で `var grp = Group("Niwa"); Clear(grp);` から始まる。
新しい `7' 植栽(指図の散布点を据える)`(`Stage7b_NiwaFromScatter`)は
`Group("Niwa/Planting")` だけを Clear する。**名前が似ていて危険度が桁違い。**

**すべきこと。** 散布点の書き出し(`<屋敷>_planting_out.json`)がある邸では
**`7'` だけを使う**。`7` は旧実装なので押さない。⭐ メニューを押す前に、
その Stage が **どの Group を Clear するか**をソースで確かめる(1 行見れば分かる)。
