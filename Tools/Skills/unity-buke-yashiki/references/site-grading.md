## 史実の裏づけ

[菊地2003] 江戸発掘67遺跡の集成:
- **「大名屋敷建設にともない、大規模な切土・盛土を行い敷地を整地する類の開発が、屋敷単位で進行した」**
  (I期=元和・寛永の天下普請期=拝領時)
- **「土地改変は高さ1〜4m程のものが多い」**
- 実測例: 紀伊家紀尾井町=盛土5.0m / 汐留195,000㎡=盛土1.5m / 長府毛利=盛土3.0m+切土10.0m /
  尾張藩上屋敷283,000㎡=盛土2.0m+切土1.8m / 尾張藩麹町邸=盛土0.4m
- II期(明暦大火後)の改築時整地は最大40cm厚 → **拝領時にこそ大規模造成**

[富山市埋文] 本郷台地東縁の富山藩邸: 傾斜地は**「段切り」= 斜面を切って高さの違う複数の平坦面を造成**。

→ **切盛は1〜4mを基本、最大5m(紀尾井町)まで史料の範囲内。**

## 何を作るのか

**目的は「建物が載る平場」を作ること。**

⚠ **細い段(雛壇リボン)を何段も刻んで長屋を並べるのは誤り**
(2026-08-13に渡辺邸で34棟建てて差し戻された)。それは §B-3 の「空地を長屋で埋めて建蔽率を上げる」
そのものになる。

正しい手順:
1. 傾斜地では **数枚の大きな平場(テラス)** を作る
2. その平場の上で SKILL.md §B-2 のレイアウト(連続御殿複合＋外周長屋帯)を組む
3. **平場にできない急斜面が残ったら、そこは庭・法面**。建物で埋める場所ではない

## 平場の作り方

- 平場の高さは**丸い数字**に量子化する(16 / 20 / 24 / 28.4 など)。
- 台地縁の屋敷は **段状テラス**で: T1表(門・表御殿) / T2奥御殿 / T3庭園・蔵。
  テラス間は幅8mの階段回廊(勾配~25%)を擁壁の開口として通す。擁壁高は 6.0(sy1.5) / 8.0(sy2.0) の丸数字。
- パッドは対象建物群の**躯体外形 + 5〜6m** を取り、端3〜4mを smoothstep でフェザー。
- 外周街路のレベルが辺ごとに大きく変わるときは、石垣天端を0.5m刻みの段でステップさせ
  (1 run 内に posY 複数バケット可)、長屋は「内側地盤 ≈ 天端」の区間だけに置き、他は築地塀にする。
- 段間の土手は当面法面(勾配40-60%)。**石垣土留めへの格上げ**は `unity-modular-stonewall` で。
- 近代DEMの掘削穴(ビル基礎跡)は**ラプラシアン緩和**(境界=周辺の正常セル固定、穴セルのみ平均化
  600-1200回)で埋めると自然な鞍部になる。

### 造成パッドのフェザー帯は「平坦」ではない(3つ踏んだ穴)
- パッド端のフェザー(6m帯)に大型建物の尻を掛けると、四隅接地(ground-min基準)で**前面が1m埋まる**。
  大型建物は「前面の主地盤」基準で据え、フェザー側の隅は下の地形を envelope 内で切り下げ/持ち上げる。
- パッドのz端フェザーの先は自然斜面。北帯に置いた台所・長局が**3.9m埋没**した。
  造成延長が正当か(近代改変 envelope の内か)を確認して帯ごと延長するのが正解。
  **envelope はビルダーの造成箱の座標をそのまま使う(推測で広げない)。**
- **ラプラシアン緩和は隣接する既造成の平場も戻してしまう**(尻上げ帯が再隆起して埋没が再発)。
  緩和→対象建物の足元を再カット→再QA、の順で締める。
- パッドが台地の自然縁で止まっていると、そこに載る建物の片側だけが4m埋まる。
  **`cur < 25f continue` のような高さガードを入れたまま拡張すると、低い側が埋め残される**。
  盛土上限(4.5m)でクランプしつつガードを外す。

## ⛔ 造成は「設計面への絶対値」で書く。現況からの差分で書かない

**壊れた地形が自己修復しない造成コードは、必ず「直したはずが直っていない」を生む。**
岡部邸(2026-08-16)で3つ同時に踏んだ。ユーザーの指摘は「地形の変な隆起や窪み」一言だったが、
中身は別物の3つだった。

| 罠 | 症状 | 直し |
|---|---|---|
| `Clamp(target, cur−CUT, cur+FILL)` | 現況基準なので目標面へ一度で届かない。8m の溝は 1パスで 5m しか埋まらない | **クランプを外す**。設計面は絶対値。切盛量は**報告だけ**する |
| `if (Find("GRADED_vNN")) return` の一回きりガード | 版を上げた時しか走らない ＝ 実質一回きり。上と合わさって永久に届かない | **撤廃**。絶対値なら何度走らせても同じ(＝本当の冪等) |
| 設計面が敷地を覆っていない(`best < 0 → continue`) | 段の矩形の外は**一度も触らない**。素地形と過去版の誤造成がそのまま残り、段の縁と生地形が垂直にぶつかる | **法面層**を足して多角形の内側 100% に高さを与える |

**設計面は三層で張る** — ① 段(矩形の中は設計値) ② 外周帯(囲いの芯線から内 9m は run の天端で平ら)
③ **法面**(①にも②にも属さない所は「最寄りの段の高さ」と「最寄りの run の天端」を距離で内挿)。

```
dInner = max(0, max(din, bd) − BAND_FLAT)      // 帯の内縁からの距離
y = Lerp(yTerrace, yRun, dT / (dT + dInner))   // dT = 最寄りの段までの距離(中なら0)
```

### 帯の判定は必ず「線分までの距離」で閉じる

`din`(run の**直線**からの符号付き距離)だけで帯を判定すると、帯は run の走り方向へ
**無限に伸びる**。ボロノイ胞が郭の中央まで届く斜めの run があると、その天端が郭のど真ん中まで
引き込まれる。岡部邸では北辺の run(天端 12.5 / 15.5)が**主郭を斜めに横切る幅24m・深さ8mの溝**
2本を掘っていた。溝の向きはその run の `outw` にちょうど直交していて、そこから逆算できた。
→ `max(din, bd)` で測る。`bd` = 線分までの最短距離。線分から離れた時点で帯を外れる。

### 隣地と地続きの辺は、相手の地面を読む

塀を建てない共有境界では、run ごとの一定天端を使うと継ぎ目に段差が立つ(実測 4.5m)。
**境界の最寄り点から外へ 6m の実地形をサンプルする**。造成の窓は自分の多角形の内側だけなので、
そこは動かない ＝ 冪等は保たれる。

### 検査 `GradeQA()` — 5本目の軸

多角形内の全セルで `|地形 − 設計面|`。許容 **0.30m**。
⚠ **ハイトマップの格子の上で測る**。`SampleHeight` を任意座標で呼ぶと双一次補間が入り、
石垣の線や石段の法面のような急な段では **0.12m のサンプルずれが 2m の差**に化ける
(実際に 228 セルが偽陽性になった)。冪等の確認は「もう一度造成して移動量 0.00m」。

## 敷地外に影響させない

ユーザー指示(2026-08-13): 「段切り造成は敷地外にはできる限り影響しないようにしてください」。

すべての地形改変を **`PIP(POLY)` かつ `DistToPolyEdge >= 0.5m`** でクリップする。
境界には垂直の段が立つが、それは土留めの位置なので正しい。
外周長屋の帯を後から触りたくないなら `DistToPolyEdge >= 10m` でさらに内側に限定する。

## 造成後は必ず全再接地

**パッドを後から広げたら、古い地盤で接地された棟が取り残される**(Yakusho が 4.16m 埋没していた)。
**整地 → 全再接地 → QA を1セットで回す**。囲い・門・建物・庭木すべてが対象(渡辺で199ピース)。

接地は **OBB輪郭9点の地面 min − sink**:
```csharp
// ローカルAABBを取り、その底面9点で地面minを取る
Vector3 mn, mx;  // = InverseTransformPoint した全頂点の min/max
float gmn = float.MaxValue, bot = float.MaxValue;
for (int i=0;i<=2;i++) for (int j=0;j<=2;j++) {
    var wp = tr.TransformPoint(new Vector3(Mathf.Lerp(mn.x,mx.x,i/2f), mn.y, Mathf.Lerp(mn.z,mx.z,j/2f)));
    gmn = Mathf.Min(gmn, Ground(wp.x,wp.z));
    bot = Mathf.Min(bot, wp.y);
}
tr.position += new Vector3(0, (gmn - sink) - bot, 0);
```
**世界AABBで接地すると回転ピースが土手の底に沈む。**

⚠ **一括接地パスは池まわりを壊す** — 護岸石・州浜・橋・水際の飛石は bounds.center が水面上にあり
SampleHeight が池底を返す。接地パスから Gogan/ShoreVeg と池矩形±6m内の Path/Props/Rocks を除外する
(`gardens-ponds.md` 参照)。

## 地形の出自を疑う

SKILL.md §A-6。このプロジェクトの地形は国土地理院5mメッシュ実測DEM由来(`GsiTerrainBuilder.cs`)だが、
**近代改変(学校造成等)を検出した区画だけは、周辺の実測地形を固定点にラプラシアン補間で「復元」**
されている。復元領域は**なめらかに見えるように作られている**ので「なめらか=自然地形」は循環論法。

- **判定は見た目でなく復元処理のコードで行う**。Stage0/造成パッドの bbox・閾値(例 `HtoW(H)<24.5`)を
  再現して現地形と照合すれば、どのセルが動いたか確定できる。バックアップ(`scratchpad/*.bin`、
  着工前のセッションディレクトリ配下にあり他セッションでも生存していることがある)があれば差分は確定的。
- **可視化は3Dレンダより「判定結果を直接ピクセルに焼いたテクスチャ」**が速く正確
  (SampleHeightで1点ずつ判定 → `Texture2D.SetPixel` → `EncodeToPNG`)。カメラ・ライティング・
  ブルームに影響されず境界が一発で出る。3Dマーカー+スクショは遠近・オクルージョンで読み違える。
- **復元領域は屋敷の外(街路・隣接屋敷)にもまたがる**(渡辺の例で復元セルの18%が区画外)。
  隣接区画・街路も含めて判定する。
- 復元自体は否定しない(明治改変地を実測のまま使うのも不正確)。
  **「推定復元である」というラベルを付けて使う**(SKILL.md §A-3 の地形版)。

## 造成の副作用と検査

- **テラス間造成で境界壁の低地側に土手が残る**: 2パッドを別々に造成すると遷移帯(±2セル)が
  壁体2.4mを超えて低地側へはみ出す。壁線から低地側 d∈[1,9]m を `min(現況, 低地パッド)` でカットして仕上げる。
- **地形を後から局所平滑すると、先に置いた建物が一律に沈む**。QAの指紋は「**埋≈|浮| が同値**」
  (例: 埋2.21/浮-2.18)= 地形だけ上がって建物が置き去り。平滑後は影響box内の建物を再接地し、
  塀・門ピースも再接地する(119ピースの実例)。
- **造成の後は必ずバックアップと diff し、変わるはずのない領域の raised/lowered=0 を確認する。**
  これを怠って どんどん堰の水路133セルを+7.9m 埋めた実例がある。
