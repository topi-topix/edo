## 施主と決めた方針

1. **Unity の待ち時間は対象外**(施主指示)。縮めるのは「考えている時間」。
2. 考える時間の大半は**1往復ごとの固定費**(経緯と規則を読み直す → 数字を読んで判断 → 次の一手を決める → 命令を書く。1往復 1〜3分)。
   ⇒ **往復の回数を減らす**のが本命。次が「最初に読む量を減らす」「結果を合否で返して判断を要らなくする」。
3. 「寄せて測るを繰り返す道具」は**プログラム(`EdoBuild` の C# 関数)**であって、役への指示ではない。
   指示を工夫しても、繰り返しの中に役がいる限り時間は縮まない。
4. **関数の中の計算を速くする(二分探索など)は効かない** — 中の繰り返しは元々ミリ秒。縮むのは数秒。
   効く計算の工夫は二つだけ: ①多くは一度測って隙の分だけ動かせば閉じる(繰り返し不要) ②**解く順(門→石段→塀)をプログラムが持つ**と前へ戻る手戻りが無くなる。

| 何を変えるか | 縮む時間 |
|---|---|
| 繰り返しの中から役を外す(プログラム化) | 数十分 |
| 部材を解く順をプログラムに持たせる | 流し直しの分(十数分〜) |
| 関数の中の計算を速くする | 数秒(やる価値は薄い) |

## ⚠ 踏まないこと

- **票1の関数を「事後に寄せる関数」にしない。**`docs/oki-kata.md` §2 の4手目は `CloseKadoSeams` / `AlignGateFace` 型を禁じている(置き方の欠陥が隠れる)。
  新関数は**置く時点の据え付けそのもの**として、固定側 → 可動側の順に「寄せる → 据える」を収まるまで回す物。建て終わった後に呼んで直す物ではない。
- 部材の基準点(ピボット・bounds の中心)で位置も向きも決めない(CLAUDE.md 規則21・oki-kata §3)。
- 収まらなければ**黙って打ち切らず不合格を返す**。0 件は最悪値と一緒に刷る(規則19)。
- 試しを速くするための縮小の試験台を作っても、**最後の確かめは本物の敷地で実メッシュを測る**(規則19「取り合いと境界の正の輪は実装」)。
- 置き方の直しは `EdoBuild` へ入れ、邸ビルダーに書かない(規則21)。票は `close --kata --hirogari` で閉じる(`docs/session-board.md` §1d)。
