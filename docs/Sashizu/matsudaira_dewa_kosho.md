## 表門 — 屋根なし冠木門+両唐破風番所

**明治初期撮影の実写真が現存する**(江戸東京博物館 温古写真集11「旧雲州松江藩松平候上屋敷門」
資料番号 88005761)。大熊喜邦の昭和14年調査で現存していた大名屋敷表門5件の一つ
(書誌確定: [泥絵と大名屋敷] 大熊喜邦・昭和14。現物未見)で、東京大空襲で焼失した。

**位置は [五千分一東京図31](明治16年官製実測図・0.32m/px)で確定** — 北辺の開口はただ1箇所
(北東の折れ点から辺沿い西へ、値は json の gate.s)、両脇に長大建物(表長屋の両翼)、西側は
建物のない垣が続く。門は空襲まで現存したので明治16年の開口位置は基準年次(安政3年)へ強く外挿できる
【位置=A寄りB/長屋の有無・長さの外挿=B】。当初の位置(道の高みからの設計判断【U】)は
この実測と食い違ったため撤回した(2026-08-23)。**確度の順位: 実測A > プロジェクト規則U。**

写真から読めるもの([松江上屋敷門写真] 温古写真集11・2026-08-21 ToMuCo で実見)【確度 A】:

- 門本体は**背の高い角柱二本+冠木**。柱頭に冠(銅板包みか)、柱の内面に長い飾金物。
  **写真の時点で冠木の上に屋根は無い。**
- **左右に向唐破風造の番所が街路側へ張り出す**。出格子が正面と側面に回り、
  切石積みの基壇に載る。屋根は箱棟+鬼飾り、唐破風に彫刻の兎毛通。
- 門扉は縦板に筋金具と乳鋲。**袖塀に潜り戸**。
- **門の両翼は海鼠壁の長屋**で、門寄りは**二階建て**。左手奥に入母屋・白漆喰の大屋根。

**基準年次(安政3年)の正は「屋根なしの冠木門+両唐破風番所」とする(2026-08-23 改説)。** 根拠:

1. 『日本案内記 関東篇』昭和5年([日本案内記 関東篇]・官製・確度A)が現役の当門を
   「**冠木門に属し、両側に唐破風造の番所を附属**」と記述 — 写真Aと独立に屋根なしを裏づける。
2. 前案(切妻小屋根説・2026-08-22)の決め手だった「屋根なし冠木門(最下層の格)と最上格の
   両唐破風番所は両立しない」という論拠は、**当門そのものを写した写真A の前では成り立たない** —
   両立しないはずの姿が現に写っている。⛔ **焼失規定([焼失規定と冠木門] は参考文献の無い
   個人ブログで確度 B/?)を根拠列に入れない。**規定が言えるのは「両立しうる制度的説明が
   一つはある」までで、屋根なしの証明ではない。原典裏取り(『青標紙』・普請奉行の達)は
   未了(`_pending.yakeatoKitei`)だが、⛔ **その成否は結論を動かさない。**
3. [黒門](屋根付き独立門+両唐破風番所)は「焼失していない国主表門」の型であり、
   当門に外挿する理由にならない。

台紙注記「早くから撤去され…」の読みと ToMuCo 原板の高精細確認は**傍証の検証**として残す。

**安政2年の地震で表門は無事**【確度 S】 — 〔別本 藤岡屋日記 上〕(東京都公文書館。東京大学地震研究所
地震史料集テキストDB 記事ID J1400017／『新収日本地震史料』第5巻別巻2-1 p.330)の永田馬場〜山王の
被害列挙に「**松平出羽守 御殿向家中長屋等大破小破、表門無別条、潰家等無之**」。⭕ 当邸は
**安政江戸地震(安政2年10月2日=1855-11-11)で表門を失っていない**。基準年次が翌年の安政3年で
復旧後の姿を描くので、門はこの記録の姿のまま建っている。同じ列挙の土井大隅守「表門倒」が
既知の[安政地震被害書上]と一致するので、割り当ての信頼性は独立に確かめられている。

⚠ **この記録は「屋根なし冠木門」という形式の結論には効かない。** 形式の根拠は明治初期の写真A
そのものであって、焼失規定が説明しているのは**この写真より前のいずれかの時点の焼失**である。
安政2年に門が無事だったことは、焼失がそれ以前だったか以後だったかを絞りこむだけで、
⛔ **「地震で焼けなかったから冠木門への降格は起きない」とは読めない** — 明治の写真に写っている
のは既に屋根の無い冠木門である。焼失規定の原典裏取り(『青標紙』・普請奉行の達)は引き続き未了。

⚠ **同じ列挙の「御殿向家中長屋等大破小破」は採らない。**当家の安政2年の被害の程度は、写本ごとに
**潰(旧説・撤回済)/瓦落/大破小破**の3通りに分かれている。書上の2写本(真田家文書 J1400137・
むし倉後記續篇 J0400633)は括弧が被害の直後に開いて複数名を束ねる書式で「被害が先・名が後」と
読まれ(2026-08-31 岡部セッションの原典実見)、その読みでの当家は「表長屋瓦落」。藤岡屋は1邸ずつ
条を立てる日記の書式で「名が先・被害が後」。⭕ **藤岡屋の書式は記録の内部から確定できる**(『藤岡屋日記』別本 上・記事ID J1400017)【確度 A】 —
同じ列挙に「一 内藤紀伊守中屋敷 **右同断**」「一 本多豊後守中屋敷 **右同断**」の2条があり、
「右同断」は直前の条の被害を承ける語なので、被害→名で読むと被害の語が名の後ろに来て語順が破綻する
(2026-08-31 内藤セッションの指摘)。⚠ **これは藤岡屋についてのみ言えることで**、括弧で複数名を束ねる
書上2写本の読みには何も言わない。⭕ **どちらも復旧後の姿には出ないので実装は変わらない。**
決着は考証方へ(掲示板「安政地震被害書上の読みが逆」)。

⭐ **ただし3通りのうち『潰』は当邸では独立に落ちる。**同じ藤岡屋の条が当邸を
「**潰家等無之**」と結んでいるので、同一記録の内部で『表御長屋潰』とは両立しない。
撤回済みの旧説(=『潰』は土井の被害)を、書上の読み直しとは**別の根拠**で裏づける形になる。
⚠ 残る『瓦落』(書上2写本)と『大破小破』(藤岡屋)の差は、同じ被害を粗く書いたか
細かく書いたかの差とも読めるが、**確かめていない**【確度 U】。⛔ 岡部セッションが
「塀は家ではない・半潰は全潰ではない」で字面の緊張を両立と読んでいるが、これも確度Uなので
当邸の記述はそれに寄りかからない。

両唐破風番所+切石畳出は **10万石以上の帯**の意匠([武家屋敷門の格式階梯]B。同帯の現物が [黒門]A=鳥取池田32.5万石)。当家18.6万石はこの帯に入る。**ただし当門の形式の典拠は帯ではなく写真そのもの**([松江上屋敷門写真]A+[日本案内記 関東篇]A)で、帯は整合の確認にとどまる。
鳥取池田は外様なので、この意匠が親藩専用でないことも同じ実例が示す。

## 取り合い — 面で決める、芯では決めない【作法U 2026-08-29】

囲いの図はこれまで**全体設計**しか持っていなかった — 開口がどこにあり、どの run がどの辺の
どこからどこまでか、まで。そこで止めると、実装は「門は開口の芯に、長屋は run の頭から丸ごとの
モジュールを並べる」としか置けず、**どの面がどの面に接するかが成り行き**になる。
実際にそうなり、同じ門の左右で食い込みと隙間が同時に出た(ユーザーが実測で発見)。

ユーザーの言葉:「オブジェクト同士の位置関係は常に**どの点同士を接するか**を厳密に考えないと
隙間が空く」。これを受けて、開口の両側とすべての隅について**接する面を名指しした取り合い表**を
設計値に持たせた(生成器が図と表にする)。決めごとは三つ:

- **可動側を必ず決める。** 門・番所・隅櫓・区画の頂点は位置そのものが意味を持つので**固定側**。
  動くのは run(長屋・練塀)の側。可動側を決めないと、両方が動くか、両方が動かない。
- **閉じの許容は「隙間 > めり込み」。** 0 を狙い、外すならめり込む側へ外す。
  隙間は郭の内が素通しで見えるので不可。
- **表長屋の鎖は在庫部材の実寸の整数倍でしか置けない。** 継ぎ目は面一(重ねると海鼠紋・瓦・窓が
  二重になる)。だから鎖の長さは棟数で決まり、**run の s の側をそれに合わせる**。
  端数は開口や隅へ押し出さず、**練塀に継ぐ遊び端**で吸う(練塀は駒を伸縮できる)。

表長屋を長さ可変の一体物にした裁定(2026-08-29)で、鎖の端数は消えた — 開口の縁から縁までを
1本で埋めるので、隅や開口へ端数を押し出す必要が無い。

### 隅 — 腕は隅部材が持ち、両隣の run は腕ぶん退がる

隅部材は頂点に据えて動かさない一体の部材で、**両辺へ同じ長さの腕を伸ばす**(留め継ぎは折れ角を
二等分するので左右対称)。留め継ぎ・降り棟の見えは隅部材でしか出ないから、**腕は隅部材が持ち、
両隣の run はその腕ぶん退がる** — 入りの run は腕の端面で止め、出の run は腕の端面から始める。
練塀の側も長屋の側も同じ扱いで、腕と直線材を二重に敷かない。⛔ 以前は練塀の側だけ
「駒が伸縮するから run を頂点まで通してよい」としていたが、これは腕と直線材が二重になる書き方で、
2026-08-30 に撤回した。長屋の妻面は腕の端で郭内へ露出する(表門の番所の背後と同じ姿)。

**部材は折れ角から起こす。⛔ 折れ角を決め打ちしてはならない。** 当邸の「直角に見える」二隅は
実測すると直角ではなく、在庫の正規90°隅では回らない。腕の長さも隅ごとに違う。
**部材の実測(折れ角・腕・丈)は設計値の `kado` 一箇所だけ**に置き、取り合い表は部材名を指すだけで
数値を持たない(絶対規則4)。⚠ 実測値は**素の単位**で、世界座標にするには据えの倍率(江戸暦の ES)を
掛ける — 2026-08-30 に素の腕を世界の腕と取り違えかけた。だから表は**素の値と倍率を併記**する。
部材の丈から出る天端と `const.dobeiH`(呼び値)の差は 1cm 未満で、取り合いに効くのは実部材のほう。

**天端は入りの run の座に合わせる。** 隅で天端が揃うのが正典なので、隅部材は入りの run の端の座に
据える。入りと出で座が違う隅では、段が**腕の端**に落ちる(南東の角・北の隅・土井境の折れの三箇所。
段の位置と量は取り合い表の註記が持つ)。

⚠ **腕は実装が読む形で持つこと。** 2026-08-29 に、腕が取り合い表の中にしか無く、
据える処理が読む欄がどこにも無いまま「隅部材が塞いでいる」ことになっていた。実装では隅がそのまま
口として残り、**外から敷地内へ踏み込める唯一の箇所**になっていた。いまは取り合いに `kado`
(部材・折れ角・座)を持たせ、`EdoMatsudairaDewaBuilder.PlaceKado` がそれを舐めて据える。
`kado` を持たない腕は**閉じに数えない**ので、欄を落とせばその場で鳴る。
検査は三本立て — 図の上の面の当たり(`perimeter_closure_check`)、建てる対象の帳簿
(`perimeter_ledger_check`)、そして腕そのもの(`kado_arm_check` — 部材の実測との一致・
隣の run の端が腕の端面に来ているか・腕が実装へ渡る形か)。いずれも感度試験つき。
西辺(西斜面・北西の登り)は2026-09-06に木柵を全面撤去し、いまは「開放(地物なし)」と設計値に
宣言を置いている——法面と樹林そのものが境と遮蔽を担い、標示の柵も要らないという判断による。
検査がその宣言を読んで除外する形にした(宣言を消せば鳴る)。

- **門扉は「出どころ」まで書く。** 開口が閉じている事実(`leaf`)と、扉を**門の躯体が持つのか
  別部材を据えるのか**(`leaf.by`)は別のこと。**三門とも躯体が自前の扉を持つ**ので、
  ⛔ 別部材を重ねてはならない(重ねると門の顔が覆われる)。通用門二つは表長屋の躯体が門口を彫って
  扉まで作り付け、表門は新造の冠木門が門柱・冠木・扉を一体で焼いている。
  ⭐ **2026-09-10(第33次)に表門の欄を実装へ合わせて直した** — 第32次までは『別部材の扉を据える』
  『丈は在庫の扉の実寸から』と書いていたが、**新造の門がそれより高い両開きの板戸を持っており**、
  普請奉行の裁定で躯体の板戸を採って別部材は据えていない。⛔ **指図が実装と食い違ったまま
  『扉がある』と言い続けない**(閉じ検査は `leaf` の有無しか見ないので食い違いを捕まえられない)。
  実装は門の名前で決め打ちせず、据えた門の実メッシュを見て判断する【U 2026-08-29】。

## 石垣基壇 — 駒は伸縮させない【ユーザー裁定U 2026-08-29】

囲いの足元が地面から浮くところは石垣基壇が受ける。その据え方の原則は三つで、
**設計値の `ishigaki` に一箇所だけ**置く(数値はこの文章にも図にも写さない — 絶対規則4)。

1. **1つの石垣オブジェクトの XYZ 方向の長さは変えない。** 駒は在庫の実寸のまま、
   `scale` は全周で固定する。
2. **run の長さは駒の重なりで調整する。** 端数は駒を伸ばして吸うのではなく、
   継ぎ目を詰めて吸う。
3. **石垣の高さは地面への埋まり具合で調整する。** 駒の天端を run の座に合わせて下ろし、
   地面より下は地中に埋める。露出の高低は**埋まり方の差**であって、石の大きさの差ではない。

`runs[].base:"Ishigaki"` は「この run に基壇が付く」という**宣言だけ**で、駒の規模を持たない。
横の割り付けは s0〜s1 を最小枚数で覆う形に決まり、ピッチが上限を超えないので
**重なりは必ず下限以上・隙間は出ない**。run が二枚ぶんの丈より短いときは駒がはみ出して
隣と重なるが、それでよい — **隙間は郭の内が素通しで見えるので不可、めり込みは可**
(囲いの閉じの許容と同じ向き)。

- **なぜ駒を伸縮させないか。** 伸縮させると隣り合う run で石の大きさが変わり、
  **ずれ量が石の大きさに比例する**ので、同じ辺の中で隙間と食い込みが同時に出る。
  外周のブックマーク15枚でユーザーが指摘した不具合の主因がこれだった。
  石の大きさが揃っていれば、継ぎ目の始末は重なり量ひとつで決まる。
- **run を割る根拠は露出**(駒の丈ではなく見えの高さ)。露出が設計値の上限を超える手前で
  run を割る — 岡部邸の外周と同じ作法。**露出が 0 以下になる区間は完全に地中で、それでよい**。
- **`ishi`(根石)は基壇を持たない run だけの欄。** `base:"Ishigaki"` を持つ run に書くと
  駒の規模の書き戻しになるので、生成器の `ishigaki_layout_check` が鳴る。
- 検算は同じ検査が三本立てで持つ — **覆い**(全長を刻んで走査し、どの点も駒の箱に入るか)・
  **継ぎ目**(重なりの上下限と枚数の最小性)・**露出**(0〜駒の丈)。
  ⚠ 割り付けの式を式で検算すると恒真になるので、覆いだけは**据えた駒の箱を並べて別口で**測る。
  感度試験(わざと壊すと鳴るか)を7通り常時走らせ、件数を無条件に標準出力へ出す。

## 屋根の取り合い — 谷樋で納める【ユーザー裁定U 2026-08-27】

棟は**入側の外縁で接している**(壁は共有しない — 身舎の壁どうしは入側二列ぶん 2間 離れている)。
接合部では**両棟の屋根面が向かい合って谷になる**。
⭐ **2026-09-08(第28次)に大棟の向きを列ごとに変えた**(表向の列と奥向の列で直交)ので、
表向の列の谷は**妻ではなく流れ(軒側)の屋根面**が向かい合う形になった(=流れ谷)。
規則は指図の `_roofRule`、谷の別は `valleys[].kind`。

**谷の辺には軒を出さない。** 両棟とも外形の縁で屋根を切ると、屋根面は軒先の高さのまま突き合い、
そこに谷樋が走る。水は縦樋を立てず、谷樋の両端の軒先から落とす【確度B=一般類型】。
**棟の間数は一つも動かない** — 室割り・玄関の軸・建蔽率のいずれにも影響しない。

⚠ **ただしこれが成り立つのは両側の屋根の形が決まっている辺だけ**【2026-09-10・第33次】。
相手の棟が帯割り(`munes[].roof`)を持たないまま軒を落とすと、屋根が無いので谷も葺き面も作れず
**壁の上が素通しになる**(部材方の報告)。⇒ 軒を落とすかは**従属値**とし、検査
`valley_eave_check` が辺ごとに出す。⛔ **『軒を出さない』を宣言しただけでは実装できない。**
いま落とせない辺が一本ある(長屋型の棟に帯割りの屋根部材が在庫に無い — `_pending.gotenRoofNagayaGata`)。
裁定は「その棟に屋根を与える」か「その辺は軒を残す(=谷にしない)」の二つだけで、
⛔ **指図方は帯割りを発明しない**(帯の割りは `_roofRule` の従属だけでは決まらず、入側と部材の有無が先)。

**渡廊下は離れた棟をつなぐ部材**であって、連なる棟の継ぎ目に使うものではない。当図で渡廊下が
架かるのは、行と行の間(表向↔中奥、長局の北列↔南列)の **2間以上** 空いた所だけ。

**谷は三種ある**(本数は指図の `valleys` が正典。⛔ 本文に写さない)。

- **妻谷** — 大棟が谷へ向く所で、妻側の屋根面が向かい合う。軒を出さずに突き合わせる。
- **流れ谷** — 大棟が谷と平行な所で、流れ(軒側)の屋根面が向かい合う。同じく軒を出さない。
- **軒谷** — **中奥と奥向が結界の帯(1間)を挟んで**、平行な長辺の軒で向かい合う所。
  軒の出 0.90×2 が帯(1.818m)をほぼ埋めるので**両者は 18mm で出会う**。ここは軒をそのままにして、
  合わせ目の下へ樋を寄せて吊る(寄せ樋)。帯の下を通るのは**御錠口と御膳所口だけ**で、渡廊下は架けない
  (結界は「面として閉じていないと意味がない」— 帯を廊下で通すと口が三つになる)。

**実装への影響** — 屋根部材は**辺ごとに軒の出を落とせる版**が要る
(現行の `build_goten_roof.py` は W'=W+2E の対称生成)。
谷の位置・種別・長さと両側の大棟の高さは json の `valleys` と `munes[].roof` を正とする
(⛔ 本数も長さも本文に写さない — 生成器が数える)。

**格は軒高で読む(厩<長屋類<御殿)**【普請奉行の裁定U・第23次 2026-09-07】。⛔ **棟高では格を
読まない** — 棟高は梁間の従属値なので、梁間の広い棟のほうが格に関わらず高く出る。数値は
`const.gotenEave` / `const.nagayaGataEave` / `const.umayaEave`(json正典)。

### 西斜面の林 — 溜池の崖は**二層**(上=樹林 / 下=草地)。域Wは3帯

⭐ **『江戸名所図会』溜池の崖を NDL 原寸で実見した結果**(掲示板 EDO-0115・確度**S**)、
崖面は **上=樹林 / 下=草地** の**二層**に読める。ハッチングは**草地の表現**であって裸地ではない。
この二層の定性は不変(2026-09-06 の帯の切り直しでも動いていない)。

**域W(西の崖)** は落差の割合 t で**3帯**に切る(2026-09-06・庭方裁定。旧4帯から改めた —
ユーザー指摘「崖の斜め部分に中途半端にパラパラと木があるのが不自然」・参考イメージ
[皇居濠の土手]【確度U・異時代/異地の参考であって江戸期の密度の典拠にはしない】)。

- **帯W1 法肩の縁** — 稜の松の列のみ。
- **帯W2 樹林** — **閉じた連続した林冠**(旧・帯W2 上部の樹林 + 旧・帯W3 林縁 を
  統合し、旧『林縁に疎らな点在』の意匠は廃止)。松:常緑広葉 ≒ 4:6。
  林縁側は低木を厚くして裾を締める。⚠ 北西の登り(辺11・落差が浅い)は
  同じ t 範囲だが密度だけを落とした「帯W2-北」を持つ(`slopeArea.shallowSpans`)。

  (空きの脇に中木と林床があり裸地は無い・庭方【B】・`slopeArea.checks.maxGapAccept`)。
  ⭐ **2026-09-10 に『林冠を抜ける突出木』を入れた**(庭方 裁定A-3)— 帯の松の一部を
  大きい個体へ振り替え、**法肩に沿って一定の距離ごとに 1 本以上が林冠から突き出る**ことを
  保証する(`slopePlanting[].emergent` / 検査 `slope_emergent_check`)。
  1 本ごとに**帯W2 の上縁から法下への離れ**も振り、梢が稜を越える深さまでに留める
  (`emergent.offsets`・上限は断面の検査で確かめる【P】)。
  ⛔ **樹種の単調も設計の欠陥**である(松が広葉と同じ高さに収まると層が読めない)。
- **帯W3 法尻の草地** — ⭐ **2026-09-10 に『草地のみ』から改めた**(庭方 裁定A-3。
  前巡の『撮り方の問題』は庭方自身が撤回した)。皇居の濠の実例が示すのは
  **『木で覆うか土留めか』**であって、草だけの帯はそのどちらも満たしていない。⇒ 三つを足した:
  ①帯を上から縮める ②**低木の地被**を置いて裸地を無くす ③**局所勾配が一定以上の断面にだけ**
  在庫の**野面石 1 段の土留め**を置く(`slopeDoryu`)。⛔ 帯の全長には置かない。
  **各断面で幅(法尻までの距離)が絶対最小幅を下回らないことを保証**する(`grass_layer_check`)—
  法肩が折れ線のため、絶対最小幅を先に決め打ちすると法尻側で薄くなる列が出るので、
  局所の落差が小さい列だけ境を押し上げて幅を確保する。⚠ 域の最北端(u−91 付近)は域そのものが
  数m²しかなく物理的に満たせない — 検査は隠さず列挙する。
- **帯の境は直線に切らない。** 境の位置に低周波のゆらぎ(相関距離つき)を与える

  ⚠ **ゆらぎを当てるのは庭方が名指しした境だけ**(落差の浅い列では絶対最小幅が帯W1 と帯W3 の

  法尻の草地は堀端通りの路肩なので、落差の割合ではなく鉛直の高さで決まる。t の境は、落差が
  極端に大きい列で草地が上へ伸びすぎないための上限で、隣邸と揃える値でもある。
  ⇒ 検査 `band_governor_check` が、宣言した支配(`borderBy`)と実測が合っているかを毎巡出す
  (縮め方の経緯は `_pending.obiW3Shukusyou`)。⛔ **『境 t を動かしたから縮んだ』と思い込まない。**

**域S(南西の谷)** は名所図会の射程の外(描かれているのは溜池に面した崖で、
岡部境は**湿った谷**)なので、⛔ 二層に従わせない。境は **t ではなく標高**で切り、
**沢の頭**(滝の三の段の天端の直上)より上が樹林(帯S-上)、下が谷底の沢(帯S-下・ヤナギと灌木)。

⛔ **竹叢を置かない**(江戸の水辺79事例中1例)。⛔ ポプラは明治の渡来木で使えない。⛔ 桜も不可。

**法肩の樹列は水から見た輪郭を作り、法肩を根で留める。**`perimeterClosure` は西辺6辺を

### 掘削の作法 — ここを外すと図が消える

⛔ 芯々2.1m で径5m を三重に重ねるのは林ではなく**藪**。
⛔ 芯々を詰めて本数を守らない — V7 の景は「**梅の隙間から鳥居が見える**」で成立する。

### 奥庭は平庭(ひらにわ)

⭐ **奥御殿の座敷から見る庭は[築山庭造伝]の平庭**(石・刈込・苔・下草で構成し高木を用いない)
とした【2026-09-01 庭方】。⭕ **幾何でも同じ結論になる** — 実形の奥行は4間しかなく、
高木の退避(棟+層の `clr`)と生垣側の退避を引くと**置ける帯が空集合**になる。
主木(クロマツ)は**3本 → 0本**、中木(落葉)は**3本 → 1本**(V2 の左手・一本ずつ位置が決まる)。
⛔ これは「入らなかったから削った」のではなく、**庭の形式を改めた**結果である。

### 白壁を消す — 棟の妻の前に塊を置く

⛔ 旧版の庭は**棟の妻(白壁)に向いていた**。表役所の西妻・奥御殿の西妻の前に中木の塊を置き、
足元を刈込で締める。⚠ そのため**刈込と下草だけは棟からの退避を軒の出まで詰める**
(`plantRule.keepoutByRole`)— 高木と同じ退避のままだと壁から 3.3m 離れてしまい、
「足元を隠す」が成り立たない。
⭐ 同じ理屈で、**樹冠が掛かってよい物(灯籠・飛石・園路・垣・板塀)には層の `clr` を足さない**
(`plantRule.clrExempt`)。枝が灯籠や飛石の上へ張り出すのは**庭の正しい姿**で、避ける物ではない。
⛔ 軒のある物(棟・渡廊下・附属屋・外周)と、道具として使う物(井戸・石段)には足す。

### 中木の退避は「樹冠の外周」から取る【2026-09-01 庭方】

⛔ **幹の芯で測ると樹冠が棟・塀・州へ食い込む**(CLAUDE.md 規則5「実メッシュで測る」に反する)。
新造したモミジは**幅が高さを上回る**株立ちなので、中木の一般の退避より樹冠のほうが大きい。
⭕ そこで**中木だけ**、退避を樹冠の外周から取るようにした。
⛔ **落葉の中木は枝を水面にかけない** — ⚠ **B案で理由が強まった**。枯池のときは「州は水の見立てで、
葉が落ちると濁る」という見立てだったが、水が入ると**落葉が実際に池に溜まる**。
⭕ 例外は★傾ける松の一本だけで、常緑なので水を汚さない。
⭐ **2026-09-01【庭方 回答12】に高木も入れた。**`JG.Pine("Big",2)`×1.65 の樹冠半径は
**3.47間 > `clr` 2.50間**(1.76m はみ出す)。主庭は回答11 の直しで `scale` 1.20 に落ちるので
樹冠半径 **2.14間 < `clr` 2.50間** となり、主庭では効かない。
⚠ **庭方は「実害はほぼ皆無」としたが、生成器の実測では西庭の主木『築山の北東裾』が
5本 → 最大4本 になる**(高木を外すと消える)。⛔ 指図方は box を動かさない = `_pending.groupArea`。
⭐ **足し方は `max`(庭方 回答1 で確定)。**`clr` はもともと樹冠半径の名目値なので、
**足すのは二重計上**。実測が名目を上回ったときだけ差し替える。

⭕ **樹冠の実寸は目録(`asset-index.tsv`)の一本が正典【P】。**新造の木も目録へ入ったので、
繋ぎの仮値(`plantRule.crownFallback`)は**廃した** — 樹冠径・樹高はすべて目録から引く。
検査 `crown_fallback_check` が、欄の再発(仮値の復活)をその場で鳴らす。
⭐ 奥庭の**生垣(h1.9m)**は中仕切塀(h2.4m)を消すための唯一の手なので、
その内側へ植える中木だけは**生垣の退避を外す**(外さないと押し出されて意図が消える)。

### 刈込は「形を揃えて刈る」が「径のばらつきは揃えない」【2026-09-10・第33次・庭方 裁定A-2】

⛔ **築山の頂(V6)から見下ろした刈込が不合格になった主因は、配置ではなく『大きさが一定』だった。**
配置(二列千鳥・単列・三日月)は一つも動かしていない。原因は二つ:

1. **二種の低木がどちらも倍率固定**で据えられていた ⇒ **部材ごとに連続の乱数の帯**を与えた
   (`planting[].parts[].scaleJitter`。⛔ 層や `plantRule` の一律の揺らぎでは二種の差が出ない)。
   帯は部材の実寸に掛かって**仕上がり高の帯**に収まる(数値は `parts` と `plantRule.roleHeight` が正典)。
2. **群ごとに種を分けて配材**されていた ⇒ **各群に二種を混ぜる**(`groups[].mix`)。
   ⛔ 種で群を分けない。⚠ 群が許された少ない株数で打ち切られても二種が残るよう、
   配材の順は**種を交互に回す**(固めて並べて乱に任せると、先頭に寄った一種だけになる)。

⭐ 理由(庭方):**刈込は形は揃えて刈るが、齢の差による径のばらつきは揃えない。**
⇒ 検査 `group_mix_check`(塊ごとの種の内訳)と `plant_height_check`(役の丈の上限)。
⚠ **丈の検査は『最も大きく育つ個体』で測る**ように改めた【第33次】— 従前は倍率だけを見ており、
**揺らぎで伸びる株を一度も見ていなかった**。⭐ 西庭の刈込も主庭と同じ大きさの幅を持つ —
同じ部材を同じ役で使う以上、庭で幅を分けない(`_pending.karikomiNishiNiwaTakasa`)。

### 型は「書いただけ」では出ない — 塊の並べ方【2026-09-09・第31次】

⭐ **庭の塊には型がある。**道の左右へ交互に振る**二列千鳥**、岸に沿って一列に流す**単列**、
木の足元を陸側からだけ抱く**三日月** — どれも「何本置くか」ではなく「**どう並ぶか**」の指定で、
庭が庭に見えるかはここで決まる。⛔ 均一に撒けば、本数を減らしても林のままである。

⛔ **ところがこの屋敷では、型の指定が長く『読まれていなかった』。**指図には型も、沿わせる線も、
芯々の帯も書いてあったのに、生成器の側は塊の成員を**箱の中の一様散布**か**芯まわりの環**でしか
置けなかった。図の注記と実際に撒かれた点が別のことを言っている状態が続き、庭方が書き出しの点を
手で測ってようやく露見した。⭕ **第31次で、型ごとに陣を組む形へ直した** — 線の弧長を芯々の帯で歩き、
千鳥は左右へ、単列は片側へ振る。三日月は木から見た角度の窓を通してから据える。

⭐ **教訓は「指定した型が実出力に出ていることを検める輪を、同じ巡で付ける」。**
値を書くこと自体は設計ではない。⛔ 誰も突き合わせない指定は、書いた時点から静かに死んでいる。

## 建蔽率と収容力

分母は敷地全体。数字は生成器が json から算出する(この文書に写さない)。
⭐ **建坪は躯体(壁)の平面で数え、軒の出は算入しない**【2026-09-08・第28次・普請奉行裁定】。
⛔ 屋根を含む外接箱の底面で測らない — 軒の出は全棟に一様に付くので、棟の数だけ差が積み上がる。
規則の正典は指図の `_kenpei`、実装側の測り方の申し送りは `_pending.kenpeiJissokuKijun`。

⭐ **2026-09-10(第33次)に表長屋の奥行を据わっている部材の実測へ直した**(普請奉行の裁定)。
⛔ **部材は作り直せない**(手組み/焼き済み)ので、**指図の側を実寸に合わせる**。
これで建坪の分子が下がるので、⛔ **前の版の建蔽率と直に比べない。**
⚠ 普請検査が実装から測った値は、**躯体ではなく内側の軒まで**含んだ奥行に対応していた —
『差は長屋の奥行で全量説明できる』という読みは半分だけ正しく、実際は
**指図が過大・実装がまだ軒込み**という二重の食い違いだった(`_pending.kenpeiJissokuKijun`)。
⭐ 部材側の注記は『躯体』と『内側の軒を含む外接』を書き分けてある(`_pending.nagayaKutaiHyouki`)。

- **大名上屋敷の建蔽率の史料値は [福井図] の5〜6割の一点しかない。** 当図はそれより大きく低い
  (広い拝領地・表門前の白洲・西庭(露地と芝野)・奥庭・明地・造成しない斜面の帰結)。数字を上げるために空地へ棟を足さない。

  (加賀本郷15%・小浜28.6%・尾張市谷47.7%)の帯の中位に収まる — 原典に忠実な比較指標はこちら。
  3例は必ず揃えて引く(下端を落とすと帯が狭く見える)。国主・広大地の類例としては加賀本郷が最も近い。
