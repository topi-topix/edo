其一　継ぎ目の詳細平面

距離程 444.8–499.5 ── 縦断にも横断にも現れない区間

⚠ この 54.7 m は縦断の基準線が途切れる区間で、横断の最寄りは ニ(560m)で 60m 下流にある。ところが図の最大の争点はここに集まる ── U7 の折れ(この指図で唯一の確度A の史料主張)、SW3a の 23 駒、隅駒 CWC3_v2 / CWC3_v6、そして継ぎ目の残置。そこで平面で1面を割いた。⛔ ここに横断は切れない ── 距離程は郭外の汀線に沿う直線区間をつないで採るので、この区間には基準線そのものが無い(reach.gaps)。
⭐ この図は規則②の「躯体」の定義が 2026-09-01 の裁定A(裁定1)でどう変わったかを重ねて見せる。桃 = 旧(汀線から 4.80 m の帯)／ 砂 = 新(据えた駒の矩形の和)／ 網 = 実駒(見え面 → ピボット線)。旧の帯は汀線からの距離で作るので出隅で半径 4.80 m の扇形になり、石は直線の駒なのでそれを埋めなかった ── その埋め残しは種地(堀底)のまま残り、地形の三角形分割で細長い楔として切られていた(現地で見えていた砂色の三角形の正体)。⭐ 砂に覆われずに残る桃が、裁定で消えたものである。⭕ 逆に砂が桃からはみ出す所は、駒がピボットから 2.60 m 手前へ張り出す分で、旧の帯はそこを取りこぼしていた(ishigaki.pieceLenNote)。⭕ いまや砂と網は、その 2.60 m の伸びを除いて一致する ── 躯体は据えた駒が実際に占める矩形の和だからで、出隅も入隅も同じ式で解ける(works.bodyBand)。⛔ 隅の駒は躯体に入れない(点でしか描いていない)── 向きが未実測で躯体がどちらへ張り出すか決まらないためで、隅は岸として扱う(works.bodyBand.cornersExcluded / ishigaki.cornersNote)。⛔ 石垣は1駒も動かしていない(CLAUDE.md 絶対規則1)── 動いたのは地形の側だけ。

其二　施工の記録

2026-08-31 実施 ── 施工後の実測・事故・残る未是正

⭐ 2026-08-31 に実施した。00002/00003 の掘り直しを Unity へ実装した結果。裁定A(EDO-0064)の設計面を build_sotobori_dem.py と同一ロジックで再計算し、2m ハイトマップへ双一次で書き込んだ。 設計どおり動いたセル 11,665(46,660 m²)／工区 46,800 m²、設計面との最大誤差 0.598 m(設計面との最大誤差は、堀底 0.30 と岸 6.40 が1セルで切り替わる境界だけに出る)。⛔ 比べた相手は施工直前の退避 TerrainBackups/sotobori_00002_00003_20260831_grade_pre/heightmap_before.bin。⚠ sotobori_dem.json の cur(2026-08-26 固定)ではない。

⛔ 施工中に踏んだ事故(復旧済)
⛔ 工区の外 31,760 m² を最大 7.94m、2026-08-26 の状態へ巻き戻していた。
原因 ── 工区の外接矩形を丸ごと設計面で上書きした。工区の外では『設計面 = cur』なので無害のはずだったが、cur は 08-26 の地形であっていまの地形ではない — 08-26 の溜池の掘り直しと 08-29 の 00001 のフィット(盛土 4,981 m³)を巻き戻した。
なぜ検算が見逃したか ── 前後の検算がどちらも |des − cur| ≤ 0.01 を除外して始まっており、『動かす予定のセル』しか見ていなかった。
復旧 ── 施工前の退避から、設計が動かす予定でないセルを戻した。⛔ 『意図せず動いたセル 0』は偽の合格だった — 2026-09-01 の検図で、凍結域 K1 の中に未是正のセルが 1 つ残っているのが見つかった(→ residual / U14)。⚠ この再測定がなぜ 0 を出したのかは未照合。
→ 指図の works.writeBack。横断の教訓は EDO-0078 と qa-and-pitfalls.md。
