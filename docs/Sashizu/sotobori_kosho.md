### 呼び名の定め — 裸の「土橋」は使わない

⛔ **「土橋」の一語は二つの別の橋を指してしまう。** 当指図では次の二語に分け、**裸の「土橋」を使わない。**

- **虎ノ門の橋** ── `Sotobori_00001` と `00002` の境、虎御門の枡形に取り付く渡り。
  **形式は史料で決まっていない【U】**(下記「段差の機構」)。実装は堰堤としての土橋だが、
  それは**実装上の選択**であって形式の断定ではない。
- **汐留の土橋** ── 幸橋御門の**東(下流)**、外堀が汐留川へ接続する地点の橋
  (現・新橋駅北の土橋交差点付近)。潮止めの堰の位置とされる場所で、**当区間より遥か下流**にある。

⭕ **工区の定義は「虎ノ門の橋の東面から東」と書く。**
⛔ **「土橋の東」と書かない** ── `00002`/`00003` は**汐留の土橋の西(上流)**にあたるので、
そのままでは事実と逆に読める。
⚠ **[外堀保存管理計画書] の引用に出る「土橋」は、文脈で二義ある。**
- **形式の類型語** ── 段差の機構の条「各見附の**橋台石垣もしくは土橋**には…」(台地部の門に見られる形式)
- **地名 = 汐留の土橋** ── 寛永13年の条「**雉子橋から土橋まで**の外堀を総石垣化」
⛔ **一括で「類型語」と断じない** ── そう読むと本文(下記「史実」1.)が誤りになる。
**引用は原文のまま残し、引用ごとにどちらかを註記する。**⚠ どちらも「虎ノ門の橋」ではない。

### 対象の範囲

**溜池の堰(どんどん)から下流の外堀ひと続き**を対象とする。上流の溜池そのものは 2026-08-26 に
掘り直し済(`EDO-0039`)で、ここには含めない。下流端は `Sotobori_00003` の東端で、
その先は東へ **幸橋御門 →(一区間)→ 汐留の土橋 → 汐留川** の順に続く(いずれも未再現)。

⚠ **三つの水面で扱いが違う。** 08-22 のリセットが「水色の囲い」の内か外かで生死が分かれた。

- **`Sotobori_00001`(堰〜虎ノ門)= 調査のみ。** 虎ノ門枡形とともに囲いの中に入っていたため
  無傷で、現況は 08-22 リセット直前と完全に一致する。水面より上に出ている所の主なものは
  堰の頭と虎ノ門の橋で、どちらも構造物であって掘り残しではない。
  ⛔ **「汀線から4m以内の縁」という言い方は使わない** — 距離だけを見て高さを見ない物差しで、
  下記「5.」で撤回した(其二の生成側は「水面より何m高いか」と「汀線から何m内側か」の両方を出す)。
  量は其二の表が正典で、**この文に数値を写さない**。
  **掘る所は無い。1セルも触らない。**
- **`Sotobori_00002` / `Sotobori_00003`(虎ノ門の橋の東面から東)= 全面 掘り直し。** 囲いの外。

⛔ **したがって工区は虎ノ門の橋の東面から東で始まる。** 00001 とその岸・堰の頭・枡形の足元は
工区の外に置く。⚠ 実装が虎ノ門の橋を土橋(堰堤)としているのは**実装上の選択【U】**であって、
形式が決まっているという意味ではない(下記「段差の機構」)。

### この普請の性格

**新設ではなく復旧である。** 虎ノ門の橋の東面から幸橋方向へ下る外堀(`Sotobori_00002` /
`Sotobori_00003`)は 2026-08-10 に一度掘られ、両岸に総石垣が据わり、新シ橋が架かっている。
2026-08-22 のジオリファレンス補正で**「水色の囲い」の外の造成を自然地形へ戻した**とき、
囲いに入っていたのは虎ノ門枡形とその足元だけで、**虎ノ門の橋の東は堀の掘削もろとも現代の地面へ復した**。

水面のメッシュは張られたままだったので、**乾いた地面の中に水の板が沈み**、両岸の石垣も
土に埋まっていた。溜池で同じ取りこぼしを直したのが `EDO-0039` で、
その報告が「同じことが外堀に残っている」と名指ししたのがこの件である。

⭐ **2026-08-31 に掘り直しを実施し、施工後の7検査を通した。**
⚠ **うち `keepout` と `toranomon` は 2026-09-01 の検図で △ に落ちた** — 凍結域 K1 の中に
未是正のセルが1つ残っており、施工記録の「意図せず動いたセル 0」は偽の合格だった(→ U14)。
施工の記録・実測・施工中に踏んだ事故は `sotobori_sashizu.json` の `stages` と `works.writeBack`、
`sotobori_terrain.json` の `postWork2026_0831` が正典。

⚠ **したがって考証の主題は「どう掘るか」ではなく「何を根拠に元へ戻すか」**である。
堀の形・石垣・橋は既存実装をそのまま採り、この指図は動かさない。
⛔ **ただし「すでに考証を通っている」とは言えない** — とくに**水位の値は史料に無い設計判断【U】**である
(下記)。段差が**在ること**は史料に依るが、**値**は当プロジェクトが決めたものにすぎない。

#### 段差の機構

- 「各見附の**橋台石垣もしくは土橋**には、各堀の水位調整のための**堰**や排水暗渠が設置されていた」/
  「弁慶濠から溜池以南の堀もやはり城門に築いた堰などを利用して**順次低くなる構造**」【確度 A】
- ⛔ **標高の値は一切書かれていない**(図10-1-2 の縦断面模式図は喰違〜牛込の区間のみ)。
  したがって **6.60 / 6.40 / 3.50 / 3.30 / 1.80、深さ 1.50、落差の値はすべて設計判断【U】**である。
  ⚠ 初版は「堀の形・水位・石垣・橋はすでに考証を通って実装されており」と書いていたが、
  **水位について「考証を通った」と言える根拠は無い**。段差の**存在**が A、**値**が U。
- ⚠ **虎ノ門の橋を土橋とするのは実装上の選択【U】で、同じ本の中に反証が3件ある。**
  1. **類型** ── 「**低地に位置する牛込門・市谷門では橋台石垣**が、台地部の四谷門・喰違・赤坂門には
     土橋が存在した」で、虎ノ門は低地側。⚠ ただし**他門からの外挿**である。
  2. **明暦3年「虎ノ門橋の普請(内藤政親)」** ── 年表が橋を架ける表現を採る。
  3. **天明6「虎ノ門外石橋下玉川上水渡樋修復」** ── **記事が構造を「石橋」と名指す**ことが
     土橋説への反証であり、**類型からの外挿ではなく当該門を名指しした記事**であるぶん 1. より重い。
     ⚠ **ただし「下を水が抜ける」こと自体は反証にならない** ── 同書は**土橋にも排水暗渠**が
     あったと書く(上の「段差の機構」の引用)ので、渡樋の存在は土橋説と両立する。
     ⚠ **「虎ノ門外石橋」が虎ノ門の渡りそのものを指すのか、郭外の別の石橋を指すのかは
     原文では決まらない【?】。**

  ⛔ **それでも実装(堰堤)は変えない。** 段差が**在ること**は A のままで、排水暗渠は橋台石垣+橋でも
  成り立つ。変わったのは**【U】の重み**(反証が1件から3件になったこと)だけである。
  ⛔ 前版は「内藤政親**丹波守**」と書いていたが、**原文照合の記録(表10-1-1)に受領名は無い** ──
  典拠に無い官名を静かに足さない(2026-08-31 削除)。

#### 一水位という置き方が成り立つ理由

「汐留」は**潮止め**に由来する【確度 B — [汐留の由来]。Wikipedia に脚注が無い】。
⚠ **その堰の位置を「汐留の土橋」とするのは【? — 未裏取り】** ── 引用元の本文は「海と堀とを仕切る堰が
あった」までで、**位置を土橋と特定していない**。一次の裏取りは『東京市史稿』港湾篇・港区史。
⭕ **それでも結論は動かない** ── 堰が汐留の土橋であっても幸橋御門であっても、**いずれも
`Sotobori_00003` の東端より下流**なので、**当区間が非感潮**であることは変わらない。
⛔ **汐留の土橋は幸橋御門ではない。** 幸橋門の**東(下流)**、汐留川との接続点(現・新橋駅北の土橋交差点付近)である。
前版は「土橋(幸橋門)」と書いて両者を同一視していたが、報告書の原文は
「雉子橋から**土橋**までの外堀を総石垣化」で**「幸橋門」の語は無い** ── 当方の誤同定だった(2026-08-31 訂正)。
**堰が潮を止める以上、その上流にあたる当区間は非感潮**なので、水面は堰の天端が決める一定値になる。
東京湾の朔望平均満潮位はおよそ T.P.+1.0m で、1.80 はその上 — 内部矛盾は無い
【B — 現代の潮位表からの外挿で、19世紀の値ではない。明治以降の地盤沈下と海面変動を跨ぐ】。
値そのものは【U】。
⛔ **汐留の土橋より下流の汐留川は感潮**なので、1.80 を延長してはならない。
⚠ 幸橋門〜汐留の土橋の一区間の扱いは、幸橋御門を建てるときに決める(U3)。

⚠ 併せて、当プロジェクトが虎ノ門の枡形に当てている定型値(内法20間2尺3寸・門内法2間4尺・橋幅3間渡9間)は

⚠ **原文が「冠木門」と書くのもこの定型の中**であって、**虎ノ門の門を冠木門と述べた記事ではない**。
⛔ **直前の明治33年「虎ノ門は高麗門を残し」と並べて読み違えないこと** ── 後者は**虎ノ門そのもの**を

### 設計の決めごと

#### 1. 壁は垂直のまま残す

⛔ **溜池の掘り直しの手つきをそのまま持ち込まない。** 溜池では最後に変更域を 45°で
均して切り口の崖をなくしたが、**外堀は総石垣で、垂直の壁こそが正しい姿**である。
45°で均すと石垣の面が土に埋まり、堀が皿になる。勾配の頭打ちは**摺り付けの帯だけ**に掛ける。

#### 2. 種地は「この堀自身の普請」だけを戻す

復元の種地は 2026-08-22 のリセット直前のハイトマップで、そこには**この堀を 2026-08-10 に
掘った形**が入っている。溜池では岸の帯にこれを使えなかった — リセット前の岸には干場や旧平場など
**他家の造成**が混ざっており、戻すと 08-22 以降に建った屋敷の平場をえぐるからである。

**外堀の工区では事情が違う。** 工区の中で現況が自然地形と食い違うセルは虎ノ門の橋の足元だけで、
そこは**凍結域 K1 として工区から外した**(下記)。残るセルで種地をそのまま戻すのは、
帯では**1セルだけ**である(数値は `sotobori_terrain.json` の `provenance`)。
つまり**帯に戻すのはこの堀自身の普請しか無い**。

⛔ **初版はこの検算を通したつもりで通っていなかった。** 「虎ノ門の橋の足元は種地と現況が一致する」と
書いていたが、実測では一致はごく一部で、**種地をそのまま戻すと生き残っている枡形・橋を数m掘り落とす**
ところだった(2026-08-26 検図)。⛔ **一致する割合も最大の掘り落としもこの文に写さない** —
正典は `sotobori_terrain.json` の `provenance`(其四が図に出す)で、
写した値は再生成で古くなる(2026-09-01 検図で、この節の写しが生成側と食い違っていた)。
だから足元は凍結域に置き、検算の数字を
`provenance` に出力させて図に載せることにした。⚠ この検算は**工区を広げれば成り立たなくなる**ので、
広げるときは必ず取り直すこと。

#### 3. 工区を閉じる — 汀線から測るだけでは足りない

工区は掘る水面(00002・00003)の汀線の外側までで閉じ、**その外は1セルも触らない**。

⛔ **「汀線+14m」と書くだけでは閉じない。** 帯は放っておくと**隣の水面 00001 とその岸、
そして虎ノ門の橋の足元を覆う** — 初版はそこを最大 6.46m 動かしていた(484m²・2026-08-26 検図)。
そこで `works.keepOut` を置き、**掘らない水面とその岸14m** および
**凍結矩形 K1(虎ノ門枡形と虎ノ門の橋の足元)**を帯から外す。
⚠ **掘る水面の内側は外さない** — 虎ノ門の橋を貫く水路は 00002 の汀線の内側にあり、
そこは床まで掘るのが正しい。

⚠ 郭内側(北東)の石垣の背面の先には虎ノ門内の4敷地があり、郭外側(南西)には愛宕下の町屋がある。
**それらの地盤はこの普請の担当ではない** — 08-22 のリセットで平らになったままでも、ここでは直さない。

#### 4. 岸は石垣の天端の少し下まで盛る

**汀線は石垣の見え面**だから、そこから躯体の厚みぶんの帯は石そのものが占める。
⛔ **この帯を「触らない」と書かない** — 天端まで上げれば石が土に埋まるので**天端基準では盛らない**が、
種地を戻すので**掘削も埋め戻しも起きる**(全土量に占める割合は `sotobori_terrain.json` が正典)。
正確な言い方は `sotobori_sashizu.json` の `works.rule` の ② が正典で、**この文で言い替えない**。
**躯体の裏面から摺り付けの手前までは、最寄りの石垣の天端の少し下まで盛る**
(石垣の**背面** = 裏込めの上の地面)。⛔ **「土居」の語は使わない** ── 当区間は総石垣で、
牛込〜赤坂の土手構造は当てはまらない【A】。
⛔ **この高さの決め方は【U】** ── 2026-08-30 のユーザー裁定Aで決めた設計判断であって、
**史料は当区間の岸の高さを語らない**。高さの値は `sotobori_sashizu.json` の
`works.rule` の ② と `bankBelowCoping` が正典。

⭐ **2026-08-30 のユーザー裁定Aで、この形に決まった【U】。** それまでは「岸には 08-22 のリセット直前の
地面をそのまま戻す」規則で、天端まで届かない所だけを附則で補っていた。附則の起点が
**躯体の裏面より外に置かれていた**ため、継ぎ目の入隅に**躯体でもなく盛る対象でもない帯**が残り、
そこが溝になっていた(継ぎ目だけで出たのは、2026-08-10 の掘削がここだけ石垣の裏まで掘っていて
種地が堀底だから)。裁定Aで**規則②そのものを天端基準に改め、附則は撤廃した**ので、旧来の溝は消えた。
⚠ **ただし出隅には、なお水面より低い所が残る。** 規則②の帯は**汀線からの距離**で作るので、
汀線が折れる所では扇形になり、**直線の駒はそれを埋めない**(現地で見える砂色の三角形)。
⛔ 継ぎ目だけの話ではなく、**東端の2出隅も同じ**(2026-09-01 検図)。
現象は `sotobori_sashizu.json` の **U11**、量は同じく **`ishigaki.cornerFan`**(経緯と実寸は U7)が
正典で、**この文に数値を写さない**。
⛔ **直し方はユーザー裁定が要るので、指図には案を書いていない。**

#### 5. 00001 で見つかった不具合は、ここでは直さない

現況調査で、00001 の南西では**三つが揃って食い違っている**ことが分かった。

- **石垣** — `Ishigaki_Ext_4`(86駒)の天端が地面に潜っている。虎ノ門の橋の取付の `Ext_5`/`Ext_6` も同様。
  ⚠ 潜り具合の数値は其十三の表(`sotobori_terrain.json`)が正典
- **汀線** — 南西の汀線が岸の上へ乗っており、水面の板が土を食っている(断面イ)。
  ⭐ これは 2026-08-29 のユーザー裁定で石垣の見え面へ合わせ直して解消した(U9)
- **量** — 水面より上に出ている面積は其二の表が正典。⛔ **この文に数値を写さない** —
  写した値が再生成のたびに古くなり、2026-08-31 の検図で同じ図の別の章と 5.6 倍食い違っていた

⛔ **初版はこれを「乾きの9割は汀線から4m以内の縁」と書いて済ませていた。** 物差しが
「汀線からの距離」で、**水面より何m高いか**という肝心の量を測っていなかった(2026-08-26 検図)。
汀線が岸へ乗っていれば、縁に見えて実は 3m 以上の土手になる。

⚠ **08-22 のリセットのせいではない** — 現況と 08-22 リセット直前が完全に一致しており、
**2026-08-10 に建てたときからこの姿**であった。
⭐ **2026-08-29 にユーザーが「石垣を正として水域と地形を合わせよ」と裁定し、00001 の汀線と地形を
石垣の見え面へ合わせて解決した。** → U9

あわせて **00001 の郭内の石垣と史料の設計高の関係**を検めた。数値は `sotobori_sashizu.json` の U1b が正典。
⛔ **2026-08-28 に石垣の天端の計算式の誤りが見つかり、この項は結論ごと差し替わった** — 経緯は `git log`。→ 未解決 U1b

#### 6. Recarve を使わない

`WaterBody` の Recarve は使わない。00002 の snap は荒掘り時代のもので、押すと復元事故になる
(2026-08-10 に確認済み)。**手動掘り → RebuildSurface → SyncWaterSnaps** の順で回す。

#### 7. 汀線は石垣の見え面に載せる

**水に接するのは石の見え面**であって、部材のピボットが並ぶ線ではない。キットのピボットはメッシュの
中心に無いので、run の端点をそのまま汀線にすると躯体の厚みぶん陸側へずれる。
2026-08-29 にユーザーが「**石垣を正として水域と地形を合わせよ**」と裁定し、00001 をこの基準へ直した。
**2026-08-30 に 00002/00003 も同じ基準へ揃えた** — 石垣の位置を実機で測り、run のピボット線と
見え面を両方とも指図に載せ、汀線の頂点を見え面の実測端点に一致させた。

⛔ **前版は 00002/00003 の run に「汀線から石垣までの隔たり」を持たせて汀線をピボット線で語っていた。**
式のうえでは見え面と同じ所に落ちていたので汀線の値は正しかったが、**基準の書き方が 00001 と食い違い**、
同じ帯を一方は「石垣の前だから床のままが正しい」、もう一方は「汀線の外に床が残る不具合」と
評価していた。基準を揃えたことで、この帯は**石垣の躯体が占める帯**だと確定した。→ U11

⚠ 隅の駒は run ではなく隅として持つ。1個ないし飛び飛びの駒なので、run 線として扱うと
長さゼロの線や堀を横断する偽の線になり、背面の検査が壊れる。

### 施工と検査

段階は `sotobori_sashizu.json` の `stages`、合否は `checks` にある。要点だけ:

- **地形の編集は Undo の外**にある。触る前に heightmap を `.bin` で退避し、
  `TerrainData.asset` と `.unity` も別に採る。`Scene.isDirty` は当てにならない。
- **MCP のタイムアウト後の再送で多重実行が起きる。** 掘削は冪等ではないので、
  流す前に実行済みかを必ず確かめる。ガードのマーカーは **active** にする。
- **石垣は1個も動かさない**(CLAUDE.md 絶対規則1)。掘削が石垣に取り合っているかは
  「背面の地盤が天端の直下にあるか」で測る。⚠ 短い折れは評価点が数点しかないので、
  中央値だけで合否を決めず実装後に目視で確かめる。
- **新シ橋の橋脚が床に届いているか**は掘った後でなければ測れない。掘削の後に検める。
