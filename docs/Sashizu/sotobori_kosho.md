# 溜池堰下流の外堀の掘り直し — 考証と決めごと

指図 `sotobori_sashizu.html` の**文章の部**。寸法は `sotobori_sashizu.json`(設計値の正典)、
実測は `sotobori_terrain.json` にあり、**この文書には数値を写さない**。**現況形で書く。**
経緯は `git log docs/Sashizu/` で追う。

**再現の基準年次は 安政3年(1856)**(CLAUDE.md の不変則)。⚠ 安政江戸地震(安政2年10月)の翌年で、
描くのは**復旧が済んだ姿**である。

## 対象の範囲

**溜池の堰(どんどん)から下流の外堀ひと続き**を対象とする。上流の溜池そのものは 2026-08-26 に
掘り直し済(`EDO-0039`)で、ここには含めない。下流端は `Sotobori_00003` の東端で、
その先の幸橋御門・汐留川は未再現。

⚠ **三つの水面で扱いが違う。** 08-22 のリセットが「水色の囲い」の内か外かで生死が分かれた。

- **`Sotobori_00001`(堰〜虎ノ門)= 調査のみ。** 虎ノ門枡形とともに囲いの中に入っていたため
  無傷で、現況は 08-22 リセット直前と完全に一致する。水面より上に出ている所も、その大半は
  汀線から4m以内の縁で、残りは堰の頭と虎ノ門土橋 — どちらも構造物であって掘り残しではない。
  **掘る所は無い。1セルも触らない。**
- **`Sotobori_00002` / `Sotobori_00003`(土橋の東)= 全面 掘り直し。** 囲いの外。

⛔ **したがって工区は土橋の東で始まる。** 00001 とその岸・堰の頭・枡形の足元は工区の外に置く。

## この普請の性格

**新設ではなく復旧である。** 虎ノ門土橋の東から幸橋方向へ下る外堀(`Sotobori_00002` /
`Sotobori_00003`)は 2026-08-10 に一度掘られ、両岸に総石垣が据わり、新シ橋が架かっている。
2026-08-22 のジオリファレンス補正で**「水色の囲い」の外の造成を自然地形へ戻した**とき、
囲いに入っていたのは虎ノ門枡形とその足元だけで、**土橋の東は堀の掘削もろとも現代の地面へ復した**。

水面のメッシュは張られたままなので、いまは**乾いた地面の中に水の板が沈んでいる**。
両岸の石垣も土に埋まっている。溜池で同じ取りこぼしを直したのが `EDO-0039` で、
その報告が「同じことが外堀に残っている」と名指ししたのがこの件である。

⚠ **したがって考証の主題は「どう掘るか」ではなく「何を根拠に元へ戻すか」**である。
堀の形・石垣・橋は既存実装をそのまま採り、この指図は動かさない。
⛔ **ただし「すでに考証を通っている」とは言えない** — とくに**水位の値は史料に無い設計判断【U】**である
(下記)。段差が**在ること**は史料に依るが、**値**は当プロジェクトが決めたものにすぎない。

## 史実(既存実装の前提)

典拠は `[外堀保存管理計画書]`(千代田区・港区・新宿区『史跡 江戸城外堀跡 保存管理計画書』平成20年3月)。
2026-08-26 に本編・資料編を取り直して原文照合した。⚠ **本書は虎ノ門〜幸橋を史跡指定範囲に含まない**
(飛び地指定は虎ノ門・溜池間)ので、当区間の記述は沿革・埋立史に限られる。

### 当区間(虎ノ門〜幸橋 = 00002 / 00003)について言えること

- **低地の堀で、牛込〜赤坂の土手構造は当てはまらない**。「史跡指定地は…牛込門～赤坂門間の堀と、
  **低地に築いた石垣を主体とした堀**のうち残存部となる虎ノ門周辺の堀の大きく２つの地域に分けられる」
  【確度 A — 本編の明文】
- **総石垣である**。慶長11年(1606)の日比谷入江埋立てに伴う「**虎ノ門から幸橋門までの堀普請**」/
  寛永13年の「**雉子橋から土橋までの外堀を総石垣化**」/ 郭外側は出土石垣のモニュメント(港区西新橋1丁目)に
  **豊後臼杵藩稲葉家の刻印** / 年表「**文久2年 虎ノ門東方石垣が孕み**、虎ノ門から山下御門までの
  御堀埋出洲掃除浚のため湯小屋取建」【いずれも 確度 A】。⭐ **基準年次(安政3年=1856)に最も近い堀の記事は 安政5年(1858)の城濠浚渫**で、
**石垣に触れる記事としては文久2年(1862)が最寄り(6年後)**である。
- ⛔ **当区間の石垣の高さ・堀幅・水面標高は本書に無い【?】。** → 未解決 U1
- **堀底は素掘り**で、出洲の堆積が繰り返し浚われている【A】。→ U4

### 段差の機構

- 「各見附の**橋台石垣もしくは土橋**には、各堀の水位調整のための**堰**や排水暗渠が設置されていた」/
  「弁慶濠から溜池以南の堀もやはり城門に築いた堰などを利用して**順次低くなる構造**」【確度 A】
- ⛔ **標高の値は一切書かれていない**(図10-1-2 の縦断面模式図は喰違〜牛込の区間のみ)。
  したがって **6.60 / 6.40 / 3.50 / 3.30 / 1.80、深さ 1.50、落差の値はすべて設計判断【U】**である。
  ⚠ 初版は「堀の形・水位・石垣・橋はすでに考証を通って実装されており」と書いていたが、
  **水位について「考証を通った」と言える根拠は無い**。段差の**存在**が A、**値**が U。
- ⚠ **虎ノ門の橋を土橋とするのは実装上の選択【U】。** 本書の類型は「**低地に位置する牛込門・市谷門では
  橋台石垣**が、台地部の四谷門・喰違・赤坂門には土橋が存在した」で、虎ノ門は低地側。
  年表も明暦3年「**虎ノ門橋の普請**(内藤政親丹波守)」と橋を架ける表現を採る。堰があること自体は A。

### 一水位という置き方が成り立つ理由

「汐留」は**潮止め**に由来し、その堰は**下流端の土橋(幸橋門)**にある【確度 B — [汐留の由来]。
Wikipedia に脚注が無い。一次の裏取りは『東京市史稿』港湾篇・港区史】。
**堰が潮を止める以上、その上流にあたる当区間は非感潮**なので、水面は堰の天端が決める一定値になる。
東京湾の朔望平均満潮位はおよそ T.P.+1.0m で、1.80 はその上 — 内部矛盾は無い(値そのものは【U】)。
⛔ **幸橋門より下流の汐留川は感潮**なので、1.80 を延長してはならない。

### 虎御門に渡櫓は無い【確度 B】

⛔ **初版は「享保16年ないし明和9年の焼失後、再建されていない」と書いていたが、同じ本の年表がこれを
否定する** — 「1731 享保16 虎ノ門焼失」の**翌年**に「1732 享保17 **虎ノ門普請**」があり、
1772年(明和9)の虎ノ門欄は空である。
渡櫓が無いことの根拠は焼失年ではなく、**明治6年の撤去記事の書き分け**(「数寄屋橋門・…・**幸橋門の渡櫓**や、
神田橋門・…・**虎ノ門**・…外郭12門の撤去」— 渡櫓を挙げる門と挙げない門を書き分けている)と、
明治33年の計画「**虎ノ門は高麗門を残し**大部分…撤去」【いずれも間接なので B】。
⚠ 正面から決めるには 図10-1-15「江戸城御外郭御門絵図 虎御門」(都立中央図書館蔵)の原図が要る。
⚠ 併せて、当プロジェクトが虎ノ門の枡形に当てている定型値(内法20間2尺3寸・門内法2間4尺・橋幅3間渡9間)は
**牛込・市谷・四谷・赤坂の各条に繰り返される定型で、虎ノ門の条には無い** — 他門からの外挿【B】。
しかも原文は「**冠木門**」で「高麗門」ではない。

### 新シ橋

嘉永期の切絵図2種(尾張屋版 4-002 / 7-118)に**記載がある**【A — ただし当方は孫引きで、実見して
台帳を起こすのが宿題】。**寸法・橋脚数・木橋という形式は典拠が無く【?】、実装値は【P】**。

## 設計の決めごと

### 1. 壁は垂直のまま残す

⛔ **溜池の掘り直しの手つきをそのまま持ち込まない。** 溜池では最後に変更域を 45°で
均して切り口の崖をなくしたが、**外堀は総石垣で、垂直の壁こそが正しい姿**である。
45°で均すと石垣の面が土に埋まり、堀が皿になる。勾配の頭打ちは**摺り付けの帯だけ**に掛ける。

### 2. 種地は「この堀自身の普請」だけを戻す

復元の種地は 2026-08-22 のリセット直前のハイトマップで、そこには**この堀を 2026-08-10 に
掘った形**が入っている。溜池では岸の帯にこれを使えなかった — リセット前の岸には干場や旧平場など
**他家の造成**が混ざっており、戻すと 08-22 以降に建った屋敷の平場をえぐるからである。

**外堀の工区では事情が違う。** 工区の中で現況が自然地形と食い違うセルは虎ノ門土橋の足元だけで、
そこは**凍結域 K1 として工区から外した**(下記)。残るセルで種地をそのまま戻すのは、
帯では**1セルだけ**である(数値は `sotobori_terrain.json` の `provenance`)。
つまり**帯に戻すのはこの堀自身の普請しか無い**。

⛔ **初版はこの検算を通したつもりで通っていなかった。** 「土橋の足元は種地と現況が一致する」と
書いていたが、実測では一致は 22.5% で、**種地をそのまま戻すと生き残っている枡形・土橋を最大 5.86m
掘り落とす**ところだった(2026-08-26 検図)。だから足元は凍結域に置き、検算の数字を
`provenance` に出力させて図に載せることにした。⚠ この検算は**工区を広げれば成り立たなくなる**ので、
広げるときは必ず取り直すこと。

### 3. 工区を閉じる — 汀線から測るだけでは足りない

工区は掘る水面(00002・00003)の汀線の外側までで閉じ、**その外は1セルも触らない**。

⛔ **「汀線+14m」と書くだけでは閉じない。** 帯は放っておくと**隣の水面 00001 とその岸、
そして虎ノ門土橋の足元を覆う** — 初版はそこを最大 6.46m 動かしていた(484m²・2026-08-26 検図)。
そこで `works.keepOut` を置き、**掘らない水面とその岸14m** および **凍結矩形 K1(虎ノ門枡形と土橋の足元)**を
帯から外す。⚠ **掘る水面の内側は外さない** — 土橋を貫く水路は 00002 の汀線の内側にあり、
そこは床まで掘るのが正しい。

⚠ 郭内側(北東)の土手の先には虎ノ門内の4敷地があり、郭外側(南西)には愛宕下の町屋がある。
**それらの地盤はこの普請の担当ではない** — 08-22 のリセットで平らになったままでも、ここでは直さない。

### 4. 石垣の背後だけ盛る — 矩形ではなく規則で書く

2026-08-10 の掘削は、入隅(00002×00003 の継ぎ目)で石垣の背後まで床を削っている。種地をそのまま
戻すと短い折れが土留めとして立たない。**汀線は石垣の見え面**だから、そこから躯体の厚みぶんの帯は
石そのものが占める。盛るのは**その裏面よりさらに背後**で、**種地が床のまま**の所だけを、
最寄りの天端の少し下まで上げる。
⚠ **躯体の帯は床のままでよい** — 盛れば石が土に埋まる。値は `sotobori_sashizu.json` の
`works.bankFill` が正典。

⛔ **初版は矩形+閾値で書いていた。** 範囲が恣意的で入隅の外へ一般化せず、しかも
「主要部を戻す」と書きながら戻すのは僅かだった(2026-08-26 検図)。規則へ改めたあとも、
**継ぎ目の入隅では石垣の背後に溝が残る。**
⛔ **前版は「入隅で距離場が破綻するから規則では解けない」と診断していたが、これは撤回する。**
2026-08-30 に細かい格子で測り直した結果、**原因は距離場ではなく、この規則の起点の取り方**だった —
起点が石垣の躯体の裏面より少し外に置かれているため、**躯体でもなく盛る対象でもない帯**が残る。
継ぎ目だけで出るのは、2026-08-10 の掘削がここだけ石垣の裏まで掘っていて種地が堀底だからである。
起点を躯体の裏面に合わせると溝は消え、しかも継ぎ目以外のどこにも掛からないことを全長で試算した。
⛔ **どの案を採るかは未決**(規則の起点を寄せる / 継ぎ目だけ手で決める / 現状のまま)。
溝の実寸と3案の効き、裁定図の在り処は `sotobori_sashizu.json` の U7 が正典。→ 未解決 U7

### 5. 00001 で見つかった不具合は、ここでは直さない

現況調査で、00001 の南西では**三つが揃って食い違っている**ことが分かった。

- **石垣** — `Ishigaki_Ext_4`(86駒)の天端が地面に潜っている。土橋取付の `Ext_5`/`Ext_6` も同様。
  ⚠ 潜り具合の数値は `sotobori_terrain.json` が正典で、**2026-08-30 に 00001 の run 線(ピボット)を
  実測へ直した**ため、再生成するまで古い
- **汀線** — 南西の汀線が岸の上へ**約5m乗って**おり、水面の板が土を食っている(断面イ)
- **量** — 水面より上に出ているのは堀の本体だけで **652m²**、うち **632m² は水面より1m以上高い**

⛔ **初版はこれを「乾きの9割は汀線から4m以内の縁」と書いて済ませていた。** 物差しが
「汀線からの距離」で、**水面より何m高いか**という肝心の量を測っていなかった(2026-08-26 検図)。
汀線が岸へ乗っていれば、縁に見えて実は 3m 以上の土手になる。

⚠ **08-22 のリセットのせいではない** — 現況と 08-22 リセット直前が完全に一致しており、
**2026-08-10 に建てたときからこの姿**であった。
⭐ **2026-08-29 にユーザーが「石垣を正として水域と地形を合わせよ」と裁定し、00001 の汀線と地形を
石垣の見え面へ合わせて解決した。** → U9

あわせて **00001 の郭内の石垣と史料の設計高の関係**を検めた。数値は `sotobori_sashizu.json` の U1b が正典。
⛔ **2026-08-28 に石垣の天端の計算式の誤りが見つかり、この項は結論ごと差し替わった** — 経緯は `git log`。→ 未解決 U1b

### 6. Recarve を使わない

`WaterBody` の Recarve は使わない。00002 の snap は荒掘り時代のもので、押すと復元事故になる
(2026-08-10 に確認済み)。**手動掘り → RebuildSurface → SyncWaterSnaps** の順で回す。

### 7. 汀線は石垣の見え面に載せる

**水に接するのは石の見え面**であって、部材のピボットが並ぶ線ではない。キットのピボットはメッシュの
中心に無いので、run の端点をそのまま汀線にすると躯体の厚みぶん陸側へずれる。
2026-08-29 にユーザーが「**石垣を正として水域と地形を合わせよ**」と裁定し、00001 をこの基準へ直した。
**2026-08-30 に 00002/00003 も同じ基準へ揃えた** — 石垣の位置を実機で測り、run のピボット線と
見え面を両方とも指図に載せ、汀線の頂点を見え面の実測端点に一致させた。

⛔ **前版は 00002/00003 の run に「汀線から石垣までの隔たり」を持たせて汀線をピボット線で語っていた。**
式のうえでは見え面と同じ所に落ちていたので汀線の値は正しかったが、**基準の書き方が 00001 と食い違い**、
同じ帯を一方は「石垣の前だから床のままが正しい」、もう一方は「汀線の外に床が残る不具合」と
評価していた。基準を揃えたことで、この帯は**石垣の躯体が占める帯**だと確定した。→ U11

⚠ 隅の駒は run ではなく隅として持つ。1個ないし飛び飛びの駒なので、run 線として扱うと
長さゼロの線や堀を横断する偽の線になり、背面の検査が壊れる。

## 施工と検査

段階は `sotobori_sashizu.json` の `stages`、合否は `checks` にある。要点だけ:

- **地形の編集は Undo の外**にある。触る前に heightmap を `.bin` で退避し、
  `TerrainData.asset` と `.unity` も別に採る。`Scene.isDirty` は当てにならない。
- **MCP のタイムアウト後の再送で多重実行が起きる。** 掘削は冪等ではないので、
  流す前に実行済みかを必ず確かめる。ガードのマーカーは **active** にする。
- **石垣は1個も動かさない**(CLAUDE.md 絶対規則1)。掘削が石垣に取り合っているかは
  「背面の地盤が天端の直下にあるか」で測る。⚠ 短い折れは評価点が数点しかないので、
  中央値だけで合否を決めず実装後に目視で確かめる。
- **新シ橋の橋脚が床に届いているか**は掘った後でなければ測れない。掘削の後に検める。

⭐ **裁定を仰ぐのは2件。**

- **U7 の入隅の納め** — 継ぎ目の折れが**実在する**ことは 2026-08-29 に、**向き**は 2026-08-30 に決着した
  (五千分一東京図を原寸で測り直した結果、08-29 の読みが誤りと分かった)。量も読取誤差の範囲で近い。
  ⚠ ただし**折れの「位置」はまだ照合していない**ので、量は過小に見積もっている可能性がある。
  残るのは石垣の背後に残る溝をどう納めるかで、**規則の起点を寄せる / 継ぎ目だけ手で決める /
  現状のまま**の3案がある。
- **U12 の合否の扱い** — 掘る水面の石垣が一つ、自分で立てた合格条件を満たさない。原因は掘削の不良ではなく
  **もともと地面が天端より高い西端**にある。**合格文に例外を書く / 工区の凍結域を伸ばす**の2案。

⛔ **どれを採るかは指図では決めない。** いずれもユーザーの「史実に沿うなら設計変更可」の範囲に入る。
⚠ **確度(S/A/B/P/U/?)と状態(解決/未決/保留/裁定待ち)は別の欄**である。指図の `unresolved` では
`cert` と `status` に分けてある。**S は当方の実測や内部事情には付けない**(実測は P)。
