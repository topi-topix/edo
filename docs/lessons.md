# 規則の由来 — CLAUDE.md の各規則が生まれた出来事

CLAUDE.md は不変則とルーティングだけを載せる(2026-09-06 に減量した。それまで 28KB あり、
毎往復・全サブエージェントの起動費になっていた)。**規則がなぜあるか**はここに置く。
番号は CLAUDE.md の絶対規則の番号。日付は出来事が起きた日。

---

## 座標系・寸法・年次

- **基準年次を安政3年(1856)に固定**: 2026-08-29 ユーザー裁定で「嘉永期(1850年前後)」から改めた。
  「江戸末期」のような幅では、どの図を正とするかで毎回迷う。安政江戸地震(1855-11-11)の翌年なので、
  描くのは復旧が済んだ姿。詳細は `references/sources.md` の [基準年次]。
- **Y=0 は海抜0m**: 2026-08-01 に移行。それ以前の Y 値は +25 して読む。
- **蹴上/踏面 0.30/0.45 を参道の坂に適用しない**: 2026-08-24 裁定。両端(平面長と比高)が地形と実測で
  固定されるので、蹴上と踏面は段数からの従属値にする(汐見坂は同じ蹴上に踏面 6.0m)。

## 絶対規則の由来

- **規則2(指図を先に起こす)**: 飛ばして2度全面差し戻された。図なら数分、建ててからだと数時間。
- **規則3(面の高さは地形が決める)**: 指図には現況図・切盛図・断面・動線図を必ず入れる。
  無い指図をユーザーに出して差し戻された。
- **規則4(指図は現況だけ)**: 2026-08-29、突き合わせ 53 件が出たままのシーンで外周の不具合を
  指摘された。指図では直っていた。
- **規則5(部材どうしを中心で合わせない)**: 2026-08-29、門は開口の芯に、長屋は run の頭から丸ごと
  並べていて、門に 1.66m 食い込み・0.96m 空くのが同時に起きた。
- **規則10(自作の低ポリの木を置かない)**: 2026-08-30 ユーザー指示「これは2度と使わないでください。
  見た目がしょぼすぎます」。`Assets/Edo/Terrain/details/BroadleafTree.prefab`(2,384 三角)が対象。
- **規則13(造成前の地盤を Unity から採らない)**: 2026-08-23、松平が朝に流した造成を岡部・土井が
  昼の標本で「造成前」として吸い込んだ。live terrain は採る時刻で値が変わる。
- **規則14(図には読める分解能がある)**: 2026-08-29、1/4 概観で「外堀の折れは無い」と確度Aで断じたが、
  原寸では新シ橋にはっきり描かれていた。古地図オーバーレイの残差は中央値 55m。
- **規則15(屋敷を苗字だけで呼ばない)**: 切絵図の「松平備前守」は「松平肥前守」の誤読で、裸の
  `Edo_Yashiki_Matsudaira` は佐賀鍋島家の溜池中屋敷。2026-08-30 に松江松平を `matsudaira_dewa` へ改称
  (指図・生成器・ビルダー・掲示板・`CheckScene` すべて)。シーンのグループ名は履歴なので変えない。
- **規則16(一通に一種別)**: 2026-08-30 ユーザー指摘「どの質問や裁定にどう回答して良いか非常に困る」、
  同日「番号は報告・共有にも振る」、2026-08-31「U12 とか言われてもどんな内容だったか分かりません」、
  同日「指図はローカルのパスで示さない — 必ず Artifact の URL で」。正典は `docs/reporting-protocol.md`。
- **規則17(意匠を決める役と書き起こす役を混ぜない)**: 2026-09-01、普請奉行が素人考えで組んだ庭の案を
  「決まった大方針」として指図方へ渡し、ユーザーに「指図担当に庭を設計する能力はあるのか」と止められた。
- **規則18(検図関門)**: 2026-09-01、松江松平の庭が庭方に一度も検められないまま Stage7 まで実装され、
  差し戻された。ルーティング表に庭方は載っていたが、通さなくても何も起きなかった。
  関門は新設なので全6邸が赤(17件)で立ち上がり、同日ユーザー裁定(案B)で移行期間を設けた。
- **規則19(輪に入っていない値は未検査)**: 2026-09-02、松江松平で同じ型を3度見逃した(東庭の平面図・
  板塀の足元の判定・それを直すために書いた水の検査が、いずれも `main()` から呼ばれていなかった)。
  検図3巡かけて見つけた5件を `wiring_gate.py` は1秒で全部出す。岡部にも `walls_table` が一度も走らない
  実例があった。

## 触ると壊れるもの の由来

- **複数セッションの同時作業**: 2026-08-24、広い staging で他セッションが編集中の指図を巻き込んで
  コミットした。以後、`git add -A` / `commit -a` は門番が止める。
- **Unity の握りっぱなし**: 2026-08-30 ユーザー指摘。心拍は別作業でも更新されるので、放置すると
  他邸が永久に触れない。20分未使用は待っている側が自動で引き取る。
- **地形の作り直し(2026-08-22)**: ジオリファレンスの 8m ズレを補正し、水色の囲いの外の造成を
  自然地形へ戻した。→ `docs/terrain-georef-fix.md`
- **コンパイルの停止**: 2026-08-14 に2回、古いアセンブリで走って「直したのに反映されない」と誤診した。
- **検査役に Unity を握ったまま呼ぶ**: 2026-08-31、外堀セッションで検査役がレンダを撮れず、
  呼び出し元が自分で撮る羽目になった(EDO-0097)。

## 役の名前の由来

- **普請奉行**: 2026-09-02 まで「本文脈」と呼んでいた(他9役が江戸の職名なのにここだけ実装用語だった)。
- **指図方**: 2026-08-29 に「作事方」を名乗ったが、史実の作事方は工事を管理する行政組織で
  図面を引く個人ではないため訂正した。
- **作事奉行(廃止)**: 2026-08-29 に「司令塔」から改名(門番と同名で紛らわしかった)。
  2026-09-06 ユーザー裁定で**廃止**。記録上3回しか呼ばれず、ダッシュボードは9月2日で止まり、
  三巡則の見張りも効いていなかった(松江松平 11巡・岡部 12巡・土井 14巡)。仕事①ダッシュボード
  ②翻訳③異常検知④取りこぼしの起票のうち、①は `build_board_html.py` が生成し、③④は挨拶フック
  (掲示板 digest・検図関門・結線関門)と直接メッセージで足りる。古い記録・コミットには
  「司令塔」「作事奉行」の名で残る(履歴なので書き換えない)。

## トークン消費の由来(2026-09-06 集計)

117 本の主セッションと 376 本のサブエージェントの記録を集計した。費用の 6 割は「文脈全体の
毎往復の読み直し」で、主セッションの往復の半分が文脈 400K 超、圧縮は 1M 手前まで起きなかった。
放置後の丸ごと再キャッシュが cache 書きの半分。指図方1回で 2,346 往復の例があった。
