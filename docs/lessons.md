# 規則の由来 — CLAUDE.md の各規則が生まれた出来事

CLAUDE.md は不変則とルーティングだけを載せる(2026-09-06 に減量した。それまで 28KB あり、
毎往復・全サブエージェントの起動費になっていた)。**規則がなぜあるか**はここに置く。
番号は CLAUDE.md の絶対規則の番号。日付は出来事が起きた日。

---

## 座標系・寸法・年次

- **基準年次を安政3年(1856)に固定**: 2026-08-29 ユーザー裁定で「嘉永期(1850年前後)」から改めた。
  「江戸末期」のような幅では、どの図を正とするかで毎回迷う。安政江戸地震(1855-11-11)の翌年なので、
  描くのは復旧が済んだ姿。詳細は `references/sources.md` の [基準年次]。
- **Y=0 は海抜0m**: 2026-08-01 に移行。それ以前の Y 値は +25 して読む。
- **蹴上/踏面 0.30/0.45 を参道の坂に適用しない**: 2026-08-24 裁定。両端(平面長と比高)が地形と実測で
  固定されるので、蹴上と踏面は段数からの従属値にする(汐見坂は同じ蹴上に踏面 6.0m)。

  取り合いを紙で計算して建ててから紙を直していた(2 週間の直しの 12%)。7 週間で完成 0/88。裁定図
  https://claude.ai/artifact/EouMVDWUjrGCaDuZ4tUHVW ・新しい輪 https://claude.ai/artifact/NLH516uX8qR8XnSxPE4Rnh

  7,000 棟中 250 棟だけ手作りし残りは類型生成で完成させた。→ `docs/typology-builder.md`
- **規則3(面の高さは地形が決める)**: 指図には現況図・切盛図・断面・動線図を必ず入れる。
  無い指図をユーザーに出して差し戻された。

  指摘された。指図では直っていた。**2026-09-19「実装後は開かない」を足した**: 松江松平の指図は凍結
  (第32次・09-09)後も第54次まで上がり、2 週間の直しの 30% が図の書式・帳簿だった。欠陥の三分類
  (許容0 / 気にしない / 指図を開く)は施主の基準で、ずれの大きさでは決めない。
  **同日夜「図を開く」を廃した**: 「屋根の型が変わるとき」を残したまま二層が撤回され、松江松平が厩の庇
  (四方→三方)で図を開いて 22,058 行の生成器(1 回 3 時間)と検分をまた回した。施主「素早く開発したい。類型で
  ガッと作って、区画ごとに細かく直す」。建った敷地の直しはすべて json の欄の上書きで、図を起こし直すのは
  施主がそう言ったときだけ(`kansei_gate.py --reopen` は発話の引用が要る)。

  見た目がしょぼすぎます」。`Assets/Edo/Terrain/details/BroadleafTree.prefab`(2,384 三角)が対象。
- **規則13(造成前の地盤を Unity から採らない)**: 2026-08-23、松平が朝に流した造成を岡部・土井が
  昼の標本で「造成前」として吸い込んだ。live terrain は採る時刻で値が変わる。
- **規則14(図には読める分解能がある)**: 2026-08-29、1/4 概観で「外堀の折れは無い」と確度Aで断じたが、

  紙で座標を計算する輪が最も高い輪(指図の版上げ → 検分の再実行)を呼んでいた。

## 触ると壊れるもの の由来

- **複数セッションの同時作業**: 2026-08-24、広い staging で他セッションが編集中の指図を巻き込んで
  コミットした。以後、`git add -A` / `commit -a` は門番が止める。
- **Unity の握りっぱなし**: 2026-08-30 ユーザー指摘。心拍は別作業でも更新されるので、放置すると
  他邸が永久に触れない。20分未使用は待っている側が自動で引き取る。
- **地形の作り直し(2026-08-22)**: ジオリファレンスの 8m ズレを補正し、水色の囲いの外の造成を
  自然地形へ戻した。→ `docs/terrain-georef-fix.md`
- **コンパイルの停止**: 2026-08-14 に2回、古いアセンブリで走って「直したのに反映されない」と誤診した。
- **検査役に Unity を握ったまま呼ぶ**: 2026-08-31、外堀セッションで検査役がレンダを撮れず、
  呼び出し元が自分で撮る羽目になった(EDO-0097)。

  図面を引く個人ではないため訂正した。
- **作事奉行(廃止)**: 2026-08-29 に「司令塔」から改名(門番と同名で紛らわしかった)。
  2026-09-06 ユーザー裁定で**廃止**。記録上3回しか呼ばれず、ダッシュボードは9月2日で止まり、
  三巡則の見張りも効いていなかった(松江松平 11巡・岡部 12巡・土井 14巡)。仕事①ダッシュボード

## 手仕舞いの規定(2026-09-06 追加)

⚠ **ユーザー指摘**「普請奉行は自分の残タスクや他普請奉行への依頼事項を掲示板に書き留めるという
役割は担ってないのでしょうか?」— 担っているはずだったが、**1サイクルの手順に無かった**。
サイクルは ⑧報告(ユーザーへ)→ ⑨返す(release)で終わっており、「残りを board に書き留める」が
どこにも無いまま、山王を止めた際に未マージのブランチを報告文にだけ書いて起票しなかった。
これは規則18・19 と同じ型の欠陥 —— **散文にも書かれておらず、飛ばしても何も起きなかった**。
→ `docs/fushin-bugyo.md`「手仕舞い」と `docs/session-board.md` §1 の第4の契機として結線した。

## 手仕舞いは「書く側」だけでは輪が閉じない(2026-09-06)

⚠ **ユーザー指摘**「最初に掲示板の残タスクを読み込むというのも漏れてそうな気がするが大丈夫?」
— そのとおりだった。手仕舞いの規定(上)を入れて宿題3件を起票した直後の digest に、その3件が
**一件も出ていなかった**。digest は「裁定待ち → ブロッカー → その他」を**古い順に10行**で切って
いたため、11日前の節目が枠を埋めていた。書く段だけ結線して読む段を見ていない、規則19 そのもの。
→ digest を 裁定待ち → ブロッカー → 宿題(新しい順6件)→ 節目(3件)の順に改め、7日動かない宿題を
1行で鳴らすようにした(旧・差配役の異常検知の代わり)。`list --type task` も足した。
⭐ **教訓: 結線したら、書いた物が本当に出るところまで自分で見る。**
