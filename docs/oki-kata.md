# 置き方の作法 — 部材をどう置き、どう据え、どう突き付けるか

**この文書が置き方の正典。**CLAUDE.md 規則4・規則21 はここを指すだけ、スキルと役の手引きもここを指すだけ。
⛔ 同じ事実をここと他所へ二重に書かない(書くならここを直して、他所は指し先に留める)。

関連: `unity-buke-yashiki/references/sashizu.md`(屋敷の取り合いの指図)・
`unity-surface-authoring`(地表と植栽の据え方の実例)・`docs/lessons.md`(由来)・`docs/typology-builder.md`。

## 0. 一行で

> **何かと何かが接するなら、触れている箇所を測って位置を決める。**
> **触れている箇所は探さずに決めておく ── 部材の型に「当たり」を持たせ、当たりが全部着くよう置き、当たりだけを測る(§0a)。**
> ⛔ 部材の基準点(ピボット・原点・bounds の中心)で決めない。絶対に。

「何か」は地面だけではない — **部材どうし・屋根と塀・隅と塀・石と土台・庇と縁**も同じ
(2026-09-21 施主指摘「何かと何かが接触している箇所です。地面だけでなく、オブジェクト同士もそうです」)。

## 0a. 接する所(当たり)を先に決める ── 決める → そこを接するよう置く → そこを測る(2026-09-27 施主指示)

> 施主「接するべきところを定義して、そこが接するように配置し、そこが接していることを計測することで正しく配置されて
> いることを確認すべき。設置する想定ではないところを測って隙間があると考えるのはナンセンス」。全ての物の置き方に効く。

**これまでの欠陥**: §3 の `Contact` は「接するべき所」を持たず、**最初に当たった点**を探してそこを 0 にしていた。
だから (1) 1 点さえ当たれば検査は必ず 0 近くで通り、残りが浮いていても捕まらない(2026-09-22 戸田ほか ── 足元の
起伏を刷り添えたのはその継ぎ当て)、(2) 逆に接する想定の無い所(石と石の目地の上)を測って「浮き」と数えた
(2026-09-27 山王の板塀の地覆)。**当たりを決めていない限り、「接している」も「浮いている」も言えない。**

### 他所の作法(調べた物・2026-09-27)

| 作法 | 何を決めているか |
|---|---|
| Unreal の Static Mesh の **Socket** | 接続点を**部材の資産の中に**名前・位置・向きで書き、相手はその点へ付ける |
| Bethesda(Fallout 4)の **Connect Point** | 部材に接続点を持たせ、**種別名が合う点どうしだけ**が繋がる |
| Unity XR の Socket・建築ゲームの socket 型 | 接続点に「受け付ける部材の種類」を持たせ、置いた後は**どの点に何が付いたか**を記録する(触れているだけでなく「繋がっている」と知る) |
| CAD(SolidWorks)の **Mate** | 「この面とこの面が一致」「この軸とこの軸が同心」と**拘束を宣言**し、それを満たすよう解く。満たせなければ過拘束として止まる |
| Skyrim の kit(GDC 2013) | ピボット・格子・**継ぎ目の断面(profile)**を最初に決めて変えない。組んで試す検め(loopback/stack/gap)を部材ごとに通す |
| 起伏のある地面に建てる(Unity の議論・建築ゲーム) | 足元の**決めた複数点**(隅・柱の足)から地面を測る。剛体で全点が着かない所は、**根入れ(基礎を地中へ伸ばす)・束(柱を足す)・段にする**のどれかを部材に持たせて埋める |
| 大工の**光付け** | 木の下端を相手(石の天端)の形へ写して削る ── 当たりは「石の上面」、目地は跨ぐ |

共通するのは、**接する所は部材の作りと一緒に決めて持たせ、置く道具は探さずにそれを使う**こと。

### 作法(この節が正典。§3 の道具はこの下で使う)

1. **当たりを部材の型に持たせる**(型ごとに一度だけ・部材方が起こすときに決める)。当たり一つごとに:
   - **形**: 面(土台が礎石に・長屋の床が基壇に)/ 線(塀の下端・地覆の下端)/ 点の組(柱の足元・石の三点・鳥居の二本)
   - **相手**: 地面 / 石の天端 / 別の部材の名指しした当たり(相手にも当たりがある ── Socket の対)
   - **跨ぎ**: 接しない所を名指す(目地・溝・縁の下)。⛔ 跨ぐ所は測らない
   - **合わせの余地**: 剛体のままでは全ての当たりが着かないとき、何で埋めるか ── 根入れ(地中へ沈める長さの上限)/
     光付け(下端を削る量の上限・`EdoBuild.ScribeToBed`)/ 伸縮(練塀の長さ)/ 束・段。**余地を持たない型は、着かなければ退ける**(§4a の硬い制約)
   - ⭐ **余地の選び方(2026-09-27 施主)**: **基本は根入れ(少し埋めて、つなぎ目を苔・土・草・暗い帯で隠す)**。
     **見た目に違和感が出る所だけ光付け**(相手の形へ削る)。理由は開発の速さ ── 埋めるのは部材を増やさず一手で済み、
     削るのは駒ごとに別のメッシュになって重い。光付けが時間を食う・点が増えて重いときは根入れへ切り替える。
     他所の作法も同じ(ゲームは埋めて隠すのが最も多い・削って沿わせるのは Spline Mesher・FenceLayout・Houdini の Ray の型 ── 調べは EDO-0437 の記録)
   - 持たせ方は**資産の側**: FBX の中の名付きの空の点・線(`Atari_*`)か、部材の登録(`EdoAssets.cs`)に添える表。⛔ 邸ビルダーに書かない(規則21)
2. **当たりが全部着くように解く**。「最初に当たる一点を 0 にする」ではなく、**全ての当たりの隙がそれぞれ許容に入る**
   位置・向き・合わせの量を求める(CAD の Mate と同じ)。解けなければ ⛔(過拘束)で刷り、その場所へは建てない。
3. **測るのは決めた当たりだけ、全部**。当たりごとに隙の最悪と場所を刷る(1 点の代表値で済ませない)。
   合格線は §4 の表(地面 ±0.01m・部材どうし 1mm 未満)。⛔ 当たりでない所の「浮き」は数えない。
   ⭐ **部材どうしのめり込みは欠陥として数えない**(2026-09-27 施主 ── 埋めて隠すのが基本の作法なので、「埋め込み 0」の決まりは廃止)。
   直すのは**見た目に違和感が出るとき**(突き抜けて見える・向こうの面が覗く)だけ。
4. **繋がりを記録する**。置いた後に「どの駒のどの当たりが、何のどの当たりに着いたか」を残す(Socket の占有の記録)。
   検査はこの記録を読んで当たりを測る ── 測る所を検査が自分で探さない。
5. **新しい型は試してから使う**(kit の検め): 平ら・斜面・相手が凸凹(野面・目地)の 3 つで置いて、当たりが全部着くか見る。

**§3 の `Contact`(最初に当たる点を探す)の位置づけ**: 当たりを持たない在庫の部材(樹木・下草・景石など自由に置く物)の
据えにだけ使う。当たりを持つ型では置き方の主役にしない。

⚠ **実装は未了**(2026-09-27 時点で、当たりを持つ型はまだ無い)。移し替えは掲示板の票で行う。それまで §4 の検査値は
「最初に当たった点」の値であって、上の意味の「当たりが全部着いている」の証ではない(規則19 の未検査と同じ扱い)。

## 1. なぜ文章の規則では効かなかったか

「接するところを測って建てる」は 8/29・9/6・9/13・9/19 と**四度文章に書いて四度漏れた**(`docs/lessons.md`)。
文章の規則は読む人が当てはめない限り効かない。効くのは**共通の層の関数**だけ。だから:

- 置く・測る・突き付ける・据えるは **`EdoBuild` の関数だけ**で行う(CLAUDE.md 規則21)
- 邸や街区ごとのビルダーに置き方を書かない。ビルダーは「どの類型が何をどこへ」だけを持つ
- ⛔ 指摘を受けた箇所だけ直す「局所修正」を禁じる。直しは `EdoBuild` へ入れ、
  報告に「この型は他のどの部材・どの邸に当たるか」を一行添える

## 2. 置き方の4手

```
1. 固定側を先に置く(門構え=門・番所、隅部材、櫓)
2. 可動側は、前の相手と**触れる所**まで寄せる — 番所→袖塀→表長屋→練塀 の連鎖。
   相手に取るのは「名指しした面」ではなく**相手の駒そのもの**。
   長さの固定された部材(長屋)は平行移動だけ。端数は鎖の末端の**伸縮側(練塀)**へ流す
3. 高さは**触れている箇所**を測って据える。⛔ 指図の y を座標として使わない
4. 事後に寄せる関数を持たない(`CloseKadoSeams` / `AlignGateFace` 型)。
   寄せる関数があるほど置き方の欠陥が隠れる
```

⚠ 順が逆になっていないか毎回問う — 塀を先に建てて切れ目へ門を挿すと、部材の実幅との差が
そのまま左右の隙になる(2026-09-19 三べ坂で門が 2.16m 引っ込んだ)。**門構えを先に据え、
その実測から塀の開口を採る。**

⚠ 横へ寄せると足元の地形が変わり、据え直すと当たりが少し開く(実測 0.062m)。
「寄せる → 据える」を**収まるまで**回してから実測を刷る ── **`EdoBuild.Converge`(取り合い `EdoBuild.Tori` の並び)/
近道 `EdoBuild.AbutAndSeat`**(`Assets/Edo/Scripts/Editor/EdoBuildOsameru.cs`・2026-09-26・EDO-0454)。返り値 `Osamari` の
`Ok`・`Reason`・`Summary()`(取り合いごとの前後・最悪値)をそのまま log へ刷る。⛔ `for (pass < 2)` の決め打ちで回さない
── 斜面 39 件の実測で決め打ち2巡は 2 件が帯の外に残った(最悪 0.256m)、`Converge` は 0 件(最悪 0.006m・多くて 5 巡)。

### 寸法の違う駒を一本の走りに並べるとき — **掛け直しの段は大きい順にしか効かない**

走りへ駒を継ぐビルダー(裏長屋の `UraNagayaRun`、表店の `MachiyaRun` など)は、座ごとに
「この座に据わるか」を検めて、退けたら**一段短い駒へ掛け直す**。このとき順は**必ず大きい駒から**。

理由は幾何: 同じ座では**広い駒は狭い駒の走りを覆う**。だから狭い駒が区画の外へ出る/先の駒と
当たるなら、広い駒も必ず同じ理由で退けられる。⇒ 掛け直しが意味を持つのは**広い→狭い**の向きだけで、
狭い駒から始めると段が下に無く、退けがそのまま歯抜けになる。しかも駒が小さいほど座の数が増え、
退けの機会そのものが増える。

⛔ **「いちばん埋まる組合せ」を座の第一候補にしない。** 動的計画法(`EdoBuild.TileWidths`)は
走りを最も埋める組合せを返すが、埋まる組合せは**小さい駒を好む** — これをそのまま第一候補に
据えると上の理屈で悪化する。実測(EDO-0362・machiya 10区画):

| 桁行の候補と順 | 歯抜け | 棟 | 退け |
|---|---|---|---|
| 12/9/6 の3種・大きい順 | 211.9m | 75 | 135 |
| +4.5/3 の5種・**組合せを第一候補**に | 171.1m | 192 | 101 |
| +4.5/3 の5種・**大きい順**(採用) | **168.9m** | 88 | 229 |

⭕ 正しい掛け方は **走りの本体は大きい駒から順に取り、組合せを引くのは列末の端数だけ**
(残りが一番大きい駒に足りなくなってから)。こうすると幾何の掛け直しの段を残したまま、
端数に 1 戸ぶんの半端を残さずに済む。

⚠ 駒の寸法を増やすこと自体は効く(211.9 → 168.9m・−20%)が、**順を間違えるとその効きを食う**。

## 3. 触れている箇所を測る — 相手ごとの道具

⭐ **ここに無い関数を探すときは C# を読み歩かず、目録 `docs/edobuild-mokuroku.md` を引く**(`EdoBuild` の公開関数の
全部・返す物・硬い/柔らかいの札・呼んでいる邸と Stage。C# の注釈から `Tools/Unity/edobuild_mokuroku.py` が刷る。
同じ道具が邸ビルダーのメニュー → Stage `docs/builder-mokuroku.md` と部材の名 `docs/edoassets-mokuroku.md` も刷る)。
目録は「在る関数」の索引で、どれを選ぶかの作法はこの節が正典。

| 相手 | 関数 | 返る物 |
|---|---|---|
| **地面** | `EdoBuild.Contact(駒)` → `SeatOnGround(駒, 沈める量)` | 隙(正=浮き/負=埋没)・その座標・同じ高さで着く頂点の数 |
| **別の駒** | `EdoBuild.Contact(駒, 相手, 向き)` → `Abut(駒, 相手, 向き, 隙)` | 隙(負=めり込み)・その座標・**当たりの筋数** |
| **石垣の天端** | `EdoBuild.CrestY` / `SeatOnCrest` | 天端の高さ |
| **造成した段の面** | `EdoBuild.PadY`(格子点の中央値)/ `GroundGrid` | 面の高さ |
| 丈に比例して埋める(景石の1/3埋め) | `EdoBuild.SeatBuried` | 埋めた量 |
| **天端を地表と同じ高さに据えた駒の下の地形**(土留め・石段の袖) | `EdoBuild.TuckUnderCrest` | 下げた節点・消した芝・面の重なりの点数・外の地表の下がり・埋没の点数 |

**帯で測るか、実メッシュ全体で測るか — 相手の部材の作りで選ぶ。**
`EdoBuild.FaceOut` / `EdoBuild.ModuleMeasure` は、駒の底から**一定の高さの帯**に入る実メッシュの
**頂点**だけを拾って面を測る。壁のように面じゅうに頂点がある駒はこれでよい(腰石・笠木・軒を帯の外へ
外せるのが利点)。だが**柱で立つ駒は頂点が柱の上下の端にしか無く、帯に頂点が1つも入らない** —
2026-09-21 実測(EDO-0326)、鳥居(`EdoAssets.Own.Torii`・実寸 2.000 × 2.320 × 0.300)は
`ModuleMeasure` の帯が空で `ModuleMeasure: 帯に頂点が無い` の例外になった。**山門・鐘楼・塔・冠木門など、
柱で立つ部材すべてに同じ穴がある。**柱物は `EdoBuild.BodyOut(駒, 点, 向き)`
(`Assets/Edo/Scripts/Editor/EdoBuildInari.cs`)で測る — 屋根を外した実メッシュの**全頂点**の、その向きへの
最大の張り出し(= 実面)で、帯で切らない。
⭐ **柱物の平面の形は「断面」で採る**(2026-09-23・EDO-0398)。`EdoBuild.SectionAt(部材, 座, 向き, 高さ)` は
**三角形と水平面の交わり**を返すので、頂点の無い高さでも柱の実形が出る。帯の頂点で代用すると、拾えるのは
貫と**礎石の天端**だけ ── 礎石は柱より 0.105m 大きく、そこへ塀の端を寄せると柱との間に 0.085m の隙が残った
(山王の勝手口。`EdoBuild.OpeningJambs` が囲いの丈を 5 段に割って、**いちばん内へ引っ込む段**へ端を取る)。
⛔ **帯が空でも黙って NaN を既定値で埋めない。**`FaceOut` は NaN、`ModuleMeasure` は例外を返す —
どちらも「測れなかった」であって「0」ではない。既定値で埋めると、柱物が丸ごと基準点置きに戻る。

駒どうしの `Contact` は、向きに直交する面を筋(既定 0.25m 角)に割り、**両方の駒がいる筋だけ**で
「こちらの前面 − 相手の背面」を取り、その最小を触れている箇所とする。だから
**名指しした面の外(庇の裏・基壇の縁・留め継ぎの先端)で当たっていても捕まる**。

**向きは「測る駒 → 相手」。外形の中心どうしで取る。**(2026-09-22・EDO-0318 ⑥ の実測)
⛔ **駒の基準点から基準点へ引かない** — 規則21「基準点で決めない」は**位置だけでなく向きにも効く**。
基準点は部材ごとに端・角・中心とばらばらなので、長い駒ほど嘘が大きい(御殿複合 80m 超で **−11.9m**
の嘘のめり込み)。`EdoTypologyBuilder.PairDir` が外形の中心どうしで向ける。
⛔ **前後を入れ違えると相手の背面まで測る** — 渡廊下の手前の核と奥の核で ±v を逆に書き、**−26.8m** が出た。
⛔ **長い複合を一つの駒として他の駒と測らない** — 外形の中心が端へ寄り、向きが複合の軸に沿う。
**棟ごとに**測り、複合の内側(軒がかぶるのが設計の所)は除いて、内側の取り合いは組んだ側が刷る。
⛔ **「屋根を外して測る」は屋根の名の篩に頼っている。**キットごとに屋根の名が違うので、篩に無い名
(`Goten_Roof_*`)は黙って屋根込みで測られる(**−1.1m**)。篩を広げると他邸の駒が動くので、
組んだ複合の中だけで屋根の名を付け替える(`NameRoofs`)。
⛔ **`Contact` の間引きは一様でも局所Y順でもいけない。**頂点の多い駒(樹木)は、地面に先に着く点が
**根元(局所Yの最小)とは限らない** — 斜面へ垂れた枝が根元より先に着くことがある(2026-09-22 実測:
局所Yで下から 437/8432 番目の、根元でも樹冠でもない中腹の頂点が実際の接地点だった。根元だけ拾う間引きは
+1.05m の偽陽性「浮き」を出した)。**局所 XZ を粗い格子へ割り、格子ごとに局所Yが最小の頂点だけ残す**
(`EdoBuild.GroundCandidates`/`LowestPerCell`・部材どうしの Contact が使う「0.25m角の筋」と同じ考え方) —
同じ(x,z)付近では地面の高さはほぼ一定なので、格子内でそれより高い頂点は地面までの隙が必ず大きく、
捨ててよい(EDO-0357)。屋敷林の**+0.97m の浮き**が全頂点では **−0.29m** だった旧例も、この格子拾いで
根本修正済み。⛔ になりかけた駒だけ間引かずに測り直す旧来のセーフティネット(60,000点)はそのまま残す。
⛔ **群(親)の `Contact` を「群ぜんたいが接地している」と読まない。**返るのは**子の最小**なので、
一続きの複合では**塚に載った 1 棟の 0.00m** が群の値になり、他の 6 棟が 2.1m 浮いていても ⭕ に見える
(2026-09-22 戸田ほか3筆・**数値の関門は全部通っていて、検証レンダで初めて崩れた**)。
一続きの駒は**棟ごとに測り、浮きと埋没の大きい方**を代表にする。⭐ 据える側の許容は、**検査の閾値と同じ数**にする。

⛔ **天端を地面と同じ高さに据えた駒は、地形の節点が天端と重なる**(2026-09-23・EDO-0414)── 天端の面と地形の面が
同じ高さで斑に描かれ、芝が天端を突き抜ける。据えた後に `EdoBuild.TuckUnderCrest` で、**実メッシュの天端の外形の中**の
節点を天端 −0.15m へ下げ、芝を消す。⛔ **元の高さが天端 +0.05m を超える節点(= 駒が埋まっている)は触らない**
(条件なしで下げたら 3.29m 掘って外の地表が 3.06m 凹んだ)。⛔ 下げる条件を**今の高さ**で見ない(下げた隣がまた
重なりと判定され、斜面を連鎖して 0.75m 掘った)。検めは「面の重なり」(その点と前後左右 0.1m がみな差 1cm 未満)で数える
── 天端の面取りや斜めの地表が横切る**線**は数えない。整地を流し直すと節点が戻るので、土留めを据える段で毎回呼ぶ。

⛔ 触れる所は「底」とも「名指しした面」とも限らない — 斜面では上手側の頂点が先に着き、据え面のある石は
その縁、木は根張りの端、板塀の柱は柱の足元が着く。**複数の所で同時に触れる**こともある(石の三点・柱の並び)。
⛔ `bounds.min.y` を「触れている箇所」と呼ばない。⛔ 「面どうしを合わせた」を「納まった」と読まない。

## 4. 許容0の数え方

| 測る物 | 何で数えるか |
|---|---|
| 区域侵犯 | **壁体**の頂点だけ(屋根・軒・垂木を外す)。**軒の張り出しは許容**し、別の列に必ず刷る(2026-09-21 施主裁定A) |
| 埋没・浮き | **触れている箇所**の隙(接地の一点)。あわせて**足元の地形の起伏**を刷る — 接地が 0 でも剛体の反対側は起伏ぶん浮く。**地面に置く物の接地は 0 が基本・浮き +0.01m から埋まり −0.01m までを許容**(2026-09-27 施主指示。⛔ 地面との間だけの許容 ── 塀と塀・建物と建物・部材どうしのずれや隙は許容しない=0。旧の目安「浮 ≤0.7」は 2026-08-18 に斜面の建物の箱で置いた根拠の無い値で廃止)。石の天端・地面へ削り合わせ(光付け)て据える木の下端(板塀の地覆・柱 ── `EdoBuild.ScribeToBed`)も同じ ±0.01m を**当たり(石の上面・見えている地表)だけ**で測る ── 目地は跨ぎで測らない(§0a。旧の ±0.02m の例外は目地の上を測った値が根拠だったので 2026-09-27 に廃止)。⚠ 床の高い建物の縁の下は浮きではない — 触れている箇所(柱・礎石・基壇)で測る |
| めり込み | ⭐ **部材どうしのめり込みは欠陥に数えない**(2026-09-27 施主 ── 埋めて隠すのが基本の作法・§0a)。直すのは**見た目に違和感が出るとき**(突き抜けて見える・向こうの面が覗く)だけで、見るのはレンダ。最悪値は見張りとして刷ってよいが ✗ にしない。測るなら駒どうしの**触れている箇所**で(外接箱の隙は回った棟で 0.00m に見える) |
| 隙 | 目の高さの実面。閉じは「隙間 > めり込み」で、0 を狙い外すならめり込む側へ |

**「0」の線(2026-09-27 施主指示)**: 部材どうし(塀と塀・建物と建物・駒と駒)の**隙は 0.001m(1mm)未満**を 0 とする(めり込みは数えない ── 上の表)。値は mm まで刷る。地面に置く物の接地だけは ±0.01m まで許容(上の表)。図と実装の位置の突き合わせ(0.02m・向き 0.5°)はこの線と別。各検査の線(目地とみなす 0.01・透塀の継ぎ目の口 0.01・類型の塀の下 0.05 など)はこの線へそろえる。

⛔ 0 件を合格と読まない — 緩い条件で 0 が出ていないか、**最悪値を必ず一緒に刷る**(CLAUDE.md 規則19)。

⚠ **測り方そのものを疑う。**2026-09-21、区画の縁に載っている塀が「外へ 10.28m」と出た。駒は正しく載っていて、
壊れていたのは距離の関数だった(§5)。**桁が合わない値が出たら、まず測り手を検める** — 直す前に、
その値が幾何として在り得るかを問う。

⚠ **自分の辺に収まっていることは、区画に収まっていることではない。**奥行のある駒は角で隣の辺を跨ぐ。
収まりは**区画の多角形**に対して測る(辺に対してではなく)。

## 4a. 硬い制約と柔らかい制約 — 退けるのは許容0だけ(2026-09-23 施主指示・EDO-0372)

置き場を選ぶ条件は二種に分け、**どちらかを必ず名乗る**。混ぜると、狙いが関門になって検査違反と建て直しが繰り返される。

| | 硬い制約(Hard) | 柔らかい制約(Soft) |
|---|---|---|
| 何か | 許容0(§4 の表の物だけ)— 区域侵犯・埋没/浮き・隙・接地が測れない | 狙い — 前庭の奥行・白洲の広さ・棟どうしの離れの目安など、良くしたいが欠陥ではない物 |
| 破る置き場 | **退ける**。どこでも破るなら**建てない**(⛔ で刷る) | 満たす置き場を探し、無ければ**試した中で最も近い所へ建てる**(⚠ で刷る) |
| 検査での数え方 | ⭕ / ✗(不合格) | ⭕ / △ **狙い未達**(不合格に数えない・建て直しを回さない) |
| 値を変えたいとき | 施主の裁定 | **表の欄の上書き**(例: 類型表 `maeniwa_ken`)。コードを直さない |

- 実装は **`EdoBuild.PlaceBest`**(`EdoBuildSeiyaku.cs`)ひとつ。`Hard(名, ok)` と `Soft(名, 狙い, 測り)` を渡し、
  勘定は `SeiyakuTally.Summary()` をそのまま log へ刷る。
- ⛔ 邸ビルダーに `if (測った値 < 狙い) 退ける` を書かない — それは柔らかい制約を関門に化けさせる書き方。
- ⛔ 硬い制約を「最も近い所」で妥協しない — 許容0 の物は狙いへ落とせない(規則4)。
- 新しい条件を足すとき、どちらか判らなければ「破ったまま建っていたら、施主は欠陥と呼ぶか」で分ける。呼ぶなら硬い。

## 6. コードで起こした物は、必ず資産にする(材質・メッシュ)

`new Material(...)` も `new Mesh()` も**資産ではない**。シーンには埋め込まれるので見た目は正しく、
**プレハブへ焼いた瞬間に資産側が null になる**。シーンでは override が効くので気づけず、
そのプレハブを**別の場所へ置いた途端に**壊れる — 材質ならマゼンタ、メッシュならその部材だけ消える。

| 起こす物 | ⛔ これを書かない | ⭕ これを呼ぶ | 置き場 |
|---|---|---|---|
| 無地の材質 | `new Material(Shader.Find("Universal Render Pipeline/Lit"))` | `EdoSolidMat.Get(色, 光沢)` | `Assets/Edo/Materials/Solid/`(色ごとに1枚) |
| メッシュ | `mf.sharedMesh = new Mesh()` | `EdoSolidMesh.Save(mesh, 名)` | `Assets/Edo/Meshes/Gen/`(中身の指紋ごとに1枚) |

**見張り**: `Edo/屋敷/切り出し状況を検査` の「材質:」「メッシュ:」の 2 行が 0 なら直っている。
0 でないルートは**材質も焼けない** — `EdoYashikiPrefab.BakeAssetSwaps` が
「資産でない物を指したまま」のインスタンスを断るため(断らなければ資産側を null で塗り潰す)。
**直し**: `Edo/屋敷/埋め込みメッシュを資産へ(全ルート)` → `Edo/屋敷/埋め込み材質を資産へ(全ルート)`。

## 8. 取り合いは部材の札で決める(2026-09-29 施主「ベストプラクティスに基づいた開発に」・EDO-0491)

**部材の取り合い(足元・正面・袖の脇の面・通り口)は、部材ごとに一度だけ定めた札(JSON)に持たせ、組み立ては読むだけ。**
Unity の定石(ソケット/接続点)に倣う。⛔ 組み立ての最中に生メッシュを帯・材の名・外接箱で推し量らない。
⛔ 推し量りの物差しを足して直さない(1本足すたびに段どうしが食い違う)。

**由来**: 十坊の表門の脇で柱と板塀の間に 1.9m の隙。門構えの位置を段ごとに別の物差しで測っていた。

| 段 | 物差し |
|---|---|
| 横と口 | 帯 0.3〜0.6H の頂点 |
| 区画の線 | 材の名で屋根を落とした全部。薬医門は軒の垂木・桁が柱と同じ `wood` で、軒の出を壁体と数えて 2.08m 下げた |
| 参道 | 扉の空き |
| 寺社の奥行 | `Body(monT)` |
| 建蔽率 | `FootprintXZ` |

さらに塀の口は門が動く前に決まり、下げた門を塀が追わなかった。

- **札**: `Assets/Edo/Data/PartSpecs/<資産名>.json`(型は `EdoPartSpec.Spec`)。資産の版ごとに一枚(`_Open`・幅違いも別)。
  - 座標: 資産の局所・倍率の前(+X = 門口・走り / +Z = 外 / 原点 = ピボット)。`unitScale` を札に持つ。
  - 門・番所: `foot`(地面に立つ所)・`front`/`back`・`jambL`/`jambR`(帯の中でいちばん内へ引っ込む段)・`passage`・`eave`(刷るだけ)。
  - 塀の駒: `faceOut`/`faceIn`・`copingOverhang`(笠木・軒の走り方向の出)。
- **作り方は二通り・中身は同じ形**:
  1. 自前(Blender): 作図の値から `vklib.write_spec` が書く。`export_fbx(..., kind="gate")` は札が無ければ止まる。
  2. 在庫: `Edo/部材/取り合いの札を焼く` が資産の断面(`EdoPartSpec.Measure`)で一度だけ測り、検め画像を撮る。画像を見て確かめてからコミットする。
- **置き方**: `EdoBuild.PlaceGamae` が門構えを札から一度で解く。据え(高さ)だけは地形を実測する。
  - 横: 通り口の芯を辺の中央へ。
  - 奥行: 正面を塀の外の面へ(柔らかい)。
  - 番所: 脇の面を門の脇の面へ当てる。
  - 区画の線: `foot` で判定し、出たら内へ下げる(硬い・許容0)。軒は越えてよい(裁定A)。
  - 口: 両端の脇の面から、端の駒の笠木の出 + 埋め 0.15m(§0a・板塀の駒は厚み 0 の一枚板なので一定)を引いた所。塀の走りは外形の端(笠木込み)を口の縁に着けるので、笠木の出を足さないと壁の本体が手前で止まる。
- **門構えの足元(2026-09-30 施主「門が浮いてます」・EDO-0491)** ── 硬い ±0.01m:
  - 当たりの部材: 札の `contact`(メッシュ名)。空なら下端から 0.05m の部材の全部。扉(下に隙があって正)と根入れの飾りを外すときだけ書く(在庫の冠木門は `["kagami"]`: 柱が足元の飾りより 2cm 高い)。読み口は `EdoBuild.GamaeContact` / `GamaeBottom`。
  - 据え: `EdoBuild.SeatGamae` ── 最下点で当てた後、当たりの部材の足跡を検査と同じ 0.1m 刻みで引き、最も深い所を地面へ上げる(頂点だけで当てると頂点の間の地面の盛り上がりで埋まる)。
  - 平場: `GradePads(..., mon: MonPad)` ── 門構えの平場は区画の線の上の区間の地盤の中央値。縁の帯・縁の法を外し、他の棟と束ねない。置き場は `FlattestStation`(道の差が 1.0m を超えるときだけ、端から 3m 空けて平らな所へ寄せる・柔らかい ⚠)。
  - 下手の浮き: 道は造成しないので、`EdoBuild.GamaeKidan` が段塀と同じ布石(`Dobei2m_Nunoishi`)を基壇に敷く。天端の平らな面 = 当たりの下端・下端 = 地面の最低 − 0.05m。区画どうしは天端を 0.02m 重ね、表の天端は `foot` の表を 0.01m 越す(表のふくらみを足しても 0.04m ── `KIDAN_BULGE` の内)。浮きが 0.005m を超える区画にだけ敷く(検査の 0.01 より細かく・標本の粗さの分)。
  - 床: 門構えの駒の床は**地面 + その駒の布石だけ**(`EdoBuild.GroundOrBed`)。脇の塀の布石・隣の駒(番所)の布石との重なりは部材どうしなので数えない(§4)。受けの縁と目地の溝は 5cm 跨ぐ(`BedIndex.AtNear` ── 塀の `GroundBedSpan` と同じ)。
  - 当たる先: 類型ビルダーの門構えの全部(門 8 種・番所)。検査は `Inspect` が埋没・浮き・区域侵犯の最悪の駒名を刷る。
- **一つの値に二つの意味を持たせない**: `passageC`(通り口の芯 = 参道・庭・本堂の軸)と `gapC/gapHalf`(塀の口)は別。番所が片方だけの門構えで二つはずれる。
- **関門(硬い)**:
  - EditMode 試験 `EdoPartSpecTests`: 札の揃い・類型ビルダーの部材との一致・実メッシュとの食い違い 0.02m 以内(`EdoPartSpec.Verify`)。
  - `typology_check.py`: 門の語に札があるか(語 → 札の表は `gate_kinds.json` の一枚)。
  - 類型ビルダー: 札の無い門構えは推し量りで置かずに退ける。
  - Stage 6 の列「門構えと塀の取り合い」: 実メッシュの水平断面で隙 ≤ 0.01m。測れないのも ⛔。
- **新しい部材を作る・採るとき**:
  - 部材方の納品物は FBX + 札 + 札の線を重ねた検め画像。
  - 在庫方の候補には札の有無を載せる。
  - 札の無い置き物は登録しても建たない。
- **広げ方(次の票)**: 棟・他の邸ビルダーの取り合いも札へ移す。材の名で屋根を見分けている `OutsideBy` の棟の列(一枚メッシュの庫裏など)が次の候補。
