# 掲示板(board) — セッション横断の報告・裁定・情報共有の作法

`edo_session.py`(claim)は**衝突を防ぐだけ**で、進捗・課題・裁定待ちは誰にも見えず、
横断影響の伝達をユーザーが人力でやっていた。それを解くのがこの体制。

- **掲示板** = `.git/edo-board/` の issue 登録簿(git 管理外・全 worktree 共有)。
  CLI は `Tools/Session/edo_board.py`。
- **セッション間の伝達は当事者が直接行う**(巡回する差配役は置いていない。経緯は `docs/lessons.md`)。

## 作業セッションの義務(これだけ守る)

### 1. post する契機は5つだけ

細かい報告は書かない。**コミットが報告を兼ねる**。
board に書くのは「コミットに現れない状態」だけ:

| 契機 | type | 例 |
|---|---|---|
| **節目** — 関門通過・レビュー待ち到達・実装ステージ完了 | `info` | 「検図3巡通過、レビュー待ち」 |
| **ブロッカー** — 資源待ち・史料待ち・他邸依存 | `blocker` | 「門戸部の間数は都立中央図書館の館内閲覧待ち」 |
| **ユーザー裁定が要る** | `decision` | 下記テンプレ必須 |
| **手仕舞い** — 手を止めるときに畳めなかった残タスク・他邸への依頼 | `task` | 「`sashizu/sanno` に未マージの是正3巡分」 |
| **範囲外の気付き** — 作業中に見つけた、いま預かった仕事の外の不具合・欠落 | `task` | 「門の壁体が区画を 0.37m はみ出す(別邸の外周でも起きる)」 |

⛔ **手仕舞いを飛ばさない。** ユーザーへの報告は会話に流れて消えるので引き継ぎにならない
(2026-09-06、山王を止めた際に未マージのブランチを報告文にだけ書いて起票せず、指摘された)。
→ 判定と書き方は **[fushin-bugyo.md](fushin-bugyo.md)**「手仕舞い」。

⛔ **範囲外の気付きを、その通の裁定・質問に足さない。**(2026-09-22 施主指示)判別は「答えが無くても
いま預かった仕事は仕舞えるか」— 仕舞えるなら `task` へ起票し、施主への通には【報告】の中に一行だけ
(題 + `edo_board.py show EDO-xxxx`)。→ 正典 **[reporting-protocol.md](reporting-protocol.md)** 規則12

```bash
# worktree からは絶対パスで(自ブランチにはまだ CLI が無いことがある。board 実体は共有)
python3 /Users/toshio/project/edo-unity/Tools/Session/edo_board.py \
  post --estate doi --type blocker --title "…" --ref "docs/Sashizu/doi_sashizu.json#_pending.monsun"
```

⛔ **正典を写さない。** 未決の中身は各邸 `_pending` が正典のまま。issue は `--ref` で指す。

### 1b. 種別の意味は機械で守る(2026-09-13・計画 D-1/D-2)

実測(2026-09-13): 生存 142 件のうち教訓 34・完了報告 39・「疑い」を blocker と称する 12 件など 7 割が
「誰も次に何もしない」件で、close は手動のみ(直近 14 日 起票 125 / close 27)。

| type | 意味 | 機械の検査 |
|---|---|---|
| `info` | 記録(節目・ユーザー裁定の写し) | **起票と同時に done**。open 一覧と digest には出ない(`list --all`) |
| `lesson` | 教訓・一般則 | `docs/lessons.md` へ 1 行追記して即 done。板は索引、文書が正典 |
| `blocker` | **誰かが止まっている** | `--blocked <誰が>` `--until <何で解けるか>` が無ければ受けない。「見つけた事実・疑い」は task か lesson |
| `task` | 宿題・手仕舞い | owner は **1 邸だけ**(相乗りは邸ごとに分ける)。cross は `--owner` 必須 |
| `decision` | 裁定要請 | 6 点セット(従来どおり) |

出口: コミット本文に `EDO-xxxx` を書くと note が付き、`closes EDO-xxxx` で done になる(post-commit)。
`release` の前に自邸の open task を見る。題の訂正は `retitle <ID> "<題>"`。直前と同文の note(類似度 0.8 超)は
`--force` 無しには受けない。題 80 字・本文 800 字まで。digest は **15 行**(裁定待ち全件 → 本物の blocker ≤5 →
自邸の宿題 ≤5 → 横断の宿題 ≤3 → 齢の警告)。

### 2. decision はテンプレ強制(ユーザーが判断できる形でしか裁定を仰げない)

```bash
python3 Tools/Session/edo_board.py post --estate sanno --type decision \
  --title "回廊の基壇の受け方" \
  --background "背景を2文以内で。専門用語の羅列にしない" \
  --options "A: 深い石垣で受ける(造成小)" "B: 平場を北へ補う(造成大)" \
  --recommend "A。理由を1文" \
  --impact "採ったときの影響。他邸への波及があれば必ず書く"
```

テンプレが埋まらないなら、
それは**まだ裁定を仰ぐ段階ではない**(選択肢を整理してから来る)。

⛔ **一件一葉 — 1件に複数の裁定を詰めない。**独立に答えられる事柄は別の issue に分ける。
詰めると片方だけ裁定が下りたときに `status` を動かせず、巡回のたびに「未裁定が残っている」
ようにしか見えない(**実例 EDO-0057** — 其の一=隅部材 / 其の二=門の切り欠きで起票し、
両方に裁定が下りた後さらに「天端の段」が湧いて3つ積み上がった)。
`post` が**機械で弾く**: 選択肢の A/B/C 記号・詰め込み(其の一/其の二・丸数字・表題の「+」)。
→ 正典 **[reporting-protocol.md](reporting-protocol.md)** 規則6・規則8

### 3. 三巡則 — 自己検図・自己考証は**ユーザー入力なしに3巡まで** <!-- obl:three-rounds canon -->

3巡目を終えてなお指摘が出続けるなら、**4巡目に入らない**。`decision` か `blocker` を
post して手を止める(前例: 裁定なしに検図10→14巡が無停止で回った。巡数を重ねるほど
自作の関門に最適化していき、本質から離れる)。**2026-09-13 から機構で守る**: `review_gate.py --rounds`
(門番が検分役の呼び出し前に打つ)と `--record` の拒否。reset はユーザーの発話か `--ack`。
`/kenzu` の Workflow `sashizu-review` は 3 巡でコードが止まる。

**【移行期間・2026-09-01 裁定B】**検分の記録が無い邸は、検分を通すまで作業を続けてよい。
ただし**ユーザーへ見せる前には必ず通す**(遡って pass を書かない)。→ CLAUDE.md 規則18

### 4. 他邸に効く発見・変更は「起票+直接メッセージ」の両方

共有境界・parcels.json・base_dem.json・地形・基準面など、**他邸に影響すること**を
発見/変更したら:

1. **board に起票**(`--estate cross`)— これが記録。相手セッションが不在でも、
   次に立ち上がるセッションが greet の digest で拾える。
2. **影響先セッションへ直接メッセージ** — `ListAgents` で相手を探し(`edo_session.py status`
   の claim の `sashizu:<邸>` や cwd と突き合わせて同定)、`SendMessage` で送る。
   ⚠ **claim の短縮ID(例 `2927b194-c95`)と `ListAgents` の名前(例「松江松平邸セッション」)は
   別物で、突き合わせる自動の手段が無い。**「直前にやり取りしていた相手 = 資源を持っている相手」
   と思い込むと誤送信する(2026-08-31、資源の保持者への依頼を無関係のセッションへ送った実例)。
   資源(unity 等)の保持者へ連絡するときは、`status` の note や `sashizu:` に出る**屋敷名**を
   手がかりに、`ListAgents` の一覧からその屋敷を担当するセッション名を選ぶこと。

⛔ **メッセージは揮発、board が記録。** メッセージには必ず issue ID(EDO-xxxx)を添える。
board に無い伝達は「無かったこと」になる。
メッセージは短く: 「EDO-0012: 松平S辺の据え付け面を+0.4m動かした。土井の共有辺検査を
流し直してほしい」程度。長い経緯は issue の note へ。

### 5. 指図の Artifact を再公開するときは URL を渡す

⛔ **`url=` を渡さずに publish すると、更新ではなく新しい Artifact が生える。**
README がリンクしている方は古いまま取り残され、ユーザーには「デグレした」ように見える
(2026-08-26 に山王で実際に起きた — 正典は正常なのに、公開版が4日前の女坂=直線のままだった)。

```bash
# 指図を再公開するときは必ず docs/Sashizu/README.md の Artifact 列の URL を渡す
Artifact(file_path="docs/Sashizu/<屋敷>_sashizu.html",
         url="<README の Artifact 列の URL>")
```

指図を直したら**その場で再公開する**。直して公開しないと、ユーザーが見る図と正典がずれる。

### 6. セッション開始時

greet フックが board の digest を自動表示する — **裁定待ち → 本物のブロッカー → 自邸宛の宿題(全件)
→ 横断の宿題3件 → 齢の1行**。⛔ 宿題は前任の手仕舞い(§1)なので必ず拾う。
全部見るなら `edo_board.py list --type task`。

⭐ **自邸宛を 5 件で切るのをやめた(2026-09-21 施主裁定 EDO-0297=A)。** それまで窓は最大 9 件で、
板は 69 件あった。**6 件目から先はどのセッションの目にも二度と触れず**、生きている 69 件のうち
44 件(64%)が起票以来ひとことも付いていなかった。溢れを止めるのは時効(§7)の役目であって、
窓を狭めることではない。
`edo_session.py start <屋敷>` もその邸+横断の open issue を出す。
**自分宛(owner=自邸)と cross の issue を読んでから作業に入る。**

### 7. 齢 — 古び14日・時効30日(2026-09-21 施主裁定 EDO-0297=A)

挨拶フックが毎回 `edo_board.py age --apply --quiet` を打つ。

| 齢(最後に何か書かれてから) | 何が起きるか |
|---|---|
| 14 日 | **古び**の印(⌛)が付く。digest に件数が出る |
| 30 日 | **時効** — 自動で畳む(`dropped`)。`list --all` には残る |

⛔ **畳むのは `task` と `blocker` だけ。**施主の返事待ち(`decision` / `awaiting-user`)は齢で畳まない。
⭕ **戻すのは一言**: `edo_board.py reopen <ID> --owner <邸>`(古び・時効が解け、その邸の宿題になる)。
⛔ 古びの印を付けるとき `updated` を動かさない(動かすと齢が 0 に戻り、時効が永久に来ない)。

**朝ひと画面** — 毎朝の日誌(`/nikki` 手順5)が
`python3 Tools/Session/board_triage.py --stuck` を焼き、**詰まっている件だけ**(古び・時効で畳んだ物・
宛先の無い宿題)の表を施主に出す。施主は処置の列に一語 — `hikitoru:<邸>` / `tatamu` / `sueoki` — 書くだけで、
`--apply` が一括で効かせる。⛔ 全件の表を出さない。読まれない画面は無いのと同じ。

## ダッシュボード

`python3 Tools/Session/build_board_html.py` が `.git/edo-board/_pm/` に二つ焼く —
**表紙 `index.html`(529 バイト・二度と変わらない)** と **中身 `dashboard.html`(880KB)**。
見たいときに誰でも流してよく、公開は同一 URL へ中身だけ差し替える:
https://claude.ai/artifact/3wTRqrXgJBp8LJUwWFZ4KY

⛔ **一枚そのものを頁にしない。**`url=` を渡して頁を上書きするには、その通話が一度その頁を
**読んで**いなければならない。880KB の頁を読むと文脈がそれだけで埋まる — これが
「公開は日に一度」の正体だった(2026-09-21 に判明)。表紙が 529 バイトなら読んでも無害で、
中身は添え物として差し替わる。旧い一枚(`…/artifact/SffWPZCmVFFBGGiUbCR3NS`・
`…/code/artifact/cfda75da-…`)は 2026-09-21 で更新を止めた。
**定期の担い手は毎朝の `/nikki`**(2026-09-20 施主裁定)。上げ方は次の節。
⛔ 焼いただけでは施主に届かない。

### 上げ方 — 楽観ロック(2026-09-22 施主指示)

複数のセッションが手仕舞いのたびに同じ一枚を上げ合う。**焼くとき版を採る → 上げる直前に照合する →
違えば焼き直してから上げる。**板は件の json(`.git/edo-board/EDO-*.json`)から毎回作り直すので、
焼き直した一枚には自分の分も相手の分も入り、取り合いにならない。

1. **焼く** — `python3 Tools/Session/build_board_html.py --stage Temp/edo-board`
   焼いて、版を `_pm/baked.json` に書き、`index.html` と `dashboard.html` を `Temp/edo-board/` へ写す。
   写す先は作業ツリーの中(`.gitignore` 対象)。Artifact は作業ディレクトリの外を受け取らず、
   worktree では `.git` がファイルなので `.git/edo-board/…` は相対でも開けない(ENOTDIR)。
2. **上げる直前に照合** — `python3 Tools/Session/build_board_html.py --check-fresh`。
   0 ならそのまま上げる。1 なら焼いてから板が動いている — 1. へ戻る。
3. **先に読んでから上げる(2026-09-22 是正)** — `Artifact(action="read", url=…)` を必ず1回先に読んでから上げる。
   読まれるのは枠の頁だけ(529バイト・読んでも文脈は埋まらない)。⛔ 板の本体 `board.html` は読まない(大きい)。
   「読まずに上げて断られたら読む」の順だと、**他の巡が先に上げていた場合は読んでいないので毎回断られる**
   (2026-09-22 の朝、同じセッションが2回弾かれた実例)。先に読めば1回で通る。
   ```
   Artifact(file_path="Temp/edo-board/index.html",
            url="https://claude.ai/artifact/3wTRqrXgJBp8LJUwWFZ4KY",
            files={"board.html": "Temp/edo-board/dashboard.html"},
            overwrite_unread=["board.html"])
   ```
   それでも断られたら(読んだ後にさらに別のセッションが上げた): 1. で焼き直して写す → もう一度 read → もう一度上げる。
   ⛔ **上げずに終えない。**
4. **判を押す** — `python3 Tools/Session/build_board_html.py --published <URL>`。判は版も押す。
   ⛔ 焼いただけ・ローカルで焼き直しただけでは押さない。

**なぜ時刻でなく版か。** 版は件の json のファイル名と中身から採る 16 桁の指紋で、同じ版なら中身が同じ。
だから誰が上げた一枚でも「今の板を写している」と言える。時刻で測ると二つ外れる —
(a) 件が消えると「一番新しい更新時刻」は下がり、覆っていると誤って読める。
(b) 別のセッションが先に焼いて後から上げると、判の時刻のほうが新しいのに、その板には
後から起票された件が入っていない。
⚠ claim の心拍と main の HEAD は**わざと版に入れていない**(入れると一枚が永久に古くなる)。
挨拶フックは判の版で古びを判定し、版の無い旧い判だけ時刻へ後退する。

### 届くまでの遅れを詰める二本立て(2026-09-21 施主裁定 EDO-0298=A+B)

焼く担い手が毎朝の日誌だけだったので、板が動いてから施主の目に入るまで**最大 24 時間**空いていた。

| | 誰が | 遅れ | どこから見えるか |
|---|---|---|---|
| **A 手仕舞いごと** | Stop フック `.claude/hooks/edo_board_fresh.py` が**焼き**、公開を促して一度だけ止める | 数分〜1時間 | Artifact(外出先でも) |
| **B 常時の窓** | `Tools/Session/board_window.py`(launchd `jp.edo.board-window`) | 5 分以内 | http://127.0.0.1:8787/ (この Mac だけ) |

⛔ **公開だけは手が要る**(Artifact は人の道具)。フックは焼くところまでしかできないので、
止められたら上の「上げ方」の 2.〜4. を踏む(焼いて写すところまではフックが済ませている)。
⛔ **ローカルの焼き直しで判を押さない** — 判は「施主が見る Artifact が新しい」ことの印で、
ここを混ぜると外向きの遅れが見えなくなる。
⭐ **裁定と詰まりの二種は板に置くだけでは届かない。** その巡のうちに施主へ 6 点セットで出す
(同じ Stop フックが、裁定を立てたのに【裁定】の見出しが無い一通を一度だけ止める)。

常駐の据え方・外し方は `Tools/Session/board_window.plist` の冒頭に書いてある。

## ⛔ 裁定を求めるときは「どこ」を必ず書く

`--type decision` / `blocker` を立てるときは、**相手が図の上で指させる場所**を本文の先頭に置く。
図版番号(其◯)・辺と s・グリッド(u,v)・世界座標・隣接物のうち最低1つ。
名前だけ(「隅の詰め」「袖塀が長くなる」)では裁定できない — 2026-08-29 にユーザーから
「どこのことを指してるのか分からない」と差し戻された実例がある。
**図がまだ無いなら、先に図を出してから起票する。**

## 普請場の一枚(施主が掲示板を見る唯一の窓)

掲示板の実体は `.git/edo-board/` にあり**リポジトリに入らない**。施主がこれを見られるのは
`python3 Tools/Session/build_board_html.py` が焼く一枚だけ。⛔ **焼いた ≠ 届いた** —
Artifact を更新したら判を押す(版も押す)。手順は「ダッシュボード」の「上げ方」— 照合してから上げ、上げたら判。
2026-09-02 に焼いた一枚が 17 日そのままで、施主が掲示板を見失った(2026-09-19)。
判が古いと挨拶フックが 1 行鳴る。

⭐ 一枚には**類型の車線(79区画の読み具合)**も入る(2026-09-19 施主裁定A)。
区画の表は `Tools/Sashizu/build_typology_page.py` の `build()` が正典で、
一枚も `docs/Sashizu/susumekata.html` も同じ関数から焼くので食い違わない。
