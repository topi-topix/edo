## 何が起きていたか

`ModernTerrain` が実世界に対して **東へ 8m・南へ 2m** ずれていた。純粋な平行移動で、縮尺の歪みはゼロ。

**確かめ方**: シーン座標 →(`Edo.Geo.GeoReference` / `JapanPlaneRectIX`。EPSG:6677 の厳密実装で
pyproj と 0.001mm 未満で一致)→ 緯度経度 → 国土地理院の DEM と突き合わせる。
地形の全テクセル(2049²・2.0m間隔)で参照ハイトマップを作り、全解像度で最良の平行移動を探した。

| 象限 | 最良のずれ | 補正後の \|差\| 中央値 |
|---|---|---|
| 南西 | dx **+8m** / dz **−2m** | 0.161 m |
| 南東 | dx **+8m** / dz **−2m** | 0.111 m |
| 北西 | dx **+8m** / dz **−2m** | 0.136 m |
| 北東 | dx **+8m** / dz **−2m** | 0.109 m |

4象限とも完全に同じ値 = 歪み無しの平行移動。原因は特定できていない
(`edo-map/scripts/export_unity_terrain*.py` は等長方形近似を使うが、それらの中心と
実際の地形の中心が 371m/465m 離れており、この地形を作った工程は別物)。

**遠方では旧地形が最大 10m 狂っていた。** 造成の無い場所で海抜 −5.46m(実測 +2.90m)など。
標高API で 5 点照合し、すべて参照が正しいことを確認済み。

### ① 8mズレの補正
ハイトマップの配列を `new[j][i] = cur[j-1][i+4]`(西へ 8m・北へ 2m)。

## いま何をすべきか

### 屋敷を建てるとき
1. **造成ステージを先に流す。** 平場は消えている。区画ポリゴンはビルダーのソースに、
   面の高さは `docs/Sashizu/<屋敷>.json` の `planes` / `terraces` に残っている
2. **指図の面の高さはそのまま使える。** 台地は平らなので 8m 横に動かしても高さが変わらない
   (山王山の山頂で 0.01〜0.03m、岡部の平場で中央値 0.00m)。**動いたのは面の「縁」だけ**
3. **手組みの石垣・長屋・門は再接地が要る。** 石垣 3,926 件のうち、下の地面が 1m 以上動いたものが 41%。
   石垣は「天端を丸い数字で通し、周りの地形を造成して合わせる」作りなので、
   **石垣まわりの造成を流し直せば地形が石垣に合い直る**(石垣自体は動かさない)

### 地盤を測るとき
- **`ref_height.npy`(この日の参照ハイトマップ)が造成前の地盤の出自である。**
  ここから世界2m格子へ焼いた **`docs/Sashizu/base_dem.json` が正典**で、各邸の `<屋敷>_dem.json` は
  `python3 Tools/Sashizu/build_base_dem.py` がその切り出しとして書く。
  `TerrainBackups/` は gitignore なので、worktree では正本(コミット済)の方だけが読める。
- ⛔ **live terrain から `Terrain.SampleHeight` で採らない。** live は自他の造成が乗る作業面である。
  2026-08-23 に、松平が 08:54 に流した造成を岡部・土井が 13:52 の標本で「造成前の現地形」として
  吸い込み、土井の DEM は松平区画の 68% が松平の設計面 27.0 になっていた(2026-08-24 に是正)。

### 座標の扱い
- **区画のポリゴンは動いていない。** 動いたのは地形の方
- 古地図オーバーレイは `LatLonToUnity` 経由で置かれているので正しい座標系にある。
  補正で**区画と地形が一致した**、というのが現時点の理解
- ⚠ ただし確証は無い。区画の角はユーザーがブックマークで打っており、
  **古地図を見て打ったのか地形の丘を見て打ったのか**で答えが変わる。気になるなら
  古地図上の道の交点と区画の角が合うかを見れば判定できる

## 溜池の掘り直し(2026-08-29) — Recarve 事故の復旧と、池・岸の作り直し

### 事故

ユーザーが `WaterBody` インスペクタの Recarve(掘り直し)を溜池で走らせた。Recarve は
**snap 矩形の全域をスナップショットで上書きしてから掘る**ため、次の2つが同時に起きた。

- 溜池の snap 矩形 = idx x[517,1127] z[582,1192] = **世界 x[−958,262] z[162,1382] / 1220×1220m(145ha)**
- その snap の実体 `Assets/Edo/Water/snap/Tameike.bytes` は **8/16 版**で、8/22 のジオリファレンス
  8m補正より前・8/23〜26 の造成より前

結果、**145ha が 8/16 の地形へ巻き戻った**。平場の設計高(岡部16.0 / 松江松平27.0 / 土井26.5 /
山王28.5 / 三屋敷12.50)は一致したままで、**法面の縁だけが約8m横へずれる**という 8m ズレの指紋が出た。
コミット済み地形との差は 87区画中 **73区画**が平均0.2m超(岡部1.30 / 土井1.25 / 松江松平1.19(最大19.41) /
観理院2.61 / 山王境内2.01 / 三べ坂安部1.47)。あわせて水位が 6.60 → **3.843**、depth 5.0 で
池底が **−1.16m** まで掘られ、堰の天端(6.39)より水面が 2.55m 低くなった(ユーザーの申告はこれ)。

### 復旧

1. snap 矩形の高さを **コミット済み地形(HEAD)** で丸ごと書き戻した(361,967セル・残差0)
2. 池と岸は「戻す」のではなく**設計して掘り直した**(下記)
3. **snap を復旧後の現況で取り直した** — 次に Recarve が押されても正しい地形が戻るだけになる

退避: `TerrainBackups/tameike_20260829_recarve_pre/`(事故直後の .asset / .unity / live のハイトマップ .bin)。

### 池と岸の設計値(2026-08-29)

水面 **6.60**(堰の天端 6.39 の 0.21m 上=越流。下流 3.50 → 落差 3.10m)。堰・滝・飛沫・石垣は動かさない。

| 項目 | 値 |
|---|---|
| 縦断(堰からの測地距離 L) | L=0 → 水深3.00 / 100 → 2.40 / 550 → 1.60 / 800 → 1.10 / 1200以遠 → 0.70 |
| 汀の浜 | 水深 = min(縦断の水深, **0.12 × 汀からの距離**) — 1/8.3 の直線勾配 |
| 微起伏 | 縦断値に ±12%(Perlin 45m)、絶対 ±0.15m(Perlin 22m)。汀では 0 |
| 岸(外側) | **もともと水面より高い陸には一切触らない(土手を作らない)。** 水面より低い外側だけを、汀の 6.60 から\
「その窪みの外縁にある自然の岸の高さ」へ線形に埋め戻す(距離比 dS/(dS+dN) で内挿)。自然地盤を超えて盛ることはない |
| 据わりの拘束 | **石垣・堰石は土留め**とみなし「天端−1.0m」まで盛ってよい。それ以外の物は「足元+0.15m」を超えて盛らず「足元−0.15m」より掘らない |
| 除外 | 堰の下流側(法線 (0.91,−0.42) 側 +2m)/ 他の水域の輪郭+3m |
| 陸の扱い | 輪郭内で元の地面が池底より **3.5m 以上高い**所だけを陸(岬)として残す(0.16ha)。それ以下の“汀ぎわの薄い土手”は**削って水没させる** — 当初は「水面より高ければ残す」にしていたため、汀に幅2〜4mの畦が立ち、ユーザーに2度指摘された |

結果: 変更28,899セル / 掘3,868m³ / 盛99,242m³ / 最大盛6.91m・最大掘2.71m。
埋め戻したのは**もともと水面より低かった外側の窪み 6,836セル(38,448m³)**だけで、
**もともと水面より高かった陸を盛った所は 0セル**(＝人工の土手は無い)。
さらに岸(下記)を入れて **水域 9.18ha・貯水量 120,250m³・平均水深1.31m**(p50 1.33 / p95 2.32 / 最大4.84)。

⚠ 初版(同日)は外側を一律 1/8 のランプで立ち上げる式にしていたため、**もともと水面より高い陸 2.49ha を
最大 +2.14m 盛って池を土手で取り巻いていた**(ユーザーの指摘で発覚)。上の規則へ改め、土手は 0 になった。

### 汀の畦(2026-08-29 ユーザー指摘・ブックマーク#1 を2回)

「囲っているところが盛られて見える」「まだ畦がのこってます」。実測して分かったこと:

1. **1回目の畦**(北腕・東岸 z≈980-1040)は `base_dem` と一致する**自然地盤**で、こちらが盛ったものではなかった。
   その背後が別の作業で 6.8〜7.4m まで掘られており、残った自然地盤が畦に見えていた。
2. **2回目の畦**(北腕・東岸 z≈1100-1160)は**輪郭の内側**にあり、
   「元から水面より高い輪郭内のセルは陸として残す」という当方の規則が、
   **汀ぎわの幅2〜4mの土を削らずに立てていた**もの。これが真犯人。

**採った規則(ユーザー裁定: 現代の地面を基準にしてよい。ただし池は埋め立てられていることを考慮する)**

| 範囲 | 扱い |
|---|---|
| 輪郭の内側 | ⛔ `base_dem` を使わない(池の footprint は近代の埋立地)。池底は設計値。**池底より3.5m以上高い所だけ**を岬として残し、それ以下の畦は削る |
| 汀の外 0〜18m | `base_dem` へ 0→1 で立ち上げる(**削りも込み**。畦は削り、窪みは埋める) |
| 18〜25m | `base_dem` そのもの |
| 25〜35m | 効果を 1→0 へ落として現況へ摺り付ける |
| 共通の制約 | 区画の中には入らない / 構造物の足元(+0.15m)を越えず、足元(−0.15m)より掘らない / 1回あたり ±3.0m / 他の水域の輪郭+6m と堰の下流は除外 |
| ぼかし | 盛削量そのものを **3×3 で1回**。⚠ 5×5×2回にすると幅2〜4mの畦が平均化されて消えず、指摘が再発した |

結果(汀の外): 盛 2,496セル 4,111m³(最大1.92m)/ 削 796セル 1,222m³(最大3.00m)。
断面は水面から背後の地盤まで**単調**になり、畦は解消。

⚠ 途中で試して**採らなかった**案: ①区画外・汀60m を一律 base_dem へ(17,629m³・最大9.57m、境界に崖)
②閉じた窪みの充填(溝は閉じておらず120セルしか効かない)③畦を削って背後の低地に合わせる(自然地盤を8,007m³削る)。

⛔ **溜池で Recarve を押さない。** 池底は上の縦断で*設計*してあり、Recarve は
「水面−depth の一枚板」に均してしまう(depth は 3.0 に直してあるので、押すと平らな 3.60 の池になる)。
