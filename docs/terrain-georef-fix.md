# 地形のジオリファレンス補正と造成の初期化 — 2026-08-22

**シーンの地形(`ModernTerrain`)は 2026-08-22 に作り直した。**
以降のセッションは、**屋敷を建てる前に必ず造成を流し直すこと。** 平場は消えている。

## 何が起きていたか

`ModernTerrain` が実世界に対して **東へ 8m・南へ 2m** ずれていた。純粋な平行移動で、縮尺の歪みはゼロ。

**確かめ方**: シーン座標 →(`Edo.Geo.GeoReference` / `JapanPlaneRectIX`。EPSG:6677 の厳密実装で
pyproj と 0.001mm 未満で一致)→ 緯度経度 → 国土地理院の DEM と突き合わせる。
地形の全テクセル(2049²・2.0m間隔)で参照ハイトマップを作り、全解像度で最良の平行移動を探した。

| 象限 | 最良のずれ | 補正後の \|差\| 中央値 |
|---|---|---|
| 南西 | dx **+8m** / dz **−2m** | 0.161 m |
| 南東 | dx **+8m** / dz **−2m** | 0.111 m |
| 北西 | dx **+8m** / dz **−2m** | 0.136 m |
| 北東 | dx **+8m** / dz **−2m** | 0.109 m |

4象限とも完全に同じ値 = 歪み無しの平行移動。原因は特定できていない
(`edo-map/scripts/export_unity_terrain*.py` は等長方形近似を使うが、それらの中心と
実際の地形の中心が 371m/465m 離れており、この地形を作った工程は別物)。

**遠方では旧地形が最大 10m 狂っていた。** 造成の無い場所で海抜 −5.46m(実測 +2.90m)など。
標高API で 5 点照合し、すべて参照が正しいことを確認済み。

## やったこと

### ① 8mズレの補正
ハイトマップの配列を `new[j][i] = cur[j-1][i+4]`(西へ 8m・北へ 2m)。
**地形オブジェクトは動かしていない** — 動かすとスプラット(塗った道・土地利用)とディテール(草)が
一緒に動いて建物からずれる。配列だけずらせば塗りは残る。

参照との \|差\| 中央値 **0.229m → 0.127m**、残ズレ **0**。

### ② 造成を自然地形へ初期化
ユーザーが `EdoSketch` の**水色(color=2)で囲った範囲の外**を、参照ハイトマップで置き換えた。
境界は 10m の余弦でブレンドしてあるので段差は無い。

- 囲いの中: **0.0000 m で無傷**
- 囲いの外: 参照と **0.0004 m** で一致

**囲いの中で守ったもの(58,695坪)** — ビルダーで再現できない手作業の地形:
堰・どんどん・虎ノ門枡形・**汐見坂の段坂**・鍋島池・三屋敷(太田/加納/松平備前)・
虎ノ門内4敷地(林/小倉/内藤能登/村瀬)・溜池の南端。
囲いの多角形は `UserData/Sketches/Assets_Edo_Scenes_Akasaka.unity.json` に残っている。

**囲いの外で消えたもの** — 全24区画の造成、町屋(田町/新町/代地)、干場、寺、
**丹羽/京極の掘削復元**(ホテル基礎跡をラプラシアン緩和で均したもの)、松平大和守、外堀まわり。

## いま何をすべきか

### 屋敷を建てるとき
1. **造成ステージを先に流す。** 平場は消えている。区画ポリゴンはビルダーのソースに、
   面の高さは `docs/Sashizu/<屋敷>.json` の `planes` / `terraces` に残っている
2. **指図の面の高さはそのまま使える。** 台地は平らなので 8m 横に動かしても高さが変わらない
   (山王山の山頂で 0.01〜0.03m、岡部の平場で中央値 0.00m)。**動いたのは面の「縁」だけ**
3. **手組みの石垣・長屋・門は再接地が要る。** 石垣 3,926 件のうち、下の地面が 1m 以上動いたものが 41%。
   石垣は「天端を丸い数字で通し、周りの地形を造成して合わせる」作りなので、
   **石垣まわりの造成を流し直せば地形が石垣に合い直る**(石垣自体は動かさない)

### 地盤を測るとき
- **`ref_height.npy`(この日の参照ハイトマップ)が造成前の地盤の出自である。**
  ここから世界2m格子へ焼いた **`docs/Sashizu/base_dem.json` が正典**で、各邸の `<屋敷>_dem.json` は
  `python3 Tools/Sashizu/build_base_dem.py` がその切り出しとして書く。
  `TerrainBackups/` は gitignore なので、worktree では正本(コミット済)の方だけが読める。
- ⛔ **live terrain から `Terrain.SampleHeight` で採らない。** live は自他の造成が乗る作業面である。
  2026-08-23 に、松平が 08:54 に流した造成を岡部・土井が 13:52 の標本で「造成前の現地形」として
  吸い込み、土井の DEM は松平区画の 68% が松平の設計面 27.0 になっていた(2026-08-24 に是正)。

### 座標の扱い
- **区画のポリゴンは動いていない。** 動いたのは地形の方
- 古地図オーバーレイは `LatLonToUnity` 経由で置かれているので正しい座標系にある。
  補正で**区画と地形が一致した**、というのが現時点の理解
- ⚠ ただし確証は無い。区画の角はユーザーがブックマークで打っており、
  **古地図を見て打ったのか地形の丘を見て打ったのか**で答えが変わる。気になるなら
  古地図上の道の交点と区画の角が合うかを見れば判定できる

## 溜池の掘り直し(2026-08-26)

**このリセットは溜池の水面下の地面も現代の埋立地へ戻していた。** 池の内側 23,672 セル(9.47ha)のうち
**71% が水面 6.6m より上の陸**になっていた(南端だけは水色の囲いの中で無傷)。2026-08-26 に掘り直した。

- 池の内側は `heightmap_before_reset.bin` の値へ戻し(池底 4.55m = waterY 6.6 − depth 2.05)、
  岸は汀から 20m で現況へ立ち上げる帯を作った
- **岸の帯は「リセット前」を使わない。** リセット前の岸には他の造成(干場・旧平場)が混ざっており、
  それを戻すと 08-22 以降に建った内藤紀伊・土岐・岡部の平場を最大 4.7m えぐる。
  帯は「池底 → 現況」の合成勾配にし、さらに**構造物からの距離で削れる量を頭打ち**(足元 0m・
  1m 超えてから 0.6m/m)にして、既存の建物・塀・石垣が浮かないようにした
- 最後に変更域だけ 2m/2m(45°)で勾配を頭打ちにして、切り口の崖を均した
- 結果: 変更 30,931 セル(12.37ha)・掘削 306,129m³・最大 9.70m。池の内側の水没率 **28.8% → 93.7%**
  (リセット前 94.1%)。新たに浮いたオブジェクト **0**、水面上の急段差はリセット前より減っている
- 直前のスナップショットは `TerrainBackups/tameike_20260826_recarve_pre/`

⚠ **`WaterBody` の Recarve は使っていない** — 溜池の snap は大的稽古場の平場と重なる(`unity-buke-yashiki` の references/gardens-ponds.md)。

## 戻し方

`TerrainBackups/terrain_20260822_georef_fix/` に 3 段階のスナップショット(gitignore 済)。

| ファイル | 中身 |
|---|---|
| `heightmap_before.bin` | 8mズレ補正の前 |
| `heightmap_before_reset.bin` | 補正済・造成あり(造成を戻す直前) |
| `grading_delta.bin` | **造成の差分**。任意の領域だけ足し戻せる |
| `ref_height.npy` / `build_ref.py` | 自然地形の参照と、その生成器 |

すべて **2049×2049 float32・実標高[m]・行=z(北+)・列=x(東+)**。
Unity へ書き戻すときは `(m - terrain.position.y) / terrainData.size.y` で正規化して `SetHeights`。

**「あの造成は残したかった」が後から出ても、`grading_delta.bin` からその領域だけ足し戻せる。**
