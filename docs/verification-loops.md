# 検証の輪 — 「誰の目にも入っていない値」は未検査であって合格ではない

⭐ **この文書が答える問い**: 「指図をどれだけ精緻にしても、実装しないとどうにもならないのか」
(2026-09-02 ユーザー質問)。

⛔ **答えは「そのままの YES ではない」。**実測で裏を取った結果、より強くて使える形が出た。
本文書がその形と、機械で見張る手立てを定める。

---

## 1. 法則

> **書いた数値は、それを見せる図か検査へ届いて初めて検められる。**
> **届いていない値は「合格」ではなく「未検査」である。**
>
> ⭐ そして **輪には種類があり、種類ごとに見える欠陥が違う。**
> ⭐ **輪には値段があり、高い輪を先に回すと作った物を捨てることになる。**

前半を **閉じ(closure)**、後半を **順序(ordering)** と呼ぶ。⛔ 両方要る。
片方だけでは、それぞれ逆向きの事故が起きる(§4・§5)。

---

## 2. 輪は3種類ある。何が見えるかが違う

| 輪 | 回し方 | ⭕ この輪でしか出ない欠陥 | ⛔ この輪では出ない欠陥 |
|---|---|---|---|
| **計算の輪** | 断面・縦断・方位・収支を**数式で**引く | 水が流れない(落差ゼロ・逆勾配)/ 帯どうしが重なる / 動線が繋がっていない / 建蔽率 | 図にしないと分からない「見え方」 |
| **図の輪** | 平面・断面・見付を**原寸で描いて見る**  | 並木に見える / 図と本文が食い違う / 撤回した説が図に残る / 抜きが描かれていない | 部材の実寸に依る取り合い |
| **実装の輪** | Unity に**建てて、レンダを見る** | 部材の実メッシュの見え方 / 屋根の掛かり / 駒どうしの隙間 / 材質 | 「水が流れない」— 建てても目に見えない |

⭐ **3つ目が在ることは、この法則の実質そのもの。**⛔ 計算と図をどれだけ精緻にしても、
**実装の輪でしか出ない欠陥は出てこない**。CLAUDE.md 規則5(部材どうしを中心で合わせない・
置いた駒の実メッシュから面を測って寄せる)と EDO-0096(数値QAの合格は run 単位の中央値
止まり — 駒ごとのばらつきはレンダで初めて見つかる)は、いずれもこの列の宣言である。

⛔ **逆も同じだけ強い。**「水が 60m を落差ゼロで流れない」「暗渠が上流へ昇っている」は
**建てても目に見えない**。実装の輪は万能ではなく、**計算の輪の代わりにはならない**。

## 3. 閉じ — 輪に入っていない産物は、無いのと同じ

⛔ **目視では見つからない。**松江松平は同じ型を**3度**見逃し、4度目で機械化した。

産物が輪から外れる形は3つある。**すべて実例が在る:**

| 型 | 何が起きるか | 実測された実例 |
|---|---|---|
| **① 孤立** | 書いたのに**呼んでいない** | 松江松平 `garden_east_svg` / `garden_section_svg` / `neishi_table` / `neishi_check`(実際にコミットされた状態で4件同時)/ ⭐ **岡部 `walls_table`(段の土留めの一覧表)は現在も一度も描かれていない** |
| **② 捨て** | 呼ぶが**戻り値を誰も受け取らない** | 松江松平が自邸の機械照合に「残る穴」として自己申告(2026-09-02) |
| **③ 出していない** | 測ったのに**成果物に載せない**(stdout 止まり) | ⭐ **岡部「法面24件が要約に出ず切盛図のキャプションにしか無い」「抜きが6枚中5枚の図に描かれていない」**(検図 2026-09-02)/ ⭐ **外堀「README の QA 不合格が指図に無い」**(検図 2026-09-01) |

⭕ ①②は **`Tools/Sashizu/wiring_gate.py`** が機械で鳴らす(全邸共通・移植不要)。
③は静的には見えないので、同ツールの `--surfaced` で**実行ログ × 成果物 HTML**を突き合わせる。

```bash
python3 Tools/Sashizu/wiring_gate.py                       # 全邸の生成器を見る
python3 Tools/Sashizu/build_<邸>_sashizu.py 2>&1 | tee /tmp/run.log
python3 Tools/Sashizu/wiring_gate.py --surfaced /tmp/run.log docs/Sashizu/<邸>_sashizu.html
```

⛔ **`build_matsudaira_dewa_sashizu.py` の `check_wiring_check` を各邸へ写さないこと。**
あれは当邸固有の報告経路(`plane_check` の束・`main()` の `WARN`)に結ばれていて、
移植には読み替えが要る — **移植の写しは 2026-08-25 に土井が偽の不一致28件を出した型**。
⭕ `wiring_gate.py` は外からソースを読むだけで、邸ごとの構造を仮定しない。

### ⛔ 0件は「合格」ではない

`wiring_gate.py` が見るのは**結線**だけ。次は原理的に見えない:

- **恒真の検査** — 走って報告されるが、何を壊しても0件を返す。
  ⭐ 実例: 岡部 `kekkai_check` は「**結界を全部消す**」でも0件(検図 2026-09-02)/
  岡部 `program_check` の文字列一致の恒真(EDO-0102)。
  ⛔ **破壊試験でしか出ない**(EDO-0106「破壊試験は必ず3通り」)。
- **検査そのものが無い領域** — → EDO-0106(検査の**型**の欠落)の持ち場。
- **建てないと見えない不良** — → §2 の3行目。

## 4. 順序 — 高い輪を先に回すと、作った物を捨てる

⛔ **「骨格が固まったら、細部を詰める前にとりあえず建てて見る」は、そのままでは誤り。**
実装の輪は**いちばん高く、やり直しもいちばん高い**。実測された代償:

- CLAUDE.md 規則2 — 指図を飛ばして**2度全面差し戻された**。「図なら数分、建ててからだと数時間」
- CLAUDE.md 規則18 — 松江松平の庭が**庭方に一度も検められないまま Stage7 まで実装され**、
  差し戻された(2026-09-01)。⭐ 庭方は致命5件で不合格 → **庭方自身が全面を再設計**。
  ⛔ 先に建てた分は効かなかった。
- メモリ — 岡部邸の実装記録(13棟・建蔽率33.7%)は 2026-08-23 に**指図ごと失効**。

⭐ **だから順序は「安い輪から」。** 正しい形:

> ⭕ **その欠陥を見られる輪のうち、いちばん安いものを先に回す。**
> ⛔ **安い輪で見えるはずの欠陥を、高い輪に初めて見つけさせない。**
> ⭕ **実装の輪へ進むのは、それでしか見えない型を取りに行くときだけ。**
> ⛔ **そのときも、安い輪(検分役)が緑になってから。**

⚠ **これは移行期間の裁定(CLAUDE.md 規則18・案B)と矛盾しない。**移行中は
「検分を通すまで作業を続けてよい」。⛔ ただし**ユーザーへ見せる前には必ず通す**の一線は動かない。

### ⚠ 「実装しないと分からなかった」を、鵜呑みにしない

実装後に出た指摘を、**そのまま「実装の輪でしか出ない」と数えない。**⭕ 1件ずつ問う:

> **この欠陥を見られる、もっと安い輪はあったか。**

- 「駒どうしに 0.72m の隙間」→ ⭕ 実装の輪でしか出ない(部材の実メッシュに依る・規則5)
- 「屋根が無い」→ ⛔ **有無は数えられる** = 計算の輪で出る(完備の検査の欠落であって、
  実装の輪の手柄ではない)

⛔ ここを混ぜると「建てなければ分からなかった」が免罪符になり、**足りない検査が足りないまま
残る**。⭐ 実装後の指摘は、**次にどの輪へ検査を1本足すか**の材料として読む。

---

## 5. 使い方 — 各巡で問う4つ

1. ⛔ **新しい設計値を入れたら、同じ巡でそれを描く図か表を出したか。**
   図の無い所は「未検査」であって「合格」ではない。
2. ⛔ **検査を書いたら、同じ巡で報告経路へ繋いだか。** → `wiring_gate.py` が見張る。
3. ⛔ **その検査は、壊したら鳴るか。** → 破壊試験3通り(EDO-0106)。⛔ 素で0件は当たり前。
4. ⛔ **実装後に出た指摘は、本当に実装の輪でしか出ない型か。** → §4 の問い。
